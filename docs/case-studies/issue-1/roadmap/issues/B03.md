## Context

Every push to `main` runs the "Example app" workflow
(`.github/workflows/example-app.yml`). Its "Build web app" job runs
`scripts/check-pages.sh` with `PAGES_MODE=require` on `main` and
`PAGES_MODE=warn` on pull requests (line 75 of the workflow). On `main`
(run 41299671748, commit `428ee07`) the check fails:

```text
##[error]GitHub Pages is not enabled for link-foundation/ui, so the example app
cannot deploy. A maintainer must act: Open
https://github.com/link-foundation/ui/settings/pages and set Build and
deployment -> Source to GitHub Actions, then re-run this workflow.
```

The full log is stored in
[`ci-logs/main-41299671748.log`](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/ci-logs/main-41299671748.log).
Pull requests are not affected: they only get a warning annotation.

The documentation and demo site ({{F54}}) is deployed with GitHub Pages, so this
setting is a prerequisite for it.

## Goal

GitHub Pages is enabled with source "GitHub Actions", and the "Example app"
workflow on `main` is green.

## Scope

### In scope

- **Maintainer action (cannot be done by an agent or a pull request):** open
  https://github.com/link-foundation/ui/settings/pages and set
  **Build and deployment → Source** to **GitHub Actions**.
- Re-run the latest "Example app" run on `main` and confirm that the deploy job
  publishes the site.
- Add the deployed URL (expected `https://link-foundation.github.io/ui/`) to
  the repository "About" section and to `README.md` if it is not there.

### Out of scope

- Changing `scripts/check-pages.sh`: it already fails on `main` with the exact
  action to take and only warns on pull requests, which is the desired
  behaviour.
- Building the real documentation site: that is {{F54}}.

## Dependencies

None. An agent that picks up this issue can only verify the setting and
update the README; if Pages is still disabled, it must comment on this issue
with the command output below and stop.

## Step-by-step plan

1. Check the current setting:
   `gh api repos/link-foundation/ui/pages --jq .build_type`. A 404 means Pages
   is disabled.
2. If it is disabled, ask a maintainer (comment on this issue) to apply the
   setting above. Do not try to enable Pages with the API from a workflow:
   the default `GITHUB_TOKEN` cannot do it, and a personal token must not be
   added for this purpose.
3. After it is enabled, re-run the workflow:
   `gh run rerun <run-id> --repo link-foundation/ui --failed`.
4. Confirm that the site loads and add its URL to the README "Quick Start"
   section.
