## Context

After one link ({{F33}}) we need a whole links network: many links that refer
to each other, laid out, interactive and fast. Two projects show what to keep
and what to avoid:

- konard.github.io network editor (learn only, the repository has **no
  licence**): seven placements in `src/links/placement.js` (circle, square
  grid, hex, dice, playing card, spiral, d3-force); collision solving in
  `collisions.js`, `collision-gaps.js`, `collision-symmetry.js`, run in
  `collision-worker.js` with `solver-job.js`; `src/pages/useCollisionSolver.js`
  keeps results keyed by job; `render.js` `networkSvg` makes one SVG string for
  the preview and every export; `export.js` exports SVG, PNG, JPEG, WebP,
  `.lino`, the clipboard and Web Share
  ([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md)).
- deepcase (Cytoscape): a link is a node plus `from`, `to` and `type` edges
  (`imports/cyto/elements.tsx`); the force layout runs with `infinite: true`
  and never settles (https://github.com/deep-foundation/deepcase/issues/51,
  https://github.com/deep-foundation/deepcase/issues/52,
  https://github.com/deep-foundation/deepcase-app/issues/269); labels overlap
  and have no level of detail
  (https://github.com/deep-foundation/deepcase/issues/37,
  https://github.com/deep-foundation/deepcase/issues/47); edges disappear
  (https://github.com/deep-foundation/deepcase-app/issues/320); nodes disappear
  on iPad (https://github.com/deep-foundation/deepcase-app/issues/235); too
  many re-renders (https://github.com/deep-foundation/deepcase/issues/65); PNG
  and PDF export and aggregation were requested
  (https://github.com/deep-foundation/deepcase-app/issues/89)
  ([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/deepcase.md)).

## Goal

A `links-network` element shows the links of a store ({{F08}}) with selectable
layouts, pan, zoom, selection, drag and keyboard navigation, labels with level
of detail, a bounded force simulation and heavy layout work in a cancellable
Web Worker, using the geometry and markers of {{F33}}.

## Scope

### In scope

- Network model: points and links, where a link may point to another link
  (its endpoint touches the target link's centre), self-loops, free ends.
  Two styles: `glyph` (links as curves) and `node-edge` (each link is a node
  with `from` and `to` edges, as in deepcase).
- Layouts: `circle`, `grid`, `hex`, `spiral`, `force` (bounded) and
  `layered` (Dagre from {{F32}}).
- Interaction: pan and zoom ({{F33}}), click and Shift+click selection,
  drag to move a point (pins it), hover highlight of neighbours, context
  menu hook, keyboard navigation between neighbours.
- Level of detail: hide labels below a zoom threshold and remove overlapping
  labels.
- Worker: `layout-worker.js` with jobs keyed by id; stale results are dropped.
- SVG back end for up to 2 000 links and Canvas back end above that, sharing
  `markers.js`.
- Export to SVG and PNG.

### Out of scope

- Converting arbitrary LiNo text to a network ({{F35}}).
- 3D views (https://github.com/deep-foundation/deepcase-app/issues/159) and
  WebGL rendering for more than 10⁴ links (follow-up; see Sigma.js below).
- Editing link values (the app handles actions).

## Dependencies

- **Blocked by {{F33}}**: `linkGeometry`, `markers.js`, both renderers,
  `createZoomPan` and `createAnimator`.
- **Blocked by {{F08}}**: the store subscription API; the view listens to
  link additions, removals and changes and updates only the changed links.
  Until {{F08}} exists, use an in-memory stub with the same `subscribe`
  signature.
- **Related:** {{F32}} (Dagre layout), {{F27}} (context menu), {{F35}},
  {{F58}} (konard.github.io migration), {{F62}} (deepcase migration).

## Step-by-step plan

1. Write `network-model.js`:
   `buildNetwork(links) → { points: Map, links: Map }`, where each input link
   is `{ id, source, target }` and `source`/`target` are a point id, a link id
   or `0` for a free end. Test self-loops, cycles and references to links.
2. Write `layouts/{circle,grid,hex,spiral}.js` as pure functions
   `(network, { width, height }) → Map<id, Point>`; positions are deterministic.
3. Write `layouts/force.js` with `d3-force` (ISC, bundled and pinned): fixed
   seed for initial positions, `alphaMin` and a maximum of 300 ticks, then
   stop. Never run an infinite simulation (deepcase issue 51).
4. Write `layout-worker.js` and `create-layout-runner.js`:
   ```js
   /** @returns {{ run(key: string, job: LayoutJob): Promise<LayoutResult>, cancel(key: string): void, dispose(): void }} */
   export function createLayoutRunner({ createWorker }) {}
   ```
   A new `run` with the same key cancels the previous one; a result whose key
   is not current is dropped.
5. Write `labels.js`: `visibleLabels(labels, zoom, { minZoom, padding })`
   returns ids without overlaps (greedy by priority).
6. Write `links-network.js` (element): picks SVG or Canvas by size, applies
   store changes incrementally (no full re-render), keyboard: arrow keys move
   to the nearest neighbour in that direction, Enter fires `on activate`,
   Escape clears selection.
7. Write `export.js`: `networkToSvg(network, positions, style) → string` and
   `networkToPng(svg, scale) → Promise<Blob>`.
8. Gallery `packages/ui-components/examples/links-network.html` with 10, 500
   and 5 000 links.

Input example (working names; the dialect is fixed in {{F03}}):

```lino
(store-view: links-network
  (items $links)
  (style glyph)
  (layout force)
  (labels (min-zoom 0.6))
  (on activate (open link-inspector (id $item.id))))
```

## Acceptance criteria

- [ ] Every layout returns the same positions for the same input on two runs
      (tests).
- [ ] The force layout stops after at most 300 ticks and the animator stops
      afterwards (test with the injected `raf`).
- [ ] A stale worker result is ignored when a newer job with the same key
      exists (test with a fake worker).
- [ ] `visibleLabels` never returns two overlapping label boxes (test).
- [ ] Adding one link to the store updates one element, not the whole view
      (Playwright counts DOM mutations).
- [ ] 5 000 links render with Canvas and panning stays above 30 fps on the CI
      machine (Playwright performance trace).
- [ ] The network is fully usable with the keyboard (Playwright).
- [ ] Exported SVG equals the preview SVG markup (test).

## How to verify

node --test packages/ui-components/tests/links-view/network/*.test.js
npx playwright test packages/ui-components/tests/e2e/links-network.spec.js

zoomed out with labels hidden; a selected link with its neighbours
highlighted.
