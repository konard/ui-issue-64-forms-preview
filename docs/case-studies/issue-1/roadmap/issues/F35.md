## Context

R16 and R1.6 ask for "a universal converter from Links Notation to a UI
visualization of a links network": any LiNo text, not only UI documents, can be
opened as a links network
([requirements](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/requirements.md)).

Prior art
([links-notation ecosystem](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)):
the link-cli WASM React workbench at https://link-foundation.github.io/link-cli/
already visualises a links store in the browser, and the doublets-web
playground (https://github.com/linksplatform/doublets-web) has a Monaco editor
with a graph view.

The konard.github.io network editor keeps five notations in sync (theory λ,
pairs, N-ary number, decimal index and LiNo such as `(1: 0 1)`), but its
`edit.js` parses them with regular expressions, which we must not repeat; the
repository has no licence, so learn only
([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md)).

The `links-notation` parser returns different shapes for the same content
written on one line, on several lines or indented
([ARCHITECTURE](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md),
section "Links Notation parse shapes"). The converter works on the raw links,
so it must give the same network for all three forms.

## Goal

`linoToNetwork(text)` turns any Links Notation text into the network model of
{{F34}} with stable ids and source positions, a `lino-network` element shows it,
selecting a point highlights the text that produced it, and the conversion
also runs in Node to produce an SVG file.

## Scope

### In scope

- Mapping rules (below) from links to points and links of the network,
  including anonymous nested links, references by id, self-references, cycles
  and quoted values.
- Diagnostics with line and column for parse errors (from the parser) and for
  unknown references (warnings).
- `networkToLino(network)` for networks that came from LiNo (round trip of
  ids and references; formatting is not preserved).
- The `lino-network` element with a text-to-view selection link.
- A Node CLI `lino-network` that writes SVG.

### Out of scope

- A text editor (use {{F38}} next to the view).
- The konard.github.io N-ary code notation and its `?code=` URLs (part of
  {{F58}}).
- Writing changes from the view back into the text (needs {{F14}}; follow-up).

## Dependencies

- **Blocked by {{F34}}**: `buildNetwork`, the layouts, the layout runner, the
  `links-network` element and `networkToSvg`.
- **Related:** {{F06}} (parsing helpers and error positions), {{F14}}
  (source-preserving edits for a later write-back), {{F38}} (editor),
  {{F46}} (dev mode can show the current document as a network), {{F58}},
  {{F59}}.
- Start early: `lino-to-network.js` only needs the `links-notation` package and
  the network model shape, so it can be written against a copy of the
  `buildNetwork` input type.

## Step-by-step plan

1. Write `packages/ui-components/src/links-view/lino-to-network.js`:
   ```js
   /**
    * @param {string} text Links Notation
    * @param {{ maxInputSize?: number, maxDepth?: number }} [options]
    * @returns {{ links: NetworkLinkInput[], diagnostics: Diagnostic[],
    *   sourceMap: Map<string, { line: number, column: number }> }}
    */
   export function linoToNetwork(text, options) {}
   /** @returns {string} */
   export function networkToLino(network) {}
   ```
   Use `new Parser({ maxInputSize, maxDepth })` from `links-notation`; never a
   regular expression.
2. Mapping rules (proposed; confirm them in the pull request description,
   write them as a table in the JSDoc and test each):
   - `(a: b c)` → link `a` with source `b` and target `c`.
   - `(a: b c d)` (more than two references) → link `a` as a sequence:
     `a` → `b`, then chained links for `c` and `d` with ids `a/1`, `a/2`.
   - A nested link without an id gets a stable id from its path, such as
     `a/0`.
   - A bare word that is not the id of a link becomes a point with that label.
   - A quoted value becomes a point with `kind value`.
   - `(a: a a)` is a self-loop; cycles are kept as is.
   - The same id defined twice gives a warning and the first one wins.
3. Normalise the three parse shapes (one line, several lines, indented) before
   mapping; fixtures `same-one-line.lino`, `same-multi-line.lino`,
   `same-indented.lino` must give equal networks.
4. Write `lino-network.js` (element): attribute `src` or inline text, shows
   diagnostics in a list, and emits `select` events with the source position.
5. Write `packages/ui-components/bin/lino-network.mjs`:
   `npx lino-network input.lino --layout force --out network.svg`.
6. Add samples `packages/ui-components/examples/lino-network.html` using
   `docs/case-studies/issue-1/samples/*.lino` as inputs.

Example input and expected network:

```lino
(1: 1 2)
(2: 2 1)
(greeting: hello 'world')
```

Expected: link `1` from `1` to `2`, link `2` from `2` to `1` (a cycle);
link `greeting` from point `hello` to value point `'world'`; no diagnostics.

## Acceptance criteria

- [ ] Each mapping rule above has its own test in `lino-to-network.test.js`.
- [ ] The three parse-shape fixtures give equal networks (test).
- [ ] Every sample in `docs/case-studies/issue-1/samples/` converts without
      errors (test loops over the folder).
- [ ] A syntax error returns a diagnostic with line and column and no throw
      (test).
- [ ] `networkToLino` then `linoToNetwork` returns an equal network for all
      fixtures (test).
- [ ] `npx lino-network fixtures/cycle.lino --out /tmp/cycle.svg` writes a
      valid SVG (test runs the CLI).
- [ ] Clicking a point in `lino-network` reports its source line (Playwright).
- [ ] No regular expression is used to parse LiNo in these files (review and
      a test that searches the source for `RegExp` and regex literals).

## How to verify

```bash
node --test packages/ui-components/tests/links-view/lino-to-network.test.js
npx playwright test packages/ui-components/tests/e2e/lino-network.spec.js
node packages/ui-components/bin/lino-network.mjs docs/case-studies/issue-1/samples/document.lino --out /tmp/document.svg
npm run lint && npm run format:check && npm run check:duplication
```

Expected screenshots: `document.lino` and `tokens.lino` as networks, and a
syntax error shown in the diagnostics list.
