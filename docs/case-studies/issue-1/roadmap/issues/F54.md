## Context

Issue #1 asks for "our own GitHub Pages documentation and demo website, built
with our own UI/UX framework" (R24). Today the repository deploys only the
template example app (`examples/universal-app`, React + Vite) from
[`.github/workflows/example-app.yml`](https://github.com/link-foundation/ui/blob/main/.github/workflows/example-app.yml),
and that deploy fails on `main` because GitHub Pages is not enabled ({{B03}}).

The research
([existing-solutions.md section 9](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md))
says the site must dogfood the framework: "prefer a thin custom static
generator, or Vite plus our Web Components, so the site dogfoods the LiNo
runtime. Astro with islands is the fallback". Vite (MIT) is the build tool;
axe-core (MPL-2.0) is allowed in CI only.

Facts about the current workflow that this issue must respect:

- `web-build` runs `scripts/check-pages.sh` with `PAGES_MODE=require` on
  `main` and `warn` on pull requests, then `actions/configure-pages@v6`, and
  uploads the Pages artifact with `./.github/actions/artifact-transport`
  (`pages: 'true'`); `pages-deploy` uses `actions/deploy-pages@v5` with
  `pages: write` and `id-token: write`.
- The `pipeline-status` job must list every job;
  `scripts/check-status-gate-covers-all-jobs.mjs` and
  `scripts/check-ci-workflows.mjs` check the workflows.
- `examples/universal-app/vite.config.js` derives the base path (`/ui/`) from
  `GITHUB_PAGES` and `GITHUB_REPOSITORY`.

## Goal

A private workspace `packages/site/` (`@link-foundation/ui-site`) whose pages
are LiNo documents rendered by `ui-dom`, built by Vite into static files and
deployed to `https://link-foundation.github.io/ui/` by one workflow, with
English and Russian content, a theme switcher and dev mode available.

## Scope

### In scope

- Pages as LiNo: `packages/site/content/<lang>/<page>.lino`. Initial pages:
  `index` (what the framework is, quick start), `getting-started`,
  `dialect` (links to `docs/spec/` from {{F03}}), `components` (placeholder
  list from the {{F26}} catalog; the full gallery is {{F55}}), `themes`,
  `about` (licence, links to repositories).
- A Vite plugin `packages/site/vite-plugin-lino-pages.js` that turns every
  content file into an HTML entry (multi-page build, one `index.html` per
  route, e.g. `dist/en/getting-started/index.html`), with a pre-rendered body
  from `renderToHTML` ({{F16}}) so the site works without JavaScript and is
  indexable, then mounts `ui-dom` on load.
- Site layout in `packages/site/layout.lino`: header with navigation, language
  switch, theme switch, main content, footer.
- Documentation kinds needed by the site (`heading`, `paragraph`,
  `code-block`, `link`) — use the {{F26}} / {{F03}} kinds if they exist,
  otherwise register them in `packages/site/src/kinds.js` with `defineKind`.
- i18n: English (`en`, default) and Russian (`ru`) with the language in the
  path (`/ui/en/...`, `/ui/ru/...`), root redirects by `navigator.language`
  with a link fallback. Use {{F13}} if merged, else `lino-i18n` directly.
- Theme switcher: themes and schemes from {{F39}} (`light`, `dark`, `system`);
  the choice is stored in the `user` configuration layer.
- Dev mode: if {{F46}} is merged, the site enables it (`?ui-dev` and the
  shortcut); otherwise {{F55}} enables it.
- Deployment: a new workflow `.github/workflows/site.yml` that builds and
  deploys the site, and removal of the Pages steps from `example-app.yml`, so
  that exactly one workflow deploys Pages.

### Out of scope

- Enabling Pages in repository settings: maintainer action in {{B03}}.
- Component gallery and playground: {{F55}}. Contributor guide: {{F56}}.
- Search, versioned docs, blog (follow-ups).

## Dependencies

- {{B03}} (blocker): Pages enabled with source "GitHub Actions"; without it
  the deploy job fails on `main`.
- {{F16}} (blocker): `render`, `defineKind`, `renderToHTML`, `data-link-id`.
- {{F26}} (blocker): controls for navigation, buttons, select (language and
  theme switch) and the component catalog for the `components` page.
- {{F39}} (blocker): theme registry, schemes, `system` following
  `prefers-color-scheme`.
- Related: {{F13}} (i18n), {{F46}} (dev mode), {{F55}} (gallery), {{F40}}
  to {{F43}} (extra themes listed when merged), {{F05}} (screenshots, axe).

## Step-by-step plan

1. Create `packages/site/package.json`:
   `{ "name": "@link-foundation/ui-site", "private": true, "type": "module" }`
   with scripts `dev`, `build`, `preview`, `test`, dev dependency `vite`.
2. `vite.config.js`: base path from `GITHUB_PAGES` and `GITHUB_REPOSITORY`
   (same logic as `examples/universal-app/vite.config.js`), the LiNo pages
   plugin, `build.outDir = 'dist'`.
3. `vite-plugin-lino-pages.js`: export
   `linoPages({ contentDir, layout, languages: ['en', 'ru'] })`; for each file
   parse with `ui-core`, merge into the layout, pre-render, emit HTML. A
   parse error fails the build with file, line and column.
4. Content example `content/en/index.lino`:

   ```lino
   (index: page
     (title 'Links UI')
     (main: stack
       (gap (token space.large))
       (intro: heading (level 1) (text 'UI described as links'))
       (lead: paragraph
         (text 'Every element, style and animation is a Links Notation link.'))
       (start: link (text 'Get started') (href 'getting-started/'))))
   ```

5. `src/main.js`: on load, find the pre-rendered root, create the store,
   mount `ui-dom`, apply the saved theme and language, enable dev mode.
6. Tests in `packages/site/tests/`: every content file parses; every page
   exists in every language (same file names); every internal `href`
   resolves to a built page; the build output contains `data-link-id`.
7. `.github/workflows/site.yml`: jobs `site-build` (checkout,
   setup-node 24, `npm ci`, `bash scripts/check-pages.sh` with the same
   `PAGES_MODE` expression, configure-pages on `main`, the site build
   command (see How to verify) with `GITHUB_PAGES` on `main`,
   upload with `./.github/actions/artifact-transport` and `pages: 'true'`),
   `site-deploy` (same as the current `pages-deploy`), and `pipeline-status`
   listing every job. Copy permissions and concurrency from `example-app.yml`.
8. In `example-app.yml` remove "Configure GitHub Pages", "Upload GitHub Pages
   artifact" and the `pages-deploy` job, and update `pipeline-status`. Keep the
   example app build artifact.
9. Run `node scripts/check-ci-workflows.mjs` and
   `node scripts/check-status-gate-covers-all-jobs.mjs`.
10. Playwright: screenshots of `/en/` in light and dark, `/ru/`, and axe.

## Acceptance criteria

- [ ] `npm run build --workspace @link-foundation/ui-site` creates
      `packages/site/dist/en/index.html` and `dist/ru/index.html` containing
      pre-rendered content with `data-link-id`.
- [ ] Every content file is LiNo and parses (test); `en` and `ru` have the
      same page set (test); no broken internal links (test).
- [ ] The site works with JavaScript disabled (Playwright, text visible).
- [ ] The theme switch changes light/dark/system and survives reload.
- [ ] axe reports no violations on `/en/` and `/ru/` in light and dark;
      screenshots attached.
- [ ] `site.yml` is the only workflow with `deploy-pages`
      (`grep -l deploy-pages .github/workflows/*.yml` prints one file).
- [ ] `node scripts/check-ci-workflows.mjs` and
      `node scripts/check-status-gate-covers-all-jobs.mjs` pass.
- [ ] After merge and {{B03}}, `https://link-foundation.github.io/ui/`
      returns HTTP 200 and shows the site.
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication`,
      `npm test` pass.

## How to verify

```bash
npm ci
npm run build --workspace @link-foundation/ui-site
node --test packages/site/tests/*.test.js
npm run preview --workspace @link-foundation/ui-site
node scripts/check-ci-workflows.mjs
node scripts/check-status-gate-covers-all-jobs.mjs
npm run lint && npm run format:check && npm run check:duplication
curl -sI https://link-foundation.github.io/ui/ | head -1   # after deploy
```
