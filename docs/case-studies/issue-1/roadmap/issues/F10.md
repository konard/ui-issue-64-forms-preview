## Context

Every UI built with the framework must be configurable through LiNo (R2) and
changeable on the fly on our sites (R9). Changes made in dev mode ({{F46}})
must be explainable to people and AI agents (R12). The architecture
([ARCHITECTURE.md](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md))
fixes the order of configuration layers:

```
defaults < theme < site < user < session
```

Dev mode writes only the `user` and `session` layers. "Make these the
defaults" ({{F47}}) exports the difference between the top layers and `site`
as an `overrides` LiNo document. The sample
[samples/overrides.lino](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/samples/overrides.lino)
shows the patch format:

```lino
(user-overrides: overrides
  (layer user)
  (base app)
  (set greeting text 'Hello, agents')
  (set material3 token color.primary '#00639B'))
```

Our sites already do this by hand: konard.github.io keeps only the difference
from the defaults in `localStorage` and immortality keeps
`immortality.ui-settings.v2` diffs
([konard-github-io-and-links-visuals.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md),
[immortality-and-anime-avatar.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md)).

## Goal

`packages/ui-config` (`@link-foundation/ui-config`) resolves every property
through the five layers, tells which layer won, writes user/session overrides,
and imports/exports layers as `overrides` LiNo patches.

## Scope

### In scope

- Patch format: `(<name>: overrides (layer L) (base DOC) (set ...) (unset ...))`.
- `set` semantics: `(set ID NAME VALUES...)`. If `NAME` equals the element's
  kind, it replaces the `positional` values (`(set greeting text 'Hello, agents')`
  changes the text). If `NAME` is a keyed prop (`token`, declared in a list
  `keyedProps`, default `['token', 'state']`), the first value is the key
  (`token color.primary`). Otherwise it replaces the prop (last wins).
- `(unset ID NAME [KEY])` removes the override in that layer.
- `resolve`, `explain`, `set`, `unset`, `clear`, `exportPatch`, `importPatch`,
  `subscribe`, `bindStore`.
- Persistence adapters for `user` (localStorage) and `session` (sessionStorage).

### Out of scope

- Structural overrides (insert/remove/move elements) — later; dev mode records
  those through {{F08}} and {{F14}}.
- Settings schemas, presets and share links ({{F15}}); the dev mode UI
  ({{F46}}); the hand-off flow ({{F47}}).

## Dependencies

- {{F08}} (blocker): store transactions and events. Consumed: `bindStore`
  applies the resolved values as one transaction with `origin: 'config'`.
  Before it merges, test `resolve` and patches against plain `UiDocument`
  objects from {{F06}}.
- Related: {{F07}} (typed values; `defaults` layer is built from kind schema
  `default` entries), {{F11}} (theme layer), {{F13}} (locale setting),
  {{F15}}, {{F46}} (expects `resolve(id, name) -> { value, layer }`), {{F47}}.

## Step-by-step plan

1. Create `packages/ui-config/package.json`
   (`"name": "@link-foundation/ui-config"`), dependencies
   `@link-foundation/ui-core`, `@link-foundation/ui-store` (workspace).
2. `src/layers.js`: `export const LAYERS = ['defaults', 'theme', 'site', 'user', 'session'];`
   Each layer is `Map<string, Override>` keyed by `id + '\u0000' + name + '\u0000' + key`.
3. `src/patch.js`: `readPatch(text) → { name, layer, base, ops, diagnostics }`
   using `parse` from `ui-core`; `writePatch({ name, layer, base, ops }) → string`
   using `format`. Unknown op names, missing ids or values become diagnostics.
   Limits: max 64 KiB of text, max 2,000 ops (configurable).
4. `src/config.js`:
   ```js
   /** @param {{ document: UiDocument, layers?: Partial<Record<Layer, string>>, keyedProps?: string[] }} options */
   export function createConfig(options) {}
   // config.resolve(id, name, key?) -> { value: unknown[], layer: Layer } | undefined
   // config.explain(id, name, key?) -> Array<{ layer: Layer, value: unknown[] }>  (lowest first)
   // config.set(layer, id, name, values, key?)   only 'user' | 'session', else throws
   // config.unset(layer, id, name, key?); config.clear(layer)
   // config.loadLayer(layer, patchText)           any layer (site/theme are loaded, never edited)
   // config.effective() -> UiDocument             base document with all layers applied
   // config.exportPatch({ layers: ['user', 'session'], against: 'site', name }) -> string
   // config.importPatch(text, layer)
   // config.subscribe(listener) -> unsubscribe    events { layer, id, name, key, before, after }
   // config.bindStore(store) -> unbind
   ```
5. `exportPatch` is diff-only: an override is written only if its value differs
   from the value resolved from the layers below `against` and including it.
   Output for the sample after `set('user', 'greeting', 'text', ['Hello, agents'])`
   must equal the sample (`samples/overrides.lino`) except for the name.
6. `src/explain.js`: `describeChanges(config, layers)` returns plain English
   lines for agents (R12), e.g.
   `greeting: text changed from 'Hello, links' (site) to 'Hello, agents' (user)`.
7. `src/storage.js`: `persistLayer(config, layer, storage, key)` writes the
   patch text diff-only on every change and restores it on start; default keys
   `link-ui.config.user.v1` and `link-ui.config.session.v1`. Invalid stored text
   is ignored with a diagnostic (never crashes the page).
8. README with the layer table, patch grammar and examples; changeset.

## Acceptance criteria

- [ ] `resolve.test.js`: with a value in all five layers, `resolve` returns the
      `session` value; after `clear('session')` it returns `user`, and so on
      down to `defaults`; `explain` lists all five in order.
- [ ] `config.set('site', ...)` throws; `config.set('user', ...)` works.
- [ ] `patch.test.js`: `readPatch(samples/overrides.lino)` gives `layer: user`,
      `base: app` and two `set` ops; `writePatch(readPatch(t))` re-parses to the
      same ops for every fixture.
- [ ] `export.test.js`: setting a user value equal to the site value exports an
      empty patch (no `set` lines); the sample scenario reproduces
      `samples/overrides.lino` ops.
- [ ] `(set material3 token color.primary '#00639B')` changes only the
      `color.primary` token, not other `token` props.
- [ ] Patches over the size or op limits, and unknown ids, give diagnostics and
      change nothing.
- [ ] `bind-store.test.js`: changing the user layer emits one store transaction
      with `origin: 'config'`.
- [ ] `storage.test.js` (in-memory `Storage` stub): reload restores the user
      layer; corrupted stored text is ignored.
- [ ] `npm test`, `npm run lint`, `npm run format:check`,
      `npm run check:duplication` pass.
