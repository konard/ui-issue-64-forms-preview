## Context

Issue #1 requires the framework to be usable from Vue.js (R20). None of our
apps use Vue today; the only Vue code is the `vue-usage` example of
lino-i18n, which the inventory names as the pilot for this binding
([ui-projects-inventory.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/ui-projects-inventory.md)
sections 4 and 5, "Wave 6").

The architecture keeps Vue thin: `ui-dom` ({{F16}}) renders custom elements,
and the Vue package only mounts it, exposes the store as reactive state and
lets Vue components render custom kinds. Vue supports custom elements when the
compiler is told which tags are custom
([existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)
section 1, "Web Components" and "Stencil"). The public names mirror the React
adapter ({{F18}}) so documentation and examples stay parallel.

## Goal

Publish `@link-foundation/ui-vue` with a `UiView` component, a Vue plugin,
composables over the store, and Vue components for custom dialect kinds.

## Scope

### In scope

- `UiView` component with props `source`, `store`, `actions`, `components`
  and an `action` emit.
- `createUiPlugin({ store, actions })` that provides the store and action
  registry with `provide`/`inject`.
- Composables: `useUiStore(selector)`, `useUiElement(id)`,
  `useUiProp(id, name)`, `useUiAction(name, handler)`; they return
  `Readonly<ShallowRef>` values and clean up with `onScopeDispose`.
- `components` prop: Vue components rendered into `ui-dom` host elements with
  `<Teleport>`.
- A documented `compilerOptions.isCustomElement` setting for `ui-*` tags
  (Vite plugin option snippet and an exported helper `isUiCustomElement`).
- SSR safety: `renderToString` from `vue/server-renderer` does not touch
  `window`; with the `ssr` prop it inlines `renderToHTML` from {{F16}}.
- Type declarations and an example Vite + Vue app.

### Out of scope

- Re-implementing built-in kinds as Vue components.
- Vue SFC import to LiNo ({{F51}}), code export to Vue source ({{F52}}).
- Nuxt module (later issue if needed); Vue 2.

## Dependencies

- {{F16}} (blocker): `render(container, store, options)`, `RenderHandle`,
  `defineKind`, `renderToHTML`, the `ui-action` event and `onAction`.
- Indirect: {{F08}} store (`subscribe`, reads, transactions), {{F06}}
  `parse` for `source` strings.
- Related: {{F18}} (same API names; copy the test list), {{F25}} (actions
  registry; accept a plain `{ name: fn }` object until it merges), {{F51}},

## Step-by-step plan

1. Create `packages/ui-vue/package.json`: name `@link-foundation/ui-vue`,
   `"type": "module"`, `peerDependencies` `vue` `^3.4` (check the current
   minor and test against the latest 3.x). Dependencies:
   `@link-foundation/ui-dom`, `@link-foundation/ui-store`,
   `@link-foundation/ui-core`. Dev dependencies: `vue`, `@vue/test-utils`
   (MIT), `jsdom` (MIT).
2. `src/composables.js`:
   ```js
   /**
    * Reactive slice of the store. Recomputes on store change events and
    * assigns only when the selected value changed (Object.is).
    * @template T
    * @param {(store: Store) => T} selector
    * @param {Store} [store]  defaults to the injected store
    * @returns {Readonly<import('vue').ShallowRef<T>>}
    */
   export function useUiStore(selector, store) {}
   /** @param {string} id @returns {Readonly<ShallowRef<UiNode | undefined>>} */
   export function useUiElement(id) {}
   /** @param {string} id @param {string} name */
   export function useUiProp(id, name) {}
   /** Registers a handler for the lifetime of the current effect scope. */
   export function useUiAction(name, handler) {}
   ```
   Subscribe with `store.subscribe` and unsubscribe in `onScopeDispose`.
3. `src/plugin.js`: `createUiPlugin({ store, actions })` returns
   `{ install(app) }`; it calls `app.provide(UI_STORE_KEY, store)` and
   `app.provide(UI_ACTIONS_KEY, registry)`. Export the injection keys as
   `Symbol`s.
4. `src/UiView.js` (render function, no SFC, so no build step is needed for
   the package): `defineComponent` that renders `h('div', { ref, 'data-ui-root': '' })`,
   calls `render` from `ui-dom` in `onMounted`, `handle.destroy()` in
   `onBeforeUnmount`, and re-creates the store only when `source` changes
   (`watch`).
5. Custom kinds: for each entry of `components`, call `defineKind` with a
   spec whose `create` returns a `<ui-vue-host>` element and pushes
   `{ id, host }` into a `shallowReactive` list; `UiView` renders
   `h(Teleport, { to: host }, h(Comp, { id }))` for each entry. Inside, the
   component reads its props with `useUiElement(id)`.
6. Actions: listen for `ui-action` on the root, emit `action` with the
   detail and call the matching handler from props or the plugin registry;
   unknown names warn once in development.
7. `src/custom-elements.js`: `export const isUiCustomElement = (tag) => tag.startsWith('ui-')`.
   README snippet:
   ```js
   vue({
     template: { compilerOptions: { isCustomElement: isUiCustomElement } },
   });
   ```
8. SSR: when `ssr` is set and there is no `window`, render the root with
   `innerHTML: renderToHTML(...)`; on the client, clear and render.
9. Example `examples/vue/` (Vite + Vue) rendering
   `docs/case-studies/issue-1/samples/document.lino`, a button that changes
   `greeting` through the store, and one custom kind rendered by a Vue
   component.
10. Tests, README with a quick start, changeset.

Example usage:

```js
import { createApp, h } from 'vue';
import { UiView, createUiPlugin } from '@link-foundation/ui-vue';

createApp({
  render: () =>
    h(UiView, {
      source: "(app: document (ok: button (label 'OK') (on press (save))))",
    }),
})
  .use(createUiPlugin({ actions: { save: () => console.log('saved') } }))
  .mount('#app');
```

## Acceptance criteria

- [ ] `view.test.js`: mounting `UiView` with the sample renders
      `ui-button[data-link-id="ok"]` (jsdom, `@vue/test-utils` `mount`).
- [ ] Changing a prop in the store updates the DOM, and the `UiView`
      render function runs once (counter in the test).
- [ ] `composables.test.js`: `useUiProp('greeting', 'text')` triggers a
      watcher only when that prop changes; disposing the scope removes the
      store listener (listener count returns to the previous value).
- [ ] `actions.test.js`: clicking `ok` emits `action` with the F16 detail and
      calls `actions.save` once; unknown actions only warn.
- [ ] `components.test.js`: a `chart` kind renders a Vue component through
      `Teleport` and updates after a store change.
- [ ] `plugin.test.js`: composables inside a component find the store
      provided by `createUiPlugin`.
- [ ] `ssr.test.js`: `renderToString` works without `window`; with `ssr`
      the HTML contains `data-link-id="ok"`.
- [ ] Mounting and unmounting 100 times leaves no store listeners and no
      `ui-*` nodes in `document.body`.
- [ ] The example builds (`npm --prefix examples/vue run build`) and a
      screenshot is attached to the pull request.
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication` and
      `npm test` pass.
