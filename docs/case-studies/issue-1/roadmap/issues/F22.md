## Context

R21 asks for a native Swift implementation. The architecture plans a SwiftPM
package with a SwiftUI renderer that reads the same LiNo documents as the web
and passes the shared conformance fixtures in `docs/spec/`
([ARCHITECTURE.md](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md),
"Platforms" and "Native ports"). The research recommends native SwiftUI for
Apple HIG fidelity, even though Compose Multiplatform can also target iOS, and
warns not to depend on Skip (LGPL libraries)
([existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)
section 8).

There is no Swift `links-notation` implementation upstream
([links-notation-ecosystem.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)
section 2 and section 5, item 10), so {{F21}} creates the parser. No Swift app
of ours exists yet; sleep-count-down (WidgetKit), time-left and resonance are
the natural pilots
([ui-projects-inventory.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/ui-projects-inventory.md)
sections 4 and 5).

## Goal

Create `packages/ui-swift/` with a SwiftUI view `UiView(document:)` that
renders the basic dialect kinds with native controls, resolves design tokens,
dispatches actions by name, marks every view with its link ID, and passes
render-tree snapshot tests for the shared fixtures.

## Scope

### In scope

- Swift targets: `UiSwiftCore` (Foundation only: element tree model, token
  resolution, platform-neutral render tree) and `UiSwiftUI` (SwiftUI views).
- Kinds: `document`, `stack`, `text`, `button`, `image`; unknown kinds render
  an empty view with a logged diagnostic.
- Tokens: the Swift output of {{F11}} as the default theme, plus runtime
  loading of a theme `.lino` file through the {{F21}} parser.
- Actions: `(on press (navigate home))` calls an `onAction` closure with
  `UiAction(source: "ok", event: "press", action: ["navigate", "home"])`.
- `.accessibilityIdentifier(id)` on every view; native accessibility labels.
- Render-tree snapshots for every fixture in `docs/spec/fixtures/` that uses
  only supported kinds, stored as LiNo.
- CI workflow on a macOS runner.

### Out of scope

- Behaviour machines, the full control set and overlays (follow-ups after
  {{F25}}–{{F27}}).
- The HIG theme pack ({{F42}}), animation ({{F44}}), dev mode on native.
- A Swift port of the full `ui-store` (undo/redo, persistence).

## Dependencies

- {{F21}} (blocker): the Swift parser module (`Link` values from LiNo text)
  and, if it includes it, the projection to the element tree required by the
  `docs/spec/fixtures/*.tree.json` files. If F21 ships only the parser,
  implement the projection in `UiSwiftCore/Projection.swift` following
  `docs/spec/projection.md` from {{F03}}.
- {{F11}} (blocker): the generated Swift token file (names and value types
  exactly as F11 emits them) used as the default theme.
- Related: {{F03}} (fixtures and vocabulary), {{F24}} (same design for
  Kotlin; keep the render-tree format identical), {{F20}} (same mapping
  table), {{F42}}.
- To start before F21 merges, build `UiSwiftCore` from hand-written element
  trees in tests and add the text entry point last.

## Step-by-step plan

1. SwiftPM needs `Package.swift` at the repository root for consumers that
   add the repository URL. If {{F21}} already created it, add the new
   targets there; otherwise create it with `path:` pointing into
   `packages/ui-swift/Sources/...`. Declare the minimum platforms (SwiftUI
   `@Observable` needs iOS 17 / macOS 14; check the current toolchain and
   Xcode on the GitHub macOS runner).
2. `UiSwiftCore/Model.swift`:
   ```swift
   public struct UiNode: Equatable { public let id: String?; public let kind: String
     public var props: [UiProp]; public var children: [UiNode] }
   public struct UiAction: Equatable { public let source: String; public let event: String
     public let action: [String] }
   ```
   Match the field names of the F03 tree JSON (`id`, `kind`, `positional`,
   `properties`, `children`).
3. `UiSwiftCore/RenderTree.swift`: a platform-neutral mapping used by the
   views and by the tests:
   ```swift
   public struct RenderNode: Equatable { public let id: String?; public let primitive: String
     public let props: [(String, String)]; public let children: [RenderNode] }
   public func renderTree(_ node: UiNode, theme: UiTheme) -> RenderNode
   ```
   Mapping: `document` to `ScrollView`, `stack` to `VStack` or `HStack`
   (from `direction`, `spacing` from `gap`), `text` to `Text`, `button` to
   `Button`, `image` to `AsyncImage` with an accessibility label from `alt`,
   other kinds to `EmptyView` plus a diagnostic.
4. `UiSwiftCore/Theme.swift`: `UiTheme` resolves `(token space.medium)` to
   a `Double` or colour string; built from the F11 generated file or from a
   theme `.lino` document.
5. `UiSwiftCore/Snapshot.swift`: `func dumpLino(_ node: RenderNode) -> String`
   producing, for the sample document:
   ```lino
   (app: ScrollView
     (body: VStack (spacing 16)
       (greeting: Text 'Hello, links')
       (ok: Button (label 'OK'))))
   ```
   Use the F21 formatter (or escaping rules) for quoting, never ad-hoc
   string concatenation of values.
6. `UiSwiftUI/UiView.swift`: `public struct UiView: View` with
   `init(document: UiDocumentModel, theme: UiTheme = .default, onAction: @escaping (UiAction) -> Void = { _ in })`.
   It switches on `RenderNode.primitive` and applies
   `.accessibilityIdentifier(id)`. `UiDocumentModel` is an `@Observable`
   class holding one observable object per element, so `setProp` re-renders
   only that element's view.
7. Actions: a `Button` calls `onAction` with the parsed `on press` link.
   Strings are never executed; `navigate` targets with a `javascript:` scheme
   are rejected (spec `behaviour.md`).
8. Tests in `packages/ui-swift/Tests/UiSwiftCoreTests/`:
   `RenderTreeTests`, `ThemeTests`, `ActionTests`, `FixtureTests` (for every
   supported fixture: the set of IDs and parent/child pairs in the render tree
   equals the one in `.tree.json`, and `dumpLino` equals
   `Tests/Snapshots/<area>/<name>.render.lino`). Set `UPDATE_SNAPSHOTS=1` to
   rewrite snapshots.
9. Example: `examples/swift/UiDemo` executable target (macOS SwiftUI app)
   rendering `docs/case-studies/issue-1/samples/document.lino`.
10. `.github/workflows/swift.yml`: `runs-on: macos-latest`, path filters
    `packages/ui-swift/**`, `Package.swift`, `docs/spec/**`; steps
    `swift build` and `swift test`. `UiSwiftCore` tests should also pass on
    Linux (optional second job with `swift:` container).

## Acceptance criteria

- [ ] `swift build` and `swift test` pass on the macOS CI job.
- [ ] `FixtureTests`: every fixture in `docs/spec/fixtures/` with only
      supported kinds has a `.render.lino` snapshot, and the test fails if a
      fixture is added without one.
- [ ] For each of those fixtures the IDs and parent/child pairs in the render
      tree equal those in its `.tree.json`.
- [ ] `RenderTreeTests` covers each row of the mapping table and the unknown
      kind diagnostic.
- [ ] `ThemeTests`: `(token space.medium)` resolves through the F11 default
      theme; a missing token gives a diagnostic, not a crash.
- [ ] `ActionTests`: pressing `ok` (invoked through the action closure in a
      test) yields `UiAction(source: "ok", event: "press", action: ["navigate", "home"])`;
      a `javascript:` target is rejected.
- [ ] Every rendered view has `.accessibilityIdentifier` equal to its link ID
      (checked in `RenderTreeTests` on the render tree; optionally with
      ViewInspector on the views).
- [ ] A screenshot of `UiDemo` on macOS (light and dark) is attached to the
      pull request.
- [ ] No dependency with a non-permissive licence (`Package.resolved` reviewed).

## How to verify

```bash
swift build
swift test
swift test --filter FixtureTests
swift run UiDemo   # macOS only; take a screenshot
```

## Prior art and libraries

- Swift Package Manager (Apache-2.0) and SwiftUI: ADOPT (existing-solutions.md
  section 8).
- ViewInspector and swift-snapshot-testing (both MIT, verify) as optional test
  dependencies.
- Skip (skip.dev): learn only; LGPL libraries must not be dependencies.
- Ionic platform modes and Flutter Cupertino: one tree, platform look
  (existing-solutions.md sections 4 and 8).
- links-notation implementations in other languages as the model for the
  Swift API shape (links-notation-ecosystem.md section 2).
