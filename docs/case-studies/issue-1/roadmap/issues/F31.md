## Context

R13 asks the framework to own charts. None of our chat projects has charts
today (formal-ai problem 12 in its
[research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md)).
immortality has `LineChart`, `Gauge`, `StatTile` and a sparkline, and every
chart there has an accessible twin: a `DataTable`, `role="img"` and a text
summary
([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md)).

The library survey
([existing solutions](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md))
recommends: D3 modules (ISC, adopt `d3-scale`, `d3-shape`); Vega and
Vega-Lite (BSD-3, learn and interoperate: our chart dialect mirrors Vega-Lite);
ECharts (Apache-2.0, candidate renderer for heavy charts); Observable Plot
(ISC); uPlot and Chart.js (MIT, learn). Highcharts and amCharts are avoided
(not permissive).

## Goal

A chart is described in Links Notation with the grammar of Vega-Lite (data,
mark, encoding), rendered by our own small SVG renderer for the common marks,
with an optional adapter for ECharts for large or complex charts, and every
chart has an accessible table twin.

## Scope

### In scope

- The chart dialect: `chart` with `data`, `mark`
  (`line`, `area`, `bar`, `point`, `arc`), `encoding` (`x`, `y`, `color`,
  `size`, `tooltip`), `title`, `description`.
- `chart-model.js`: from LiNo to a normalised spec (pure).
- `svg-renderer.js` using `d3-scale` and `d3-shape`.
- Axes, legend, tooltip, keyboard navigation between data points.
- `stat-tile`, `gauge` and `sparkline` as small charts.
- Table twin and text summary for every chart.
- `echarts-adapter.js` (optional peer dependency, loaded lazily).

### Out of scope

- Importing Vega-Lite JSON (that is in `@link-foundation/ui-convert`, see
  {{F53}}); this issue only keeps the model compatible.
- Diagrams ({{F32}}) and links networks ({{F34}}).
- Chart animation beyond a simple fade (see {{F44}}).

## Dependencies

- **Blocked by {{F16}}**: the custom element base and incremental updates. The
  pure `chart-model.js` and the SVG string renderer can be written before it.
- **Related:** {{F11}} (chart colours come from tokens such as
  `color.chart.1`), {{F29}} (the table twin uses `table`), {{F53}} (Vega-Lite
  import), {{F55}} (gallery).

## Step-by-step plan

1. Create `packages/ui-components/src/charts/` and export it.
2. Write `chart-model.js`:
   ```js
   /**
    * @param {import('links-notation').Link[]} links
    * @returns {ChartSpec} normalised spec with resolved data and encodings
    * @throws {ChartSpecError} with the position of the bad link
    */
   export function chartFromLinks(links) {}
   /** @returns {string} LiNo text */
   export function chartToLino(spec) {}
   ```
   Field types follow Vega-Lite: `quantitative`, `temporal`, `ordinal`,
   `nominal`.
3. Write `scales.js` that maps encodings to `d3-scale` scales (bundle and pin
   the version in `package.json`; never load D3 from a CDN at run time).
4. Write `svg-renderer.js`:
   `renderChartSvg(spec, { width, height, tokens }) → string`. It must be
   deterministic, so the same input gives the same SVG (snapshot tests).
5. Write `chart.js` (the custom element): renders the SVG, a visually hidden
   `table` twin (button "Show data table" makes it visible), `role="img"` with
   `aria-label` from `description`, and arrow-key navigation between points
   with a tooltip that is also announced through `aria-live`.
6. Write `stat-tile.js`, `gauge.js` and `sparkline.js`.
7. Write `echarts-adapter.js`: `toEChartsOption(spec)` (pure, tested) and a
   lazy `import('echarts')` only when `(renderer echarts)` is set. ECharts is
   an optional peer dependency.
8. Colours: use the token series `color.chart.1` … `color.chart.8`; pick them
   so each one has 3:1 contrast with the background.
9. Gallery page `packages/ui-components/examples/charts.html`.

Input example:

```lino
(sales: chart
  (title 'Monthly sales')
  (description 'Sales grew from 12 to 30 between January and June')
  (data
    (row (month 2026-01) (value 12))
    (row (month 2026-02) (value 18))
    (row (month 2026-03) (value 30)))
  (mark line)
  (encoding
    (x (field month) (type temporal))
    (y (field value) (type quantitative))))
```

## Acceptance criteria

- [ ] `chartFromLinks(parse(chartToLino(spec)))` equals `spec` for every
      fixture.
- [ ] A bad spec (unknown mark, missing field) throws `ChartSpecError` with the
      link position (test).
- [ ] `renderChartSvg` output is identical across two runs (snapshot test).
- [ ] Line, area, bar, point and arc marks render in the gallery (screenshot
      per mark).
- [ ] Every chart has a data table twin and a non-empty accessible name
      (Playwright plus axe).
- [ ] Arrow keys move between points and the value is announced (Playwright
      checks the `aria-live` text).
- [ ] `echarts` is not in the bundle unless `(renderer echarts)` is used
      (test of the built entry imports).

## How to verify

```bash
node --test packages/ui-components/tests/charts/*.test.js
npx playwright test packages/ui-components/tests/e2e/charts.spec.js
npm run lint && npm run format:check && npm run check:duplication
```

Expected screenshots: the five marks in the light and dark themes, the sales
chart with a focused point and tooltip, and the same chart with the table twin
shown.

## Prior art and libraries

- D3 modules `d3-scale` and `d3-shape` (ISC): adopt.
- Vega-Lite (BSD-3-Clause): grammar to mirror.
- ECharts (Apache-2.0): optional renderer.
- Observable Plot (ISC), uPlot (MIT), Chart.js (MIT): learn.
- Highcharts, amCharts: avoid (not permissive).
- immortality `LineChart`, `DataTable`, `Gauge`, `StatTile` (Unlicense).
- Check the current versions of all of the above before adding them.
