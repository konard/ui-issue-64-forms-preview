## Context

`link-foundation/ui` was created from the template
[link-foundation/js-ai-driven-development-pipeline-template](https://github.com/link-foundation/js-ai-driven-development-pipeline-template).
The planning for issue #1 found that the repository still identifies itself as
that template everywhere. Anyone who installs, links or reads the project sees
the wrong name, and the release pipeline would publish the template's package
name:

| Place                                                                                                    | Current value                                                                           |
| -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `package.json` `name`                                                                                    | `@link-foundation/example-package-name` (version `0.11.31`)                             |
| `package.json` `description`                                                                             | `A JavaScript/TypeScript package template for AI-driven development`                    |
| `package.json` `repository.url`                                                                          | `git+https://github.com/link-foundation/js-ai-driven-development-pipeline-template.git` |
| `package.json` `bin`, `keywords`                                                                         | `example-package-name` → `./bin/example-package-name.js`; `template`, `ai-driven`       |
| `README.md` title                                                                                        | `# js-ai-driven-development-pipeline-template`                                          |
| `docs/CONTRIBUTING.md` title                                                                             | `# Contributing to js-ai-driven-development-pipeline-template`                          |
| `src/index.js`                                                                                           | template example functions `add`, `multiply`, `delay`                                   |
| `.changeset/*.md`                                                                                        | 7 pending template changesets that would release the template package                   |
| `tests/package-metadata.test.js`, `tests/release-preflight.test.js`, `experiments/cli-symlink-probe.mjs` | assert the template name and binary                                                     |

`CHANGELOG.md` also holds the template's release history.

## Goal

The repository identifies itself as the associative UI framework
`link-foundation/ui` in its package metadata, README, contributing guide,
source entry point and tests. The CI pipeline keeps working.

## Scope

### In scope

- Rename the root package. Recommended: make the root `package.json` a private
  workspace root named `@link-foundation/ui-monorepo`, which is never published.
  The packages from {{F01}} get published names such as
  `@link-foundation/ui-core`. If the maintainer prefers a single published
  package for now, use `@link-foundation/ui`. Record the decision in the pull
  request.
- Set `description`, `repository.url`
  (`git+https://github.com/link-foundation/ui.git`), `homepage`, `bugs` and
  `keywords`. Suggested keywords: `ui`, `links-notation`, `associative`,
  `design-system`, `wysiwyg`.
- Remove the template `bin` entry and `bin/example-package-name.js` (the
  framework has no CLI yet). Replace `src/index.js` and `src/index.d.ts` with a
  minimal placeholder that exports the package version and nothing else, so the
  smoke and package tests still have an entry point.
- Rewrite the `README.md` title and introduction for the framework. Keep the
  sections that `scripts/check-required-docs.sh` requires (Quick Start,
  Configuration, Contributing, License), and link `docs/ARCHITECTURE.md` and
  `docs/ROADMAP.md`. Keep the template's CI documentation in a separate
  `docs/CI.md` if the README still needs it.
- Retitle `docs/CONTRIBUTING.md`.
- Delete the template's pending `.changeset/*.md` entries (not `config.json` or
  `README.md`). Move `CHANGELOG.md` to `docs/template-history/CHANGELOG.md` and
  start a fresh `CHANGELOG.md`.
- Update the tests that assert the template name
  (`tests/package-metadata.test.js`, `tests/release-preflight.test.js`) and
  `experiments/cli-symlink-probe.mjs`.

### Out of scope

- Creating the workspace layout: that is {{F01}}.
- Publishing to npm: that is {{B05}}.
- Moving the template case studies: that is {{B02}}.

## Dependencies

None. This bug blocks {{F01}} (the workspace needs the final root name) and
{{B05}} (npm release needs the final package name).

## Step-by-step plan

1. Run `grep -rn "example-package-name\|js-ai-driven-development-pipeline-template" --exclude-dir=node_modules --exclude-dir=docs/case-studies .`
   and save the list in the pull request description.
2. Edit `package.json` as described above, then run
   `npm install --package-lock-only` so `package-lock.json` gets the new name.
3. Remove `bin/example-package-name.js` and the `bin` field. Update
   `tests/package-metadata.test.js`: assert the new name, assert that `bin` is
   absent, and drop the symlink CLI test.
4. Replace `src/index.js` with
   `export const version = '<version from package.json>';` (or read it from
   `package.json`), update `src/index.d.ts` and `tests/index.test.js`.
5. Update `tests/release-preflight.test.js` fixtures that embed the package
   name.
6. Rewrite the `README.md` header and introduction, and retitle
   `docs/CONTRIBUTING.md`.
7. Delete the template changesets and move `CHANGELOG.md` as described. Add
   one new changeset, `.changeset/rename-to-ui.md`, with a `minor` bump that
   says "Rename the template package to the associative UI framework".
8. Run every quality gate (see How to verify) and fix any fallout.

## Files to create or change

## Acceptance criteria

- [ ] `grep -rn "example-package-name\|js-ai-driven-development-pipeline-template" --exclude-dir=node_modules --exclude-dir=case-studies --exclude-dir=template-history .`
      prints nothing, except links that intentionally credit the template.
- [ ] `node -p "require('./package.json').repository.url"` prints
      `git+https://github.com/link-foundation/ui.git`.
- [ ] The README title names the UI framework, and the README links
      `docs/ARCHITECTURE.md` and `docs/ROADMAP.md`.
- [ ] `bash scripts/check-required-docs.sh` passes.
- [ ] No template changeset is pending; exactly one new changeset exists.
- [ ] `npm test`, `npm run lint` and `npm run format:check` pass locally and in
      CI.
