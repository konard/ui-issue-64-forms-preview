## Context

All visible text of the framework and of the apps built with it must be
translatable, and the translations must live in LiNo (R2). Our apps already
localise in different ways (R23 asks to remove that duplication):

- formal-ai uses [`lino-i18n`](https://www.npmjs.com/package/lino-i18n)
  0.4.0 (`js/i18n.js`, catalogs such as `js/i18n-catalog.lino`, locales en,
  ru, zh, hi), checks in CI that every language has the same keys
  (`tests/e2e/scripts/check-i18n-catalog.mjs`) and lints hard-coded language
  ([formal-ai issue 659](https://github.com/link-assistant/formal-ai/issues/659)); some labels are still JavaScript dictionaries
  (`LABELS` in `site-chrome.js`) and there is no right-to-left support
  ([formal-ai.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md)).
- meta-sovereign-chat has its own `i18n.js` with 41 JSON locale files
  ([meta-sovereign-chat.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/meta-sovereign-chat.md)).

`lino-i18n` 0.5.0 (Unlicense, Node ≥ 22.11 per its `engines`) provides
`createI18n`, `parseLinoCatalogs`, `formatLinoCatalogs`, `getLocaleDirection`,
`determineLocale`, CLDR plurals, `{var}`/`{{var}}` interpolation, a browser
entry (`lino-i18n/browser`), loaders (`lino-i18n/loaders`) and a CLI with
`lino-i18n check --dir <dir> [--reference <locale>]`. Verified at planning
time:

```js
import { createI18n, parseLinoCatalogs } from 'lino-i18n';
const locales = Object.fromEntries(
  parseLinoCatalogs(text).map((c) => [c.locale, c.translations])
);
const i18n = createI18n({ locales, defaultLocale: 'en', fallback: ['en'] });
i18n.t('ok.label', {}, { locale: 'ru' }); // 'Хорошо'
```

## Goal

`packages/ui-i18n` (`@link-foundation/ui-i18n`) lets UI documents reference
messages instead of literal text, picks the locale from the configuration
layers ({{F10}}), sets text direction, and ships CI checks for key parity and
hard-coded text.

## Scope

### In scope

- Message references in documents: `(t KEY)` and `(t KEY (PARAM VALUE) ...)`,
  e.g. `(ok: button (label (t ok.label)))`,
  `(greeting: text (t greeting (name 'Ada')))`.
- `createLocalizer({ config, catalogs })`, `resolveText`, `localizeDocument`.
- Locale as the root prop `locale` resolved through {{F10}} layers (so dev
  mode and users can switch it in `user`/`session`), fallback
  `determineLocale(navigator.languages, approved)`.
- Direction: `dir` (`ltr`/`rtl`) from `getLocaleDirection`.
- Framework catalogs in `packages/ui-i18n/locales/` for en, ru, zh, hi.
- Checks: key parity and "no hard-coded text" for LiNo documents.

### Out of scope

- Translating app content (each app's own issue: {{F60}}, {{F61}}, {{F64}}).
- Machine translation workflows (`lino-i18n translate-catalog` exists; not
  wired here).
- Framework adapters other than plain JS (React/Vue use `lino-i18n/react`,
  `lino-i18n/vue` in {{F18}}/{{F19}} if needed).

## Dependencies

- {{F10}} (blocker): `config.resolve(rootId, 'locale')`, `config.set('user', ...)`
  and `subscribe`. Before it merges, pass `{ getLocale, onLocaleChange }`
  callbacks instead of a config object.
- Related: {{F06}}/{{F07}} (value parsing; `(t ...)` becomes a `message`
  typed value), {{F16}} (renders `dir` and resolved text), {{F37}} (language
  selector), {{F61}} (formal-ai migration from 0.4.0).

## Step-by-step plan

1. Create `packages/ui-i18n/package.json` (`"name": "@link-foundation/ui-i18n"`),
   dependencies `lino-i18n` (pin `0.5.0`; check for a newer version first and
   read its CHANGELOG), `@link-foundation/ui-core`. Note the `engines` of
   `lino-i18n` in the README (Node ≥ 22.11 while the root says ≥ 20; raise the
   CI Node version for this package if needed).
2. `src/message.js`: register the `message` value type with {{F07}}:
   `(t ok.label)` → `{ type: 'message', key: 'ok.label', params: {} }`.
3. `src/catalogs.js`: `readCatalogs(text) → Record<locale, Record<key, string>>`
   (wraps `parseLinoCatalogs`); `loadCatalogDir(dir)` for Node (wraps
   `loadLocalesFromDirectory` from `lino-i18n/loaders`).
4. `src/localizer.js`:
   ```js
   /**
    * @param {{ config?: Config, catalogs: Record<string, Record<string, string>>,
    *           approved?: string[], defaultLocale?: string }} options
    */
   export function createLocalizer(options) {}
   // l.locale() -> 'ru'; l.direction() -> 'ltr' | 'rtl'
   // l.text(value, params?) -> string        (message value or literal)
   // l.localizeDocument(doc) -> UiDocument   (messages replaced, root gets (dir ...) and (lang ...))
   // l.subscribe(listener) -> unsubscribe    (locale changes)
   ```
   Missing keys return the key and call `options.onMissing(key, locale)`.
5. Framework catalog `packages/ui-i18n/locales/ui.lino` (all four locales in
   one file):
   ```lino
   en
     ui
       dialog
         close "Close"
       settings
         reset "Reset"
   ru
     ui
       dialog
         close "Закрыть"
       settings
         reset "Сбросить"
   ```
   (zh and hi likewise; ask the reviewer to confirm translations.)
6. `scripts/check-i18n.mjs` (in the package, exposed as root script
   `check:i18n`): runs `lino-i18n check --dir packages/ui-i18n/locales --reference en`
   and then `checkHardcodedText(files)`.
7. `src/lint.js`: `checkHardcodedText(docText, { textProps = ['label', 'title', 'placeholder', 'description'], kinds = { text: true } })`
   returns diagnostics for literal strings in those props or in `text` positional values
   when the document root has `(i18n required)`. Uses `ui-core` `parse`,
   never regex.
8. README: authoring guide, the `(t ...)` syntax, how to add a locale, RTL.

## Acceptance criteria

- [ ] `localizer.test.js`: with locale `ru` set in the `user` layer,
      `l.text({ type: 'message', key: 'ui.dialog.close' })` is `Закрыть`;
      clearing the layer falls back to `en`; missing keys call `onMissing`.
- [ ] Interpolation and plurals work through lino-i18n (`{name}`, and a plural
      key tested for `ru` counts 1, 3, 5).
- [ ] `direction.test.js`: `ar` and `he` give `rtl`; `en`, `ru`, `zh`, `hi`
      give `ltr`; `localizeDocument` adds `(dir rtl)` to the root for `ar`.
- [ ] `lint.test.js`: `(ok: button (label 'OK'))` in a document with
      `(i18n required)` gives one diagnostic; `(label (t ok.label))` gives none.
- [ ] `npm run check:i18n` passes; removing one key from `ru` makes it fail.
- [ ] `npm test`, `npm run lint`, `npm run format:check`,
      `npm run check:duplication` pass.
