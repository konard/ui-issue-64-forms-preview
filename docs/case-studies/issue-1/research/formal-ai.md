# Research: link-assistant/formal-ai web UI

Scope: the browser-facing UI of [link-assistant/formal-ai](https://github.com/link-assistant/formal-ai).
That covers the `js/` folder, the static HTML pages, CSS, i18n through `lino-i18n`, IndexedDB memory,
the web-search component, the chat interface, settings, and trace and links-network visualization.
We read it as input for the associative UI framework planned in
[link-foundation/ui#1](https://github.com/link-foundation/ui/issues/1).

Method:

- A sparse, blob-filtered shallow clone of `js/`, `ts/`, `packages/`, `package.json` and `docs/`. The repo is about 1 GB and was not fully cloned.
- Issue bodies and titles fetched with `gh`.
- All downloaded content was treated as data and never executed.

URL bases:

- `FA` = `https://github.com/link-assistant/formal-ai/blob/main/`
- `I` = `https://github.com/link-assistant/formal-ai/issues/`

## 1. Overview

### 1.1 Stack

| Layer                   | Technology (version pinned in `package.json`)                                                                                                                                                                                                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Chat app (`/app/`)      | React 19.3.1, written as JSX, no TypeScript at runtime                                                                                                                                                                                                                    |
| Component library       | `@chakra-ui/react` ^3.37 with `@emotion/react`. Adoption is incremental (issues [#541](https://github.com/link-assistant/formal-ai/issues/541), [#550](https://github.com/link-assistant/formal-ai/issues/550)), configured with `preflight: false` and empty `globalCss` |
| Markdown / sanitising   | `marked` 18.1.1 and `dompurify` 3.4.17                                                                                                                                                                                                                                    |
| Diagrams                | `mermaid` 12.2.0, loaded on demand (`mermaid.bundle.js`) with `securityLevel: strict`                                                                                                                                                                                     |
| OCR                     | `tesseract.js` 7, loaded on demand (`ocr.bundle.js`, experimental setting)                                                                                                                                                                                                |
| i18n                    | `lino-i18n` 0.4.0, bundled into `vendor.bundle.js` and exposed as `FormalAiVendor.LinoI18n`                                                                                                                                                                               |
| Web search              | `@link-assistant/web-search` 0.11.1, using RRF merge and dedup, plus a web-capture HTTP adapter                                                                                                                                                                           |
| Code parsing in browser | `@babel/parser`                                                                                                                                                                                                                                                           |
| Syntax highlight        | `js/syntax-highlight.js`, a dependency-free highlighter that emits `hljs-*` classes                                                                                                                                                                                       |
| Engine                  | WASM worker (`js/formal_ai_worker.wasm` from `js/wasm-worker/src/lib.rs`) plus JS worker modules (`js/worker/`, listed in `js/worker-modules.js`)                                                                                                                         |
| Bundling                | `bun build` into IIFEs: `vendor.bundle.js`, `web-search-component.bundle.js`, `ocr.bundle.js`, `mermaid.bundle.js`, `app.js`. The minified bundles are committed ([#953](https://github.com/link-assistant/formal-ai/issues/953))                                         |
| Other pages             | Vanilla JS IIFEs (landing, docs, download, telegram, vscode)                                                                                                                                                                                                              |
| Shells                  | PWA (`manifest.webmanifest`, `pwa-register.js`); Electron desktop (`desktop/main.cjs`, which serves the same `js/` chat and adds a preload bridge); VS Code extension (`vscode/`, desktop and vscode.dev hosts)                                                           |
| Mirror                  | `ts/` is a generated mirror of `js/` (`formal-ai translate --from js --to ts`). Hand edits are forbidden                                                                                                                                                                  |

The architecture doc (`docs/architecture/runtime-and-surfaces.md` §13) states the browser split:

- JavaScript owns UI state, seed fetching, CORS orchestration and DOM integration.
- Rust/WASM owns the parity-sensitive primitives.
- The "three-root doctrine" (R992–R996) now makes JS/TS a full implementation target, with equivalence through the meta-language.

### 2.4 Theming

- **Tokens.** `--fa-*` custom properties are defined in `01-tokens.css`. Dark values come from `:root[data-theme="dark"]` plus a `@media (prefers-color-scheme: dark)` fallback.
- **Selector counts.** About 248 `[data-theme="dark"]` and 244 `[data-theme="light"]` selectors across the CSS. Most dark overrides live in `06-dark-theme.css`.
- **Chakra bridge.** `theme.js` maps tokens 1:1, e.g. `fa.surface.card → var(--fa-surface-card)`. Chakra components therefore follow the same CSS variables without a parallel theme object.
- **Root-class composition.** Skins, chat styles, composer styles and icon packs are orthogonal root classes. The CSS combines them, e.g. `.ui-skin-glass.composer-style-glass-clear`.

### 2.5 i18n

- **Runtime.** `js/i18n.js` is an IIFE exposing `window.FormalAiI18n`. It calls `loadCatalogs([...])` and `createI18n({locales, defaultLocale:'en', fallback:['en']})`, then dispatches `formal-ai:i18n-ready`.
- **Catalog format.** Nested Links Notation blocks (`en` / `buttons` / `key "..."`) with `"""` multiline strings ([#117](https://github.com/link-assistant/formal-ai/issues/117)).
- **CI checks.**
  - Key parity across all locales (`tests/e2e/scripts/check-i18n-catalog.mjs`).
  - A lint against hardcoded natural language ([#659](https://github.com/link-assistant/formal-ai/issues/659), R379).
- **Gaps.**
  - `PUBLISHED_RUNTIME_SOURCE = "lino-i18n@0.3.0"` in `i18n.js`, while `package.json` pins `0.4.0`.
  - The vanilla pages use their own JS `LABELS` dicts instead of the catalogs.

### 2.6 Preferences & memory

- **Preferences (`preferences.js`, 123 lines).**
  - A hand-rolled Links Notation reader/writer with root `demo_preferences` and indented `key "value"` lines. Booleans are stored as `on`/`off`.
  - API: `window.FormalAiPreferences {load, save, format, parse, STORAGE_KEY, ROOT}`.
  - Every page shares the `formal-ai.preferences.v1` key.
  - It does not use the `links-notation` parser.
- **Memory (`memory.js`).**
  - IndexedDB database `formal-ai-demo`, store `events`, root `demo_memory`, bundle header `formal_ai_bundle`, `LINK_STORE_SCHEMA_VERSION "0.2.0"`.
  - Events are append-only. `EXPORT_FIELDS` include `kind`, `role`, `intent`, `tool`, `inputs`, `outputs`, `content`, `attachments`, `sentAt`, `evidence`, `accessCount`, `writeCount`, `conversationId` and `conversationTitle`.
  - It exports `formal-ai-memory.lino`. Import, reset and purge sit behind confirmations ([#196](https://github.com/link-assistant/formal-ai/issues/196)).
  - It reports a `doublets-web` backend only if that global runtime is present.

### 2.7 Web search component

- **Ranking.** `getDefaultProviderIds()` selects the providers, and `mergeResults` merges their results with the `rrf` strategy and `removeDuplicates`.
- **Capture adapter.** Fetches `/fetch?url=…` from a configurable base (default `http://localhost:3000`, 2,000 ms deadline). On transport failure it falls back to a direct CORS fetch.
- **Output.** Results are pushed as evidence strings into the trace. [#153](https://github.com/link-assistant/formal-ai/issues/153) asks for a unified, deduplicated search-result template.

### 2.8 Accessibility snapshot

- **ARIA.** About 89 `aria-*` attributes: `aria-label` ×26, `aria-hidden` ×14, `aria-pressed` ×11. Also 9 `role=status`, plus `radiogroup`/`menu`/`menuitem`/`option` roles and 2 `aria-live` regions.
- **Focus.** `:focus-visible` styles appear in `02`, `03`, `06` and `07`.
- **Reduced motion.** `prefers-reduced-motion` appears only 3 times, all in `04-message-content.css`.
- **Keyboard.** The resizer supports keyboard steps (40 px, 16 px with Shift).
- **Audits.** No systematic audit (axe or similar) exists in CI. Open bug [#447](https://github.com/link-assistant/formal-ai/issues/447): the left panel cannot be scrolled with the mouse.

## 5. Patterns worth adopting

1. **CSS-token → component-library bridge.**
   - One set of `--fa-*` CSS variables is the source of truth.
   - Chakra semantic tokens point at `var(--…)` (`theme.js`).
   - The framework should generate both from one Links Notation token document.
2. **Orthogonal appearance axes as root classes.** Skin × chat style × composer style × icon pack × theme combine freely and are applied as root classes plus CSS vars. This maps directly to a "theme = set of axis values" model.
3. **Icon-pack abstraction.** Each action has a semantic name, mapped per pack (font name, short name, shape), with a `names` text-only fallback. Use this as the basis for public-domain icon handling.
4. **Priority-based responsive overflow.** `data-menu-priority` moves top-bar actions into the drawer as width shrinks. #388 asks for measured sizes; generalize this into a layout primitive.
5. **Collapsible sections with isolate.** An isolate button plus Shift+click "expand only this".
6. **Per-setting reset and reset-all** using a default-detection helper (`settingIsDefault`).
7. **Shared preferences contract** across separately built pages: one storage key, Links Notation format, `data-theme` on `<html>`.
8. **Natural-language interface commands.** The UI can be configured through chat (`interface-commands.jsx`), a natural fit for an associative, notation-driven config.
9. **Issue reporting with user context.**
   - A prefilled GitHub issue within the URL budget, embedding UI state (skin, theme, viewport, language, mode).
   - Use it as a framework-level "report UI bug" component.
10. **Append-only event log** for memory, giving export/import as `.lino` and destructive actions behind confirmation and export prompts.
11. **Quality gates in CI.**
    - i18n key parity and a hardcoded-language lint.
    - A UI-boundary lint (no business logic in view code).
    - Per-locale and per-theme screenshots.
    - A cross-org duplication scanner (`cross-org-duplication.yml`).
12. **Stable test hooks.** Systematic `data-testid` (`setting-*`, `composer-*`, `conversation-*`) and `window.FormalAi*` page APIs for E2E.
13. **Security defaults.** A strict CSP on static pages, DOMPurify on rendered markdown, Mermaid with `securityLevel: strict`, and cache-busting asset versions.
14. **Reasoning-trace presentation.** A hierarchical step view with fade gradient, last-paragraph preview and an animation budget; a candidate reusable "process/trace" component.
15. **Terminology rule.** Say "links network", not "graph" (#664), so the framework's visualization components use consistent vocabulary.

## 7. Problems and limitations

1. **Monolith.** `application.jsx` is 1,445 lines with one `App`. Its predecessor `main.jsx` reached 9,269 lines (#951); a CI line budget and boundary lint were needed to contain it.
2. **Mixed paradigms.** Three styles coexist: React + Chakra (partial migration), plain CSS classes, and vanilla IIFE pages using `window.*` globals (`FormalAiI18n`, `FormalAiPreferences`, `FormalAiVendor`). There is no module graph across pages.
3. **CSS order dependence.** The 7 stylesheets must load in numeric order. Dark mode is a large override sheet rather than token swaps, which produces recurring "element not themed" bugs (#388, #541, #550).
4. **Version drift.** `i18n.js` reports `lino-i18n@0.3.0` while `package.json` pins `0.4.0`.
5. **Limited locales.** Only en, ru, zh and hi. There is no RTL support or pluralization evidence in the UI layer.
6. **Accessibility is partial.**
   - No automated a11y audit.
   - Reduced motion is handled in a single stylesheet, even though animations (minimum message time, step reveal) are central.
   - The sidebar has a mouse-scroll bug (#447).
   - No documented contrast checks beyond a `contrast` skin.
7. **Mobile fragility.** Repeated mobile bugs: iOS accessory bar, focus layout, overflow and menu width (#108, #110, #112).
8. **Committed minified bundles** make diffs and reviews noisy (#953).
9. **No platform-guideline mapping.** Skins are named after looks (glass, material) rather than formally following Apple HIG, Material 3 or Fluent. Material and glass are approximations.
10. **No WYSIWYG configuration.** All configuration happens through the settings panel or chat commands; there is no visual editor or inspector.
11. **No animation recording.** Animations are CSS/JS timing only; there is no capture or replay of UI sessions, even though the event log could support it.
12. **Charts.** No chart components; diagrams rely on Mermaid only, and Mermaid rendering breaks on GitHub (#1190).
13. **Asset licensing.** Icon packs are third-party fonts (FontAwesome, Material Symbols, Bootstrap Icons, Ionicons, Remix, Tabler), not public domain. A public-domain-only framework needs its own set or a `names` fallback.

## 8. Migration notes (formal-ai → associative UI framework)

1. **Phase 0: contracts first.**
   - Freeze the existing external contracts as compatibility tests: `formal-ai.preferences.v1` (root `demo_preferences`), `data-theme`, the `formal-ai:i18n-ready` event, `window.FormalAi*` hooks and all `data-testid` values.
   - The framework's config loader should read the old preference document and map each key (`uiSkin`, `chatStyle`, `composerStyle`, `toolbarIconPack`, `glassOpacity`, `uiLanguage`, …) onto framework config links.
2. **Phase 1: tokens.**
   - Express `01-tokens.css` plus the dark overrides as one Links Notation token document with context-relative values (light/dark/contrast).
   - Generate the CSS vars and the Chakra semantic-token bridge from it.
   - Delete `06-dark-theme.css` incrementally, verified by per-theme screenshot diffs (#672 F1).
3. **Phase 2: shared chrome.** Replace `site-chrome.js` and `download.js` helpers with framework `SegmentedControl`/`ThemeChooser`/`LocaleChooser` vanilla-JS bindings, and move the `LABELS` dicts into lino-i18n catalogs.
4. **Phase 3: skins as framework themes.**
   - Map `ui-skin-*`, `chat-style-*`, `composer-style-*` and `toolbar-icon-pack-*` to framework theme axes.
   - Add guideline-conformant skins (Material 3, Fluent 2, Apple HIG/glass) to satisfy #557.
   - Keep the class names as aliases during the transition.
5. **Phase 4: components.**
   - Extract framework components in this order:
     - `CollapsibleSection`
     - `ToolbarButton` with priority overflow
     - Settings rows with reset
     - Composer
     - Message
     - Reasoning-trace view
     - Issue reporter
     - Links-network view
   - Keep each `data-testid`.
   - This also advances #951 (split monolith) and #550 (uniform components).
6. **Phase 5: storage.**
   - Back the framework's state store with the same append-only event-log shape as `memory.js`, so UI edits, memory and recordings share one exportable `.lino` bundle and `doublets-web` can be dropped in later.
   - Replace hand-rolled parsers with `links-notation` and `lino-objects-codec`.
7. **Phase 6: hosts.** Electron and VS Code webviews consume the same framework package (#353 parity). React Native, Swift and Kotlin bindings reuse the token, i18n and config documents rather than the DOM components.
8. **Risks.**
   - Chakra coupling: the framework should own the tokens and treat Chakra as one optional binding.
   - The generated `ts/` mirror must be regenerated, not hand-edited.
   - The CI gates (i18n parity, UI boundary, line budgets) must keep passing throughout the migration.
