## Context

Themes must restyle any control without code changes (R14), and the same style
description must work for every target framework (R6): the DOM renderer
({{F16}}) needs CSS; React Native, SwiftUI and Compose ({{F20}}, {{F22}},
{{F24}}) need resolved values per element. The architecture defines `ui-style`
as "style rules as links resolved against tokens"
([ARCHITECTURE.md](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md)).
The sample
[samples/styles.lino](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/samples/styles.lino):

```lino
(button-style: style
  (selector (type button) (variant filled))
  (background (token color.primary))
  (color (token color.on-primary))
  (radius (token shape.corner.medium))
  (state hover (elevation 2))
  (state pressed (scale 0.98)))
```

Because `:` separates an id from a link in LiNo, CSS syntax such as `:hover`
or `max-width: 640px` cannot appear in bare values. The ecosystem research
(section 5) prescribes structured links instead: `(state hover)`,
`(media (max-width 640px))`
([links-notation-ecosystem.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)).

## Goal

`packages/ui-style` (`@link-foundation/ui-style`) reads style rules written in
LiNo, matches them to UI elements, resolves token references through
`ui-tokens`, and produces either a CSS stylesheet or a resolved style object
for one element in a given state and environment.

## Scope

### In scope

- Rule grammar (below): selectors, declarations, `state`, `media`,
  `container` blocks, nesting of `state` inside `media`.
- States: `hover`, `focus` (focus-visible), `pressed`, `disabled`, `selected`,
  `checked`.
- Conditions: `(media (max-width 640px))`, `(media (min-width ...))`,
  `(media (prefers-color-scheme dark))`, `(media (prefers-reduced-motion reduce))`,
  `(container (min-width 400px))`.
- Property vocabulary with CSS mapping and types (from {{F07}}).
- Cascade: specificity, then source order (later wins).
- `compileCss()` and `resolveStyle()`.

### Out of scope

- Animations and transitions ({{F44}}); layout algorithms ({{F28}}); complete
  themes ({{F39}}–{{F43}}).
- Arbitrary CSS selectors (combinators other than `within`, pseudo-elements).

## Dependencies

- {{F07}} (blocker): typed values and `toCss` for declaration values.
- {{F11}} (blocker): `resolveTokens` and CSS variable naming
  (`color.primary` → `--color-primary`). Consumed: names for `var(...)` in CSS
  output and concrete values for `resolveStyle`. Before F11 merges, use a stub
  `Map` of resolved tokens and the same naming rule.
- Related: {{F16}} (expects selectors such as `ui-button[variant="filled"]`),
  {{F20}}, {{F22}}, {{F24}}, {{F25}} (state machines provide the current
  state), {{F39}}, {{F46}} (Styles tab).

## Step-by-step plan

1. Create `packages/ui-style/package.json` (`"name": "@link-foundation/ui-style"`),
   dependencies `@link-foundation/ui-core`, `@link-foundation/ui-tokens`.
2. Grammar, documented in the README:
   ```lino
   (card-style: style
     (selector (type card) (within (type dialog)))
     (padding (token space.medium))
     (media (max-width 640px)
       (padding (token space.small)))
     (container (min-width 400px)
       (direction horizontal))
     (state disabled (opacity 0.38)))
   ```
   Selector parts: `(type KIND)`, `(id ID)`, `(PROP VALUE)` for prop equality,
   `(within SELECTOR)` for an ancestor.
3. `src/properties.js`: table `name → { css, type }`, at least `background →
background-color (color)`, `color (color)`, `radius → border-radius
(dimension)`, `padding`, `gap`, `opacity (number)`, `elevation → box-shadow`
   (value is `var(--elevation-N)` from tokens), `scale → transform: scale()`,
   `font-size`, `font-weight`, `border-width`, `border-color`, `direction →
flex-direction`. Unknown property → diagnostic `unknown-property`.
4. `src/read.js`: `readStyles(text) → { rules: StyleRule[], diagnostics }`:
   ```js
   /** @typedef {{ id: string, order: number, selector: Selector, declarations: Decl[],
    *   blocks: Array<{ kind: 'state'|'media'|'container', condition: unknown, rule: StyleRule }> }} StyleRule */
   ```
5. `src/match.js`: `matches(selector, node, ancestors)`; specificity tuple
   `[ids, props + states, types]`.
6. `src/resolve.js`:
   ```js
   /**
    * @param {UiNode} node @param {UiNode[]} ancestors
    * @param {{ states?: string[], viewport?: { width: number }, container?: { width: number },
    *           colorScheme?: 'light'|'dark', reducedMotion?: boolean }} env
    * @returns {{ style: Record<string, TypedValue>, sources: Record<string, string> }}  sources = rule id per property
    */
   export function resolveStyle(rules, tokens, node, ancestors, env) {}
   ```
   `sources` lets dev mode show which rule won (R12).
7. `src/css.js`: `compileCss(rules, { tagFor = (k) => 'ui-' + k })`. Mapping:
   `hover → :hover`, `focus → :focus-visible`, `pressed → :active`,
   `disabled → :is(:disabled, [disabled], [aria-disabled="true"])`,
   `selected → [aria-selected="true"]`, `checked → [aria-checked="true"]`;
   `(max-width 640px)` → `@media (max-width: 640px)`; container →
   `@container (min-width: 400px)`. Expected output for the sample:
   ```css
   ui-button[variant='filled'] {
     background-color: var(--color-primary);
     color: var(--color-on-primary);
     border-radius: var(--shape-corner-medium);
   }
   ui-button[variant='filled']:hover {
     box-shadow: var(--elevation-2);
   }
   ui-button[variant='filled']:active {
     transform: scale(0.98);
   }
   ```
   Escape all attribute values; never emit `url(` from unvalidated text.
8. Golden CSS files and tests; README; changeset.

## Acceptance criteria

- [ ] `read.test.js`: the sample gives one rule with 3 declarations and 2
      `state` blocks; a rule with `:hover` inside a bare value is reported as a
      diagnostic, not silently accepted.
- [ ] `resolve.test.js`: for the `ok` button of `samples/document.lino` with
      the sample tokens, `resolveStyle(..., { states: ['hover'] })` gives
      `background` = colour `#6750A4` and `elevation` = 2; without `hover`
      there is no `elevation`.
- [ ] `media (max-width 640px)` applies at `viewport.width` 640 and not at 641;
      `container (min-width 400px)` likewise.
- [ ] `cascade.test.js`: `(id ok)` beats `(type button) (variant filled)`
      which beats `(type button)`; with equal specificity the later rule wins.
- [ ] `css.test.js`: `compileCss` of the sample equals `tests/golden/styles.css`
      and parses without errors with a CSS parser used only in tests (for
      example `postcss`, MIT).
- [ ] `npm test`, `npm run lint`, `npm run format:check`,
      `npm run check:duplication` pass.

  to be expressed as rules later ({{F60}}).
