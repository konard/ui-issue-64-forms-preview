## Context

Issue #1 asks the framework to own "all traditional UI/UX elements" (R13)
and to express every classical look as a theme (R14). For
[konard/immortality](https://github.com/konard/immortality) the look includes
sound. Its
[`app/src/sound.ts`](https://github.com/konard/immortality/blob/main/app/src/sound.ts)
(Unlicense, so it can be ported) is a Web Audio synthesizer with:

- 26 voices and 10 UI events (`hover`, `click`, `toggle`, `select`, `scan`,
  `open`, `close`, `type`, `intro`, `notify`);
- up to 6 voices per event, played in `random`, `cycle` or `layer` mode;
- a bus of tone shelf → compressor/limiter → convolution reverb send, with
  stereo panning from the pointer position;
- a lazily created `AudioContext` (browsers block audio until a user gesture);
- `throttledScan`, which limits repeated scan sounds;
- an `onSoundCue` event bus that one animated background listens to;
- per-voice provenance `{character, sourceLabel, sourceUrl}`; no audio files
  are shipped, every sound is synthesized from code.

Comfort settings (sound on/off, volume) belong to the viewer: applying a
shared look or preset must keep them and randomizing must not touch them
([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md),
"Sound as part of motion" and "Comfort settings stay local"). No other
roadmap issue covers sound; {{F64}} needs this issue to migrate immortality.

## Goal

A package `@link-foundation/ui-sound` that reads a sound theme written in
Links Notation, synthesizes its voices with Web Audio, and plays them for
framework interaction events, with sound off by default, a viewer-owned
volume, and no effect on users who never enable it.

## Scope

### In scope

- A LiNo sound theme format: voices (oscillator/noise graphs with envelopes),
  event bindings with a mode, bus settings and provenance per voice.
- A player: lazy `AudioContext` on the first user gesture, the three modes,
  per-event throttling, pointer-positioned stereo, master volume and mute.
- Binding to framework events from {{F25}} (the actions registry and state
  machine transitions), plus a public `cue(name)` call and an `onCue`
  subscription (the `onSoundCue` equivalent).
- Comfort keys `sound.enabled` and `sound.volume` in the user layer of {{F10}},
  marked so presets, shared looks and randomize never change them.
- One default theme (`quiet`, 4–6 soft voices) and a port of the immortality
  voices as a second theme with their provenance.

### Out of scope

- Audio files and music playback; speech output (screen readers already
  speak); haptics.
- A visual sound editor (a later designer issue may reuse the format).
- Migrating immortality itself ({{F64}}).

## Dependencies

- {{F10}} (blocker): configuration layers. Consumed: the user layer and a way
  to mark keys as comfort keys (if {{F10}} has no such flag, add a list of
  comfort keys in this package and open a follow-up issue against {{F10}}).
- {{F25}} (blocker): the actions registry and state machine events. Consumed:
  an event subscription such as `onAction(name, handler)`; use the name that
  is actually merged.
- Related: {{F44}} (intro sequences may cue sounds on their timeline),
  {{F45}} (recordings should store cues so a replay can play them), {{F39}}
  (a theme may name its sound theme), {{F15}} (schema kinds for the settings
  panel), {{F02}} (provenance records), {{F64}} (first consumer).

## Step-by-step plan

1. Create `packages/ui-sound/` (`"name": "@link-foundation/ui-sound"`,
   `"type": "module"`), depending on `links-notation` and the framework core.
2. Write `docs/spec/sound.md` and a sample theme, for example:

   ```lino
   (sound-theme quiet
     (voice tick
       (oscillator triangle (frequency 880))
       (envelope (attack 0.002) (decay 0.04) (sustain 0) (release 0.02))
       (gain 0.2)
       (source (label 'own work') (license CC0-1.0)))
     (voice soft-open
       (oscillator sine (frequency 440) (glide 660 0.08))
       (envelope (attack 0.01) (decay 0.12) (sustain 0) (release 0.05))
       (gain 0.15)
       (source (label 'own work') (license CC0-1.0)))
     (event click (mode random) (voices tick))
     (event open (mode cycle) (voices soft-open))
     (event scan (throttle 120))
     (bus (shelf 4000 -6) (compressor -18 4) (reverb 0.15)))
   ```

3. `src/theme.js`: parse the theme with `links-notation` into a plain object
   and validate it (unknown keys → diagnostics, never a throw).
4. `src/graph.js`: build an `AudioNode` graph for a voice from the plain
   object. Accept the `BaseAudioContext` as a parameter so tests can pass an
   `OfflineAudioContext` or a fake.
5. `src/player.js`: `createSoundPlayer({ theme, config, now })`, with
   `play(event, { x })`, `cue(name)`, `onCue(handler)`, `setVolume`, `mute`,
   lazy context creation on the first `pointerdown`/`keydown`, modes and
   throttling. Inject the clock (`now`) and the random source (seeded) so
   tests are deterministic.
6. `src/bind.js`: subscribe to the {{F25}} events and map them to sound events
   (`press` → `click`, `open` → `open`, and so on) with a LiNo mapping table.
7. Add the comfort keys to the {{F10}} user layer and exclude them from
   presets, shared looks and randomize.
8. Port the 26 immortality voices into `themes/immortality.lino`, one
   `(source ...)` per voice taken from `SOUNDS` in `sound.ts`.
9. Respect `prefers-reduced-motion` only for sounds tied to motion
   (`intro`, `scan`); never start sound before a user gesture.
10. Write `packages/ui-sound/README.md` with the format, the API and the
    accessibility rules.

## Acceptance criteria

- [ ] `theme.test.js`: both bundled themes parse with no diagnostics; an
      unknown voice key yields a diagnostic, not an exception.
- [ ] `graph.test.js`: rendering `tick` in an `OfflineAudioContext` (or a fake
      context recording node calls) creates the expected nodes and the output
      is silent after attack + decay + release.
- [ ] `player.test.js`: with a seeded random source, `random` mode picks the
      same voice sequence on every run; `cycle` mode rotates; `layer` mode
      plays all voices; `scan` plays at most once per 120 ms of injected time.
- [ ] No `AudioContext` is created before a simulated user gesture, and none
      at all while `sound.enabled` is false (the default).
- [ ] `comfort.test.js`: applying a preset or a shared look and randomizing
      leave `sound.enabled` and `sound.volume` unchanged.
- [ ] `bind.test.js`: a {{F25}} `press` action plays the `click` event once.
- [ ] Every voice in `themes/immortality.lino` has a `(source ...)` record.
- [ ] `npm test`, `npm run lint`, `npm run format:check`,
      `npm run check:duplication` pass.

## How to verify

```bash
npm install
node --test packages/ui-sound/tests/*.test.js
npm test && npm run lint && npm run format:check && npm run check:duplication
```

For a manual check, open a page that uses the player, enable sound in the
settings, click a button and open a dialog: each plays its voice once, and
reloading the page keeps the volume.

## Prior art and libraries

- `konard/immortality` `app/src/sound.ts` (Unlicense): event → voices,
  modes, bus, provenance, lazy context.
- The Web Audio API (MDN): `OscillatorNode`, `GainNode`,
  `DynamicsCompressorNode`, `ConvolverNode`, `StereoPannerNode`,
  `OfflineAudioContext` for tests.
- Optional: [Tone.js](https://github.com/Tonejs/Tone.js) (MIT) as a reference
  for envelopes; do not add it as a dependency unless the plain Web Audio
  version becomes too complex (check the licence and size first).
