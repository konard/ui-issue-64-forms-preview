## Context

The repository convention (used by issue #1) stores the research for issue
`N` in `docs/case-studies/issue-N/`. The template that `link-foundation/ui`
was created from left 19 such folders behind, and they describe **template**
issues, not issues of this repository:

`docs/case-studies/issue-3`, `issue-7`, `issue-13`, `issue-21`, `issue-23`,
`issue-25`, `issue-29`, `issue-31`, `issue-33`, `issue-36`, `issue-38`,
`issue-40`, `issue-41`, `issue-42`, `issue-56`, `issue-58`, `issue-75`,
`issue-93`, `issue-212`.

There are also template analyses in `docs/`: `ISSUE-199-RELEASE-ANALYSIS.md`,
`ISSUE-203-ANALYSIS.md`, `ISSUE-216-ANALYSIS.md`, `ISSUE-228-ANALYSIS.md`,
`ISSUE-262-ANALYSIS.md` and `issue-273-analysis.md`, plus
`experiments/issue-273-plan.md`.

The roadmap creates dozens of issues in this repository, and it will soon
have issues 3, 7, 13 and so on. When one of them gets a case study, its folder
already exists with unrelated content, and an agent working on it may read the
wrong evidence or overwrite template history.

The following files refer to these paths and must keep working:

- `.github/workflows/release.yml` (comments that cite `docs/case-studies/issue-23`)
- `scripts/simulate-fresh-merge.sh` (cites `docs/case-studies/issue-23`)
- `tests/release-badge.test.js` (reads
  `docs/case-studies/issue-3/original-format-release-notes.mjs`)
- `experiments/issue-273-plan.md`, `CHANGELOG.md`
- other case studies that link each other

## Goal

All template history lives under one clearly named folder that cannot collide
with this repository's issue numbers. Every reference to it is updated, and the
convention is documented.

## Scope

### In scope

- Move every inherited folder to `docs/template-history/case-studies/issue-N/`
  with `git mv`, so history is kept. Move the `docs/ISSUE-*.md` and
  `docs/issue-273-analysis.md` analyses to `docs/template-history/` as well.
- Add `docs/template-history/README.md`. It explains that issue numbers in this
  folder refer to
  https://github.com/link-foundation/js-ai-driven-development-pipeline-template/issues
  and lists each folder with a one-line summary taken from its README.
- Update every reference listed above, and any further ones found with grep.
- Update `.prettierignore`, `.lycheeignore`, `eslint.config.js` and
  `scripts/check-file-line-limits.sh` if they contain path patterns that must
  also cover `docs/template-history/case-studies/*/data/`.
- Add a short "Case study folders" note to `docs/CONTRIBUTING.md`:
  `docs/case-studies/issue-N/` is only for issue `N` of `link-foundation/ui`.

### Out of scope

- Editing the content of the moved documents.
- Renaming the package: that is {{B01}}.

## Dependencies

None. This bug can be done in parallel with {{B01}}. Both touch
`docs/CONTRIBUTING.md`, so rebase on whichever merges first.

## Step-by-step plan

1. List the inherited folders:
   `ls docs/case-studies | grep -v '^issue-1$'`. Only `issue-1` belongs to this
   repository. Also check for folders added after this issue was written.
2. `mkdir -p docs/template-history/case-studies` and `git mv` each folder and
   analysis file.
3. Find the references:
   `grep -rn "case-studies/issue-[0-9]\|docs/ISSUE-\|issue-273-analysis" --exclude-dir=node_modules --exclude-dir=template-history .`
   and update each path. Do not change paths inside `docs/case-studies/issue-1/`
   that point to `docs/case-studies/issue-1/`.
4. Search ignore files and scripts for `docs/case-studies/*/data/` patterns.
   Add the equivalent `docs/template-history/case-studies/*/data/` pattern next
   to each one.
5. Write `docs/template-history/README.md` and the CONTRIBUTING note.
6. Run all checks.
