## Context

R13 asks the framework to own all of its UI elements. R15 asks it to follow the Google, Microsoft and Apple design guidelines, and to make migration from MUI easy. Each system names the same concepts differently:

- Material 3 publishes tokens as `md.sys.*` and `md.ref.*`;
- Fluent 2 uses global and alias tokens such as `colorNeutralBackground1`;
- Apple HIG is prose guidance, and its documentation is proprietary;
- WAI-ARIA APG defines roles and keyboard patterns;
- Open UI (a W3C Community Group) researches common component anatomy and names.

See [existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md) (sections on tokens, design systems and accessibility). The research recommends a three-layer token model (reference → system/semantic → component), DTCG 2025.10 for interchange, and React Aria plus WAI-ARIA APG as acceptance criteria for behaviour.

The dialect already uses token names such as `color.primary`, `color.on-primary`, `space.medium`, `shape.corner.medium` and `motion.duration.short` ([`docs/ARCHITECTURE.md`](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md), [`samples/tokens.lino`](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/samples/tokens.lino)). The component issues ({{F26}}–{{F29}}) and the themes ({{F40}}, {{F41}}, {{F42}}) need one catalogue of component names and one token taxonomy to build against.

## Goal

Write `docs/guidelines/`: a digest that maps component names and token names from Material 3, Fluent 2, Apple HIG, WAI-ARIA APG and Open UI into **one component catalogue** and **one token taxonomy** for this framework. It must summarise and link; it must never copy copyrighted text.

## Scope

### In scope

- `docs/guidelines/README.md`: purpose, sources, the licence rule ("summarise and link"), and how to update.
- `docs/guidelines/component-catalogue.md`: one table row per framework component. The columns are:
  - our kind name;
  - Open UI name;
  - ARIA role or APG pattern (with link);
  - Material 3 name;
  - Fluent 2 name;
  - Apple HIG name;
  - MUI name;
  - keyboard summary (our own words);
  - owner issue.
- `docs/guidelines/token-taxonomy.md`: the three layers, the categories and naming rules of our tokens, and a mapping table to M3 system tokens, Fluent alias tokens, HIG semantic concepts and DTCG `$type`.
- `docs/guidelines/catalogue.lino` and `docs/guidelines/tokens-taxonomy.lino`: the same data as LiNo, so code and tests can use it.
- `tests/guidelines-catalogue.test.js`, which checks that the `.lino` files parse and agree with the tables.

### Out of scope

- Implementing tokens ({{F11}}), components ({{F26}}–{{F29}}) or themes ({{F40}}–{{F42}}).
- The full MUI migration guide ({{F57}}). This issue provides only the MUI name column.
- Any copied text, images or icons from the guideline sites.

## Step-by-step plan

1. Read the official sources, in this order:
   - WAI-ARIA APG patterns: https://www.w3.org/WAI/ARIA/apg/patterns/
   - Open UI research: https://open-ui.org
   - Material 3 components and tokens: https://m3.material.io
   - Fluent 2: https://fluent2.microsoft.design
   - Apple HIG: https://developer.apple.com/design/human-interface-guidelines
   - MUI components: https://mui.com/material-ui/all-components/

   Record the date you read them in `README.md`.

2. Fix the list of framework kinds. Start from the APG patterns and the controls named in the component issues:
   - actions: `button`, `icon-button`, `toggle-button`, `link`;
   - selection: `checkbox`, `radio-group`, `switch`, `slider`, `select`, `combobox`;
   - text: `text-field`, `text-area`;
   - containers: `dialog`, `popover`, `menu`, `menubar`, `tabs`, `toast`, `tooltip`, `accordion`, `disclosure`, `card`;
   - data and navigation: `list`, `tree`, `table`, `grid`, `breadcrumb`, `navigation-bar`, `navigation-rail`, `toolbar`;
   - feedback: `progress`, `spinner`, `badge`, `avatar`, `divider`;
   - layout: `stack`, `grid-layout`, `split-pane`.

   Use kebab-case, matching the dialect samples.

3. Fill `component-catalogue.md` with one row per kind. Where a system has no equivalent, write `—`. Every cell with a per-system name links to that system's page. Mark each per-system name you could not confirm on the official page with "(verify)".
4. Write the keyboard summary of each kind in your own words, at most 15 words, and link the APG pattern. Never paste APG text.
5. Write `token-taxonomy.md`. It covers:
   - **Layers:** `ref.*` (raw palette, the scale), system/semantic tokens without a prefix (`color.primary`, `space.medium`), and component tokens (`button.container.color`).
   - **Categories:** `color`, `space`, `size`, `shape` (`shape.corner.*`), `typography` (`type.body.medium.*`), `elevation`, `motion` (`motion.duration.*`, `motion.easing.*`), `opacity`, `z` (layers), `breakpoint`, `focus`.
   - **Naming rules:** lower-case, dot-separated paths, kebab-case segments, a size scale `x-small … x-large`, and colour pairs `color.X` / `color.on-X`.
   - **A mapping table**, one row per system token. Columns: ours, M3 (`md.sys.color.primary`, ...), Fluent (`colorBrandBackground`, ...), HIG concept (for example "tint colour", "label colour"), DTCG `$type` (`color`, `dimension`, `duration`, `cubicBezier`, `shadow`, `typography`).
6. Write `catalogue.lino` and `tokens-taxonomy.lino`. Example records:

   ```lino
   (button: component-entry
     (aria-pattern button)
     (apg 'https://www.w3.org/WAI/ARIA/apg/patterns/button/')
     (material3 'common buttons')
     (fluent Button)
     (hig Buttons)
     (mui Button)
     (owner F26))
   (color.primary: token-entry
     (layer system)
     (dtcg-type color)
     (material3 md.sys.color.primary)
     (fluent colorBrandBackground))
   ```

   Quote every URL and every value that contains spaces or `:`.

7. Write `tests/guidelines-catalogue.test.js`. It parses both `.lino` files with `links-notation` and checks that:
   - every catalogue kind appears in `component-catalogue.md`;
   - every token path matches `^[a-z][a-z0-9-]*(\.[a-z0-9-]+)*$`;
   - every URL starts with `https://`.
8. In `README.md`, add a "Licence of sources" paragraph, and link the folder from `docs/ARCHITECTURE.md` (one line under "Themes and other frameworks as LiNo"). The paragraph says:
   - the Apple HIG is proprietary documentation, and SF Symbols/SF Pro must not be bundled;
   - Material and Fluent documents are used for names only;
   - names and links are facts, and every description is our own wording.

## Acceptance criteria

- [ ] `docs/guidelines/component-catalogue.md` has at least 35 kinds, each with the APG/ARIA, Open UI, Material 3, Fluent 2, HIG and MUI columns filled or `—`.
- [ ] `docs/guidelines/token-taxonomy.md` defines the three layers, at least 10 categories and the naming rules, and maps at least 30 system tokens to M3, Fluent, HIG and DTCG `$type`.
- [ ] `catalogue.lino` and `tokens-taxonomy.lino` parse with `links-notation`, and `node --test tests/guidelines-catalogue.test.js` passes.
- [ ] The digest contains no copied sentence from the guideline sites; a reviewer spot-checks 5 random descriptions against the sources.
- [ ] Every per-system name links to its official page or is marked "(verify)".
- [ ] `npm run format:check` and `npm test` pass.
