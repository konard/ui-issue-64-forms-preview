## Context

R6 says any UI framework is "just" a LiNo document. Four JSON formats
describe UIs or animations declaratively, and supporting them makes the
framework useful to agents and existing hosts on day one
([existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md),
interop section):

- **Google A2UI** (Apache-2.0) is the agent-to-UI protocol. An agent streams
  JSON messages that describe components from a catalog as a flat list with
  IDs, plus data-model updates. v0.8 is listed as stable and v0.9 as a draft,
  so check the current version before starting.
- **Microsoft Adaptive Cards** (MIT; check the repository licence) are JSON
  cards built from `body` elements, inputs and `actions`.
  - Schema 1.6 is current, and Teams supports up to 1.5.
  - The host config acts as a theme.
  - `fallback` and `fallbackText` handle versioning.
- **JSON Forms** (MIT) pairs a JSON Schema for the data with a UI schema of
  layouts and controls (`VerticalLayout`, `HorizontalLayout`, `Group`,
  `Categorization`, `Control` with a `scope`, and `rule`s).
- **Lottie** has a spec, version 1.0 from September 2024, maintained by the
  Lottie Animation Community at the Linux Foundation. lottie-web is MIT.
  Spec 1.0 excludes text layers, effects and expressions.

The research concludes that the dialect should be lossless to and from JSON,
so importing these formats is mechanical. meta-sovereign already plays
Telegram `.tgs` stickers, which are Lottie, through the lottie-web light
build with no `eval`
([meta-sovereign-chat.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/meta-sovereign-chat.md)).

## Goal

Add four import and export pairs to `@link-foundation/ui-convert`. Each one
turns a format into UI-dialect LiNo and back:

- A2UI messages become document diffs.
- Adaptive Cards become documents, and host configs become themes.
- JSON Forms become form documents.
- Lottie becomes shapes plus animations.

Within the supported subset each pair is lossless, and outside it the pair is
explicit about what it lost. Actions are always data, never code.

## Scope

### In scope

- `importA2ui(messages)` and `exportA2ui(doc)`. A pure
  `a2uiMessagesToDiffs(messages)` turns streamed messages into incremental
  `set`, `insert` and `remove` diffs.
- Adaptive Cards:
  - `importAdaptiveCard(json)` and `exportAdaptiveCard(doc, { targetVersion })`;
  - `hostConfigToTheme(hostConfig)`.
- JSON Forms: `importJsonForms({ schema, uischema })` and `exportJsonForms(doc)`.
- Lottie: `importLottie(json)` and `exportLottie(doc, animationId)`, for
  shape layers (rect, ellipse, path, fill, stroke, group), the transform
  properties (position, scale, rotation, opacity, anchor) and bezier
  keyframe easing.
- Unknown properties are preserved as `(extra <format> '<json>')`, so a round
  trip does not drop them. Every lossy step produces a diagnostic.
- A mapping table for each format: `src/interop/<format>/mapping.lino`.

### Out of scope

- A2UI transport (A2A, SSE or WebSocket) and agent hosting. This issue
  converts messages only.
- The Adaptive Cards templating language (`${...}`). Expressions are kept as
  literal strings and are never evaluated.
- Lottie text layers, effects, expressions, image and audio assets, and
  precomps beyond one level. They are rejected with a diagnostic, and
  expressions are never evaluated.
- Rendering. The output is LiNo; {{F16}} renders it, and {{F44}} plays the
  animations.
- DivKit and json-render. They could be added later in the same layout.

## Dependencies

- {{F06}} (blocker). Supplies the parser, the element tree and the
  serialiser. Every importer builds a tree and serialises it with
  `links-notation`, and every exporter walks a parsed tree.
- Related:
  - {{F26}}, {{F27}}, {{F29}}: the target kind names (`text`, `image`,
    `stack`, `button`, `text-field`, `checkbox`, `select` and so on). Use
    the names actually merged, and keep them in the `mapping.lino` files.
  - {{F44}}: the animation format Lottie maps to.
  - {{F39}}: the theme format for host configs.
  - {{F17}} and {{F51}}: the other `ui-convert` importers. Share their
    package layout and diagnostics type.
  - {{F52}}: code exporters.
- If `packages/ui-convert/` does not exist yet, create it with
  `src/index.js` and `src/diagnostics.js`, and use the same layout {{F17}}
  describes.

## Step-by-step plan

1. Collect fixtures in `packages/ui-convert/tests/fixtures/interop/`:
   - official sample cards from the Adaptive Cards repository;
   - A2UI sample message streams from the A2UI repository;
   - two JSON Forms examples (person, with a rule);
   - three small Lottie files that use only in-scope features.

   Record the source URL and licence of every fixture in `fixtures/interop/SOURCES.md`.

2. Adaptive Cards (`src/interop/adaptive-cards/`). Map
   `TextBlock`, `Image`, `Container`, `ColumnSet`, `Column`, `FactSet`,
   `ActionSet`, the `Input.*` elements, `Action.Submit`, `Action.OpenUrl`,
   `Action.ShowCard` and `Action.ToggleVisibility`.
   - Read the version from the card's `version`.
   - On export with `targetVersion: '1.5'`, replace newer elements with
     their `fallback`, or drop them and keep `fallbackText`, with a
     diagnostic.
   - Here is the output for a card with one `TextBlock`, one `Input.Text`
     and one `Action.Submit`:
     ```lino
     (card: document
       (source adaptive-cards '1.6')
       (body: stack
         (title: text 'Hello' (size large) (weight bold))
         (name: text-field (label 'Name') (bind name)))
       (actions: stack (direction row)
         (submit: button (label 'OK') (on press (submit card)))))
     ```
   - `Action.OpenUrl` becomes `(on press (open-url 'https://example.com'))`.
     The URL is quoted because it contains `:`.
3. `hostConfigToTheme(hostConfig) -> string`. It maps default container
   colours, foreground colours, spacing, font sizes and font weights to
   tokens in the {{F39}} theme format, and lists unmapped paths.
4. A2UI (`src/interop/a2ui/`). Implement:

   ```js
   /** @param {object[]} messages A2UI protocol messages, in stream order
    * @returns {{ diffs: Array<{ op: 'insert' | 'set' | 'remove', id: string, parent?: string, kind?: string, props?: object }>, diagnostics: Diagnostic[] }} */
   export function a2uiMessagesToDiffs(messages) {}
   ```

   - The A2UI flat component list with child IDs maps directly onto links.
   - Bind data-model paths as `(bind <path>)`.
   - Read the message names and the catalog schema from the current spec,
     and pin the supported version in `A2UI_VERSION`.
   - `importA2ui` applies all diffs to an empty tree. `exportA2ui` produces
     one full surface message sequence.

5. JSON Forms (`src/interop/json-forms/`).
   - `Control` scopes such as `#/properties/name` become `(bind name)`. In
     LiNo the raw scope must be quoted, because `#` starts a comment.
   - Labels, `required`, `minimum`/`maximum`, `enum` and `format` come from
     the data schema.
   - A `rule` with effect HIDE, SHOW, ENABLE or DISABLE and a `condition`
     becomes `(rule (hide (when (bind vegetarian) (equals false))) (target diet))`.
   - Layouts map to `stack` with `(direction column)` or `(direction row)`.
     `Group` becomes a titled section, and `Categorization` becomes tabs.
6. Lottie (`src/interop/lottie/`).
   - Frame times convert to ms with `fr`.
   - Each in-scope layer becomes a shape element.
   - Animated transform properties become {{F44}} tracks, and bezier
     `i`/`o` handles become `(cubic-bezier ...)` easings per key:
     ```lino
     (dot: shape (path 'M0 0 L10 0 L10 10 Z') (fill '#FF5500'))
     (dot-pulse: animation
       (source lottie '1.0')
       (target dot)
       (duration 1000ms)
       (track opacity (key 0 0) (key 0.5 1) (key 1 0))
       (track translate (key 0 '0px 0px') (key 1 '100px 0px')))
     ```
   - `exportLottie` writes the spec 1.0 subset. Check whether the Lottie spec
     publishes a JSON Schema; if it does, validate the output against it in
     the test.
7. `src/interop/index.js` provides `detectFormat(json)`, which returns
   `'a2ui' | 'adaptive-cards' | 'json-forms' | 'lottie' | null`. Also add
   the CLI subcommand
   `npx ui-convert import <file.json> [--format <name>] > out.lino` and the
   matching `export <file.lino> --format <name>`.
8. Write the README section with a capability matrix per format (supported,
   partial or unsupported elements), the tests and a changeset.

## Acceptance criteria

- [ ] For every in-scope fixture, `export(import(x))` deep-equals `x` after
      normalisation (key order, default values), so the round trip is
      lossless.
- [ ] Every imported fixture produces LiNo that parses with `links-notation`,
      and `serialize(parse(lino))` is stable.
- [ ] `interop-adaptive-cards.test.js`: exporting a 1.6 card with a `Table`
      to `targetVersion: '1.5'` uses its fallback and emits a diagnostic.
      `hostConfigToTheme` maps at least colours, spacing and font sizes.
- [ ] `interop-a2ui.test.js`: applying `a2uiMessagesToDiffs` incrementally,
      message by message, gives the same tree as `importA2ui` on the whole
      stream.
- [ ] `interop-json-forms.test.js`: the person example yields one field per
      `Control` with the correct `bind`, `required` and limits, and a HIDE
      rule becomes a `rule` link.
- [ ] `interop-lottie.test.js`: a fixture with text layers or expressions is
      rejected with diagnostics, and `grep -rnE "eval\(|new Function" packages/ui-convert/src`
      is empty.
- [ ] `tests/e2e/interop-lottie.spec.js`: an exported Lottie file plays in
      lottie-web (a devDependency of the test only), and its frame at 50
      percent matches a screenshot of the {{F44}} player within the
      Playwright pixel tolerance. Skip this test until {{F44}} has merged.
- [ ] Unknown JSON properties survive a round trip via `extra`, which a test
      checks for each format.
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication` and
      `npm test` pass.
