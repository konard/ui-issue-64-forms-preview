## Context

Issue #1 asks to "modify the UI/UX on the fly on any of our websites" (R9) and
to make migration of existing projects easy (R23). Dev mode ({{F46}}) works on
pages rendered by `ui-dom`, where every element already has a `data-link-id`.
Most of our sites are not built with the framework yet. This issue brings dev
mode to them: import the live DOM into the UI dialect with the HTML/DOM
importer from {{F17}}, show it in the same inspector, apply edits to the
foreign page, and export the edits as LiNo so they can drive a migration.

Two delivery channels:

- **Bookmarklet**: a `javascript:` URL that injects a loader script. Zero
  install, but a page's Content Security Policy (CSP) can block the injected
  script.
- **Browser extension** (Manifest V3): injects the same bundle with the
  `scripting` API on user action. Code injected by an extension is not
  subject to the page's CSP for script loading, so it works on more sites.

The deepcase application shell already shipped a Chrome extension target
([deepcase research, section 1](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/deepcase.md)).
click-to-component, LocatorJS and Onlook are prior art for "select an element
on a running site"
([existing-solutions.md section 3](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)).

## Goal

A user on any web page clicks the bookmarklet or the extension button, the dev
mode inspector opens over the page, shows the page as a LiNo element tree,
lets the user change text, attributes and inline styles, and exports the
changes as an `overrides` document plus the imported LiNo of the selected
subtree.

## Scope

### In scope

- A foreign-page adapter in `@link-foundation/ui-devmode`
  (`src/foreign/`): uses `importDom(root, options)` from {{F17}} to build the
  element tree and its `nodeMap` (link ID to DOM node), and implements the same
  adapter interface that {{F46}} uses for `ui-dom` pages: `tree()`,
  `nodeFor(id)`, `idFor(node)`, `applyProperty(id, name, value)`,
  `observe(callback)`.
- Deterministic IDs from {{F17}} (`id` attribute, else structural path). The
  adapter never adds attributes to the page; it keeps mappings in a `WeakMap`.
- Editable properties: text content of leaf elements, attributes (except
  `on*`, `src`/`href` with `javascript:`), inline style declarations.
  Applying writes to the DOM and records an override in the `session` layer.
- Re-import on DOM changes (`MutationObserver`, debounced 200 ms), keeping the
  selection when the ID is stable.
- Persistence per origin: overrides saved under a key such as
  `link-ui-devmode:<origin>:<pathname>` in `localStorage` (bookmarklet) or
  `chrome.storage.local` (extension); re-applied when dev mode is opened again.
- Export: the `overrides` document (with {{F47}} if merged) and "Copy subtree as
  LiNo" (the {{F17}} output for the selected element), useful for migrations
  ({{F57}}).
- Bookmarklet: `packages/ui-devmode/dist/bookmarklet.txt` built from a tiny
  loader that injects `<script type="module" src="{bundleUrl}">`; the bundle
  URL is configurable at build time (default: the documentation site from
  {{F54}} when it exists).
- Extension: `packages/ui-devmode-extension/` (private workspace, not
  published to npm) with `manifest.json` (Manifest V3, permissions
  `activeTab` and `scripting`, `storage`), a toolbar action that calls
  `chrome.scripting.executeScript` with the bundled dev mode file, and a
  packaging script that writes a zip.
- The inspector is mounted in a shadow root inside a fixed host element so
  the page's CSS does not change it and it does not change the page.

### Out of scope

- Publishing to the Chrome Web Store or Firefox Add-ons (needs accounts; a
  follow-up).
- Writing changes back to the foreign site's source code (Onlook-style).
- Pages inside cross-origin iframes; closed shadow roots are skipped and shown
  as a single opaque node.

## Dependencies

- {{F46}} (blocker): inspector, overlay, property grid, policy and the adapter
  interface (if {{F46}} did not define an explicit adapter interface, extract
  it in this issue without changing behaviour for `ui-dom` pages).
- {{F17}} (blocker): `importDom(root, options)` returning
  `{ text, tree, nodeMap, diagnostics }`, deterministic IDs and the security
  rules (scripts and `on*` attributes dropped).
- Related: {{F47}} (export and share), {{F54}} (hosting of the bookmarklet
  bundle), {{F57}} (migration playbook uses the subtree export), {{F05}}
  (Playwright).

## Step-by-step plan

1. `src/foreign/adapter.js`:
   `createForeignAdapter({ root = document.body, importDom, ignore })`
   returns the adapter. `ignore` excludes the dev mode host element.
2. `src/foreign/apply.js` (pure helpers plus DOM writes):
   `applyProperty(node, name, value)` for `text`, `attr <name>`,
   `style <property>`; refuses `on*` attributes and `javascript:` URLs.
3. `src/foreign/persist.js`: `loadOverrides(storage, location)`,
   `saveOverrides(storage, location, overrides)`, with `storage` either a
   `localStorage` wrapper or a `chrome.storage.local` wrapper (both async).
4. `src/foreign/entry.js`: the injected entry. If dev mode is already mounted
   it toggles it; otherwise it creates the host element, imports the DOM,
   mounts the inspector with the foreign adapter and re-applies saved
   overrides.
5. `scripts/build-bookmarklet.mjs`: bundles `entry.js` (Vite library mode,
   ES module) and writes `dist/bookmarklet.txt` containing
   `javascript:(()=>{...})()` that loads the bundle. Document the CSP
   limitation in the README.
6. `packages/ui-devmode-extension/`: `manifest.json`, `background.js`
   (action click → `executeScript({ target: { tabId }, files: ['devmode.js'] })`),
   `scripts/package.mjs` that copies the bundle and zips the folder.
7. Fixture page `packages/ui-devmode/tests/fixtures/foreign.html`: plain HTML
   with a nav, two cards, a form, an inline `style` and a strict CSP `meta`
   variant `foreign-csp.html`.
8. Tests: unit tests for apply and persist; Playwright tests that load the
   fixture, inject the bundle with `page.addScriptTag`, select a card title,
   change its text and colour, reload and re-open dev mode.

## Acceptance criteria

- [ ] On `foreign.html` the Outline shows the imported tree with the same IDs
      as `importDom` from {{F17}} returns for that page.
- [ ] Changing a card title text and `color` updates the page; reload and
      re-open restores both from storage.
- [ ] The page DOM has no attributes added by dev mode (Playwright compares
      `outerHTML` of `body` without the host element before and after opening).
- [ ] `applyProperty` refuses `onclick` and `javascript:` values (unit test).
- [ ] The overrides export of the session parses as LiNo and contains one
      `set` link per change.
- [ ] `dist/bookmarklet.txt` is produced by `npm run build` in the package and
      starts with `javascript:`.
- [ ] The extension folder loads unpacked in Chromium in a Playwright test
      (persistent context with `--load-extension`) or, if that is not possible
      in CI, the manual steps and a screenshot are in the pull request.
- [ ] The README states that the bookmarklet fails under strict CSP and the
      extension should be used there (checked with `foreign-csp.html`).
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication`,
      `npm test` pass.

## How to verify

```bash
node --test packages/ui-devmode/tests/foreign-*.test.js
npm run build --workspace @link-foundation/ui-devmode
npm test
npm run lint && npm run format:check && npm run check:duplication
```

Then run the Playwright test from the {{F05}} infrastructure on
`foreign.html` and attach a screenshot of the inspector over the plain page.

## Prior art and libraries

- click-to-component, LocatorJS (MIT, verify each): select an element on a
  running page.
- Onlook (Apache-2.0, verify): visual edits of a running app, writes code.
- React DevTools and Vue DevTools extensions: content script plus panel.
- Chrome extension docs: Manifest V3, `chrome.scripting.executeScript`,
  `activeTab`. Firefox supports Manifest V3 too (check the current status of
  the `scripting` API there before claiming support).
- deepcase-app Chrome extension shell (see Context).
- Vite library mode (MIT) for the bundle.
