## Context

R15 asks us to follow the Microsoft design guidelines alongside Google's and
Apple's. Fluent 2 is Microsoft's current design system. Its main
implementation is the `microsoft/fluentui` repositories, which are MIT
licensed. Fluent organises tokens in two tiers:

- global tokens: the raw palette and size ramps;
- alias tokens: semantic names such as `colorNeutralBackground1`,
  `colorNeutralForeground1` and `colorBrandBackground`.

Fluent ships a dedicated high-contrast theme, and the research names it as
the reference for our high-contrast mode
([existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)).
The status of Fluent UI Web Components v3 is unclear, so we use Fluent as a
**source of tokens and rules, not as a runtime dependency**.

This theme gives teams moving off Fluent UI React a known target. It also
gives our Windows-flavoured apps a native look, the same way {{F40}} serves
Material and {{F42}} serves Apple platforms.

## Goal

Ship `fluent2`, a theme package with light, dark and high-contrast schemes,
built on the {{F39}} engine and following the Fluent 2 section of the {{F04}}
digest. It also needs a brand-ramp generator and a mapping table from Fluent
UI React v9 components to our kinds.

## Scope

### In scope

- `packages/ui-themes/themes/fluent2/` contains:
  - alias tokens for neutral and brand backgrounds, foregrounds and strokes;
  - corner radius, spacing, font size and line height ramps;
  - shadows, plus motion durations and curves;
  - each token mapped to our semantic names.
- Brand ramp. `fluentThemeFromBrand(brandRamp | seed)` takes the 16 brand
  stops (10–160) and derives the light and dark alias values.
- High contrast. `fluent2` has a `mode high-contrast` and a forced-colours
  mapping, and both are checked against Fluent's high-contrast theme.
- Style rules and templates for the {{F26}} controls, using Fluent
  appearances: button `primary`, `secondary`, `outline`, `subtle` and
  `transparent`; input; checkbox; radio; switch; slider.
- `fluent-mapping.lino`, a mapping table from Fluent UI React v9 component
  and prop names to our kinds.

### Out of scope

- Any runtime dependency on `@fluentui/*` or on Fluent UI Web Components.
- Bundling Segoe UI or Fluent System Icons. The font stack starts with
  `system-ui`, and icons come from {{F36}}.
- Mica, acrylic and other OS material effects. Those come later as an
  optional `(material acrylic)` style that falls back to an opaque surface.

## Dependencies

- {{F39}} (blocker). Supplies the theme format, modes, contrast pairs,
  templates and CSS compilation.
- {{F04}} (blocker). Supplies the Fluent 2 section of the digest: alias-token
  roles, ramps, control anatomy and the high-contrast rules, all with source
  links. To start before {{F04}} merges, read
  https://fluent2.microsoft.design directly, record the source URLs, and
  reconcile later.
- Related: {{F40}} and {{F42}} (sibling themes that share the test helpers),

## Step-by-step plan

1. Write `packages/ui-themes/scripts/generate-fluent2.mjs`.
   - Add `@fluentui/tokens` (MIT) as a **devDependency** only. Check that
     this package name and the exports `webLightTheme`, `webDarkTheme` and
     `teamsHighContrastTheme` exist in the current version.
   - The script reads those theme objects and writes
     `themes/fluent2/{colors,shape,spacing,type,shadow,motion}.lino`, and the
     generated files are committed.
   - If the package does not expose them, copy the values from the Fluent 2
     docs by hand, with source comments.
2. Map the names. Every Fluent alias token becomes a pair of our semantic
   name and the original:
   ```lino
   (fluent2-colors: theme
     (token color.surface '#FFFFFF' (fluent colorNeutralBackground1))
     (token color.on-surface '#242424' (fluent colorNeutralForeground1))
     (token color.primary '#0F6CBD' (fluent colorBrandBackground))
     (pair color.on-surface color.surface)
     (mode dark
       (token color.surface '#292929' (fluent colorNeutralBackground1))))
   ```
   These values are illustrative; take the real ones from the generator.
   Tokens with no semantic equivalent keep a namespaced name such as
   `fluent.color-neutral-stroke-accessible`.
3. In `src/fluent2/brand.js`, implement:

   ```js
   /** @param {Record<number, string> | string} brand 16-stop ramp (10..160) or one seed colour
    * @param {{ id?: string }} [options]
    * @returns {string} LiNo theme text extending fluent2 */
   export function fluentThemeFromBrand(brand, options) {}
   ```

   - Given a seed, build the ramp by interpolating OKLCH lightness with the
     {{F07}} colour helpers.
   - Check the stops the light and dark aliases use for brand colours against
     the generator output for the default brand ramp. The usual pattern is
     stop 80 for light and stop 100 for dark, but verify it.

4. High contrast.
   - The `mode high-contrast` values come from Fluent's high-contrast theme.
   - In forced-colours mode, map surfaces to `Canvas`, text to `CanvasText`,
     the brand colour to `Highlight` and borders to `CanvasText`.
   - Every focusable control keeps a visible 2px focus outline.
5. Write `themes/fluent2/styles.lino` and `templates.lino` for the in-scope
   controls. Use Fluent's `(state hover)`, `(state pressed)` and
   `(state disabled)` alias tokens, not opacity layers. Fluent shows state
   with colour changes, while {{F40}} uses state layers.
6. Write `themes/fluent2/fluent-mapping.lino` in the same row format as
   {{F40}}:

   ```lino
   (map Button (kind button)
     (prop appearance primary (variant filled))
     (prop appearance outline (variant outlined))
     (prop appearance subtle (variant text))
     (status mapped))
   ```

   - Cover at least these components: Button, ToggleButton, Input, Textarea,
     Checkbox, RadioGroup, Switch, Slider, Dropdown, Combobox, Dialog, Menu,
     Tooltip, Toast, Drawer, TabList, Card, Avatar, Badge and Spinner.
   - Reuse the mapping loader and Markdown generator from {{F40}}. If {{F40}}
     has not merged yet, move them to `src/mapping.js` in this issue.

7. In `examples/themes/fluent2.html`, build a gallery in light, dark and
   high contrast. Add Playwright screenshots (including a run with
   `forcedColors: 'active'`), tests, `docs/themes/fluent2.md` and a
   changeset.

## Acceptance criteria

- [ ] `fluent2-theme.test.js`: the package loads with no error diagnostics,
      and every `pair` passes 4.5:1 (text) or 3:1 (non-text UI, marked
      `(pair ... (min 3))`) in light, dark and high contrast.
- [ ] Every generated token keeps its original Fluent name, so a test can
      rebuild a `{ colorNeutralBackground1: ... }` object identical to the
      generator input for the light theme.
- [ ] `generate-fluent2.mjs` is deterministic: two runs produce identical files.
- [ ] `fluent2-brand.test.js`: the default brand ramp reproduces the light
      and dark brand aliases of the generator output, and a seed colour
      produces 16 stops with monotonic lightness.
- [ ] `fluent2-mapping.test.js`: every listed component has a row, every
      mapped kind exists, and `docs/themes/fluent2.md` is up to date.
- [ ] `npm ls --omit=dev` for `@link-foundation/ui-themes` lists no
      `@fluentui/*` package, and no font files are added.
- [ ] Playwright screenshots in light, dark, high contrast and
      `forcedColors: 'active'` are attached to the pull request. Focus
      outlines are visible in all four, and axe reports no violations.
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication` and
      `npm test` pass.
