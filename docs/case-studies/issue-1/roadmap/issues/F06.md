## Context

Every package of the framework reads UI documents written in Links Notation
(LiNo). The official parser
[`links-notation`](https://www.npmjs.com/package/links-notation) (npm 0.27.1,
Unlicense) returns generic `Link` objects (`{ id, values }`), not a UI tree.
The same document has three different parse shapes depending on how it is
written (see "Links Notation parse shapes" in
[ARCHITECTURE.md](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md)
and the script
[experiments/issue-1/lino-parse-shapes.mjs](https://github.com/link-foundation/ui/blob/main/experiments/issue-1/lino-parse-shapes.mjs)):

| Form                      | `new Parser().parse(text)` result                                                    |
| ------------------------- | ------------------------------------------------------------------------------------ |
| One line                  | one link `(ok: button (label OK) (on press (navigate home)))`                        |
| Multi-line parentheses    | head repeated: `((ok: button) ((ok: button) (label OK)) ...)`                        |
| Indented (no parentheses) | a flat list of path links: `(app: document)`, `((app: document) (title '...'))`, ... |

`parser.parseGroups(text)` keeps the indented structure as
`{ element: Link, children: IndentedGroup[] }`. {{F03}} defines the single tree
projection (the UI dialect) and ships conformance fixtures. This issue
implements that projection in the first package, `@link-foundation/ui-core`.

## Goal

`packages/ui-core` exports `parse(text)` that turns any of the three forms of
the same document into the same `UiDocument` tree, `format(doc)` that prints it
back to canonical LiNo, and passes every {{F03}} conformance fixture.

## Scope

### In scope

- `parse(text, options)` → `UiDocument` (roots, `byId` map, diagnostics).
- Projection rules from {{F03}} (`docs/spec/elements.md`,
  `docs/spec/projection.md`): the first value is the kind; atoms after it are
  `positional` values (`(greeting: text 'Hello, links')`); a sublink with an
  id is a child element; a sublink without an id is a **property** when its
  head is declared for the parent kind in `docs/spec/vocabulary.lino`,
  otherwise an **anonymous child** when its head is a registered kind,
  otherwise it is kept verbatim with the warning `unknown-sublink`.
- Unfolding of the multi-line head-repeated shape and of indented path links
  (prefer `parseGroups` for indented input).
- `format(doc, { style: 'inline' | 'multiline' | 'indented' })`.
- Diagnostics: `duplicate-id` (error), `duplicate-property` (warning, last
  wins), `unknown-sublink`, and parse errors with line and column taken from
  `ParseError` (`line`, `column`, `offset`).
- Safety limits passed to the parser: `maxDepth` (default
  `DEFAULT_MAX_DEPTH` = 64) and `maxInputSize`.
- A conformance runner over the {{F03}} fixtures.

### Out of scope

- Typed values (numbers, units, colours, token references) — {{F07}}. Here all
  atoms stay strings and nested links stay arrays.
- Schema validation of kinds and properties (per-kind schemas come with
  {{F26}}); a mutable store — {{F08}}; keeping comments and layout — {{F14}}.

## Step-by-step plan

1. Create `packages/ui-core/package.json` (`"name": "@link-foundation/ui-core"`,
   `"type": "module"`, `"exports": { ".": "./src/index.js" }`), dependency
   `links-notation` (check the current version; 0.27.1 at planning time).
2. `src/types.js` — JSDoc types only. The node shape is exactly the element
   shape of `docs/spec/element-tree.schema.json`, so conformance compares
   `JSON.stringify` output directly:
   ```js
   /**
    * @typedef {string | RawValue[]} RawValue  atom = string, nested non-element link = array
    * @typedef {{ name: string, values: RawValue[] }} UiProperty   e.g. { name: 'label', values: ['OK'] }
    * @typedef {object} UiNode
    * @property {string|null} id            'ok', or null for anonymous elements
    * @property {string} kind               'button'
    * @property {RawValue[]} positional     atoms after the kind
    * @property {UiProperty[]} properties   in source order
    * @property {UiNode[]} children         in source order
    * @typedef {{ roots: UiNode[], byId: Map<string, UiNode>, diagnostics: Diagnostic[] }} UiDocument
    * @typedef {{ code: string, severity: 'error'|'warning', message: string,
    *             line?: number, column?: number, id?: string }} Diagnostic
    */
   ```
3. `src/fold.js`: **path folding** as specified in `docs/spec/projection.md`:
   a link without an id whose first value is structurally equal
   (`Link.equals`) to an already-seen element head, or to a path made of
   them, appends its other values to that element or sublink. This handles
   both the multi-line shape `(H (H a) (H b))` and the indented path links.
   Implement the pseudocode of the spec; never inspect the text with regular
   expressions, only walk `Link` objects.
4. `src/vocabulary.js`: `loadVocabulary(text)` reads `vocabulary.lino` with the
   same parser; `src/project.js`: `projectLink(link, vocabulary) → UiNode`
   applying the element rules. `parseGroups` MAY be used for indented input;
   a test asserts it gives the identical tree.
5. `src/parse.js`: `parse(text, { maxDepth, maxInputSize } = {})`. Detect the
   indented form (top-level links that are not parenthesised, i.e.
   `parseGroups` yields groups with children) and choose the path. Catch
   `ParseError` and return `{ roots: [], diagnostics: [{ code: 'parse-error', line, column, message }] }`
   instead of throwing; export `parseOrThrow` for callers that want to throw.
6. Build `byId`; on a duplicate id add the error `duplicate-id` and keep the
   first node in `byId`; a repeated single-valued property keeps all entries
   in `properties` but adds the warning `duplicate-property` (readers use the
   last one), as `docs/spec/ordering-and-ids.md` specifies.
7. `src/format.js`: `format(doc, { style })`. Build `Link` objects and call
   `link.format()` / `formatIndentedDocument` from `links-notation`; quote
   values that need it with `escapeReference`. Default style `multiline`
   (one child or prop per line, two spaces).
8. `src/index.js` re-exports `parse`, `parseOrThrow`, `format`, `projectLink`,
   `walk(doc, visitor)` and the type definitions; add `src/index.d.ts`.
9. Tests (see below) and `packages/ui-core/README.md` with the three input
   forms and the resulting tree printed as JSON.

Example — input (any of the three forms):

```lino
(ok: button (label 'OK') (variant filled) (on press (navigate home)))
```

Output (`JSON.stringify(doc.roots[0])`, abbreviated):

```json
{
  "id": "ok",
  "kind": "button",
  "positional": [],
  "properties": [
    { "name": "label", "values": ["OK"] },
    { "name": "variant", "values": ["filled"] },
    { "name": "on", "values": ["press", ["navigate", "home"]] }
  ],
  "children": []
}
```

## Acceptance criteria

- [ ] `forms.test.js`: `samples/document.lino` (multi-line), its one-line
      equivalent and `samples/indented.lino` (after adding the same props) give
      deep-equal trees; the root is `{ id: 'app', kind: 'document' }` with child
      `body` of kind `stack` containing `greeting` and `ok`.
- [ ] `conformance.test.js` runs every {{F03}} fixture under
      `docs/spec/fixtures/`: trees equal the `.tree.json` files and
      diagnostics (codes and severities) equal the `.diagnostics.json` files.
- [ ] `format.test.js`: for every sample and fixture,
      `parse(format(parse(t)))` deep-equals `parse(t)` for all three styles.
- [ ] `diagnostics.test.js`: an unclosed `(` yields `code: 'parse-error'` with
      the correct `line` and `column`; a duplicate `ok:` yields `duplicate-id`;
      input nested deeper than `maxDepth` yields an error, not a crash; an
      unregistered sublink such as `(colour red)` under `button` yields the
      warning `unknown-sublink` and is kept.
- [ ] `parse` never throws on any string (test with 200 deterministic seeded
      random inputs built from `(`, `)`, `:`, `'`, spaces, letters, newlines).
- [ ] `grep -rn "new RegExp\|\.match(\|\.replace(/" packages/ui-core/src` shows
      no regex used to read LiNo structure.
- [ ] `npm test`, `npm run lint`, `npm run format:check`,
      `npm run check:duplication` pass.
