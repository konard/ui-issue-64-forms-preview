## Context

R24 asks for our own documentation and demo website built with the framework;
R7 asks for "the simplest possible description, which is sharable by default".
{{F54}} creates the site (`packages/site/`, LiNo pages, Vite, Pages deploy).
This issue adds the two pages that make the site a demo:

- **Component gallery** (`/<lang>/components/`): every component of the
  catalog, with its variants rendered side by side for each theme and colour
  scheme, and the LiNo source next to each example.
- **Playground** (`/<lang>/playground/`): a LiNo editor and a live preview;
  the document is shared through the URL.

Research
([existing-solutions.md sections 3 and 9](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)):
Storybook (MIT) controls are "a property grid generated from component
metadata"; Ladle and Histoire (MIT) are references "for a minimal component
playground that the docs site can implement with our own designer"; Xcode
Previews show a variant matrix (theme × size × locale × accessibility). The
doublets-web playground (Monaco plus graph view) is our own prior art
([links-notation-ecosystem.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)).
Shared links in our projects: konard.github.io `#settings=<urlencoded JSON>`,
immortality diff-only links, formal-ai's 8,192-character URL budget
([konard.github.io research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md),
[formal-ai research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md)).

## Goal

A visitor can browse all components with their variants, open any example in
the playground, edit the LiNo, see the result at once, inspect it with dev
mode ({{F46}}), and copy a link that reproduces exactly that document.

## Scope

### In scope

- Gallery generated at build time from the component catalog ({{F26}}): for
  each component a section with its examples and a matrix
  `theme × scheme × state` (states such as default, hover, pressed, disabled
  forced through the state attributes defined by {{F12}}, if any; otherwise
  only `disabled` and default). Each cell has a "Open in playground" link.
- Example sources in `packages/site/content/examples/<component>/*.lino`,
  reused by the gallery, the playground examples list and tests.
- Playground: split view (resizable with {{F28}} if merged, else CSS grid),
  left an editor (plain `textarea` with line numbers, or the {{F38}} code
  editor if merged), right the live preview rendered by `ui-dom` in an
  isolated container; theme and scheme selectors; examples dropdown.
- Live update debounced 150 ms; parse errors shown under the editor with line
  and column; the last valid preview stays visible.
- Dev mode ({{F46}}) available on the preview (button "Inspect"), with edits in
  the inspector written back to the editor text.
- Share link: `#lino=<encodeURIComponent(text)>`; if longer than 8,192
  characters, try a compressed form `#lino-z=<base64url(deflate-raw)>` with
  `CompressionStream` (check browser support; fall back to "too long, copy the
  text"). Opening a link loads the document into the editor.
- Untrusted input: shared documents are validated before rendering
  (size limit, depth limit, only known kinds, actions disabled except a
  harmless `log`, URLs only `https:` or relative, `javascript:` rejected).

### Out of scope

- The full designer ({{F48}}) inside the playground (a link "Open in designer"
  is enough if it exists).
- Server-side storage of shared documents.
- Code export buttons ({{F52}}) — a follow-up.

## Dependencies

- {{F54}} (blocker): site package, page pipeline, layout, i18n, theme

## Step-by-step plan

1. `packages/site/src/gallery/catalog.js`: `loadCatalog()` returns
   `[{ kind, title, examples: [{ id, file, text }] }]` from the {{F26}}
   catalog and the example files. Missing examples fail a test.
2. `packages/site/src/gallery/matrix.js` (pure):
   `buildMatrix(example, { themes, schemes, states }) -> [{ key, links }]`
   wrapping the example in `(theme ...)` and `(scheme ...)` links.
3. Gallery page generation in the {{F54}} Vite plugin: one page per
   language listing all components; each cell pre-rendered.
4. `packages/site/src/playground/share.js`:
   `encodeShare(text) -> Promise<{ hash, tooLong }>` and
   `decodeShare(hash) -> Promise<string | null>`.
5. `packages/site/src/playground/validate.js`:
   `validateDocument(text, { kinds }) -> { tree, errors }` using
   `new Parser({ maxInputSize: 65536, maxDepth: 32 })` from `links-notation`
   and the `ui-core` validator; actions replaced with a no-op logger.
6. `packages/site/src/playground/playground.lino` and `playground.js`: the
   page (editor, preview, toolbar: examples, theme, scheme, Inspect, Copy link).
7. Edits from the dev mode inspector update the store; regenerate the editor
   text with the source-preserving formatter from {{F14}} if merged, else
   with `formatLinks`.
8. Tests and Playwright scenarios (below).

Example shared document:

```lino
(demo: document
  (body: stack
    (gap (token space.medium))
    (hello: text 'Hello from the playground')
    (go: button (label 'Press me') (variant filled))))
```

## Acceptance criteria

- [ ] Every component in the catalog has at least one example and appears in
      the gallery in every theme and scheme (test).
- [ ] `decodeShare(encodeShare(t))` equals `t` for all examples, including
      non-ASCII text and hex colours (test).
- [ ] `validateDocument` rejects: input over the size limit, depth over the
      limit, unknown kinds, `javascript:` URLs; and accepts every example.
- [ ] Playwright: typing in the editor updates the preview within 500 ms; an
      invalid edit shows line and column and keeps the last preview.
- [ ] Playwright: copy link, open it in a new page, the same document renders.
- [ ] Playwright: "Inspect" opens dev mode on the preview; changing a label
      in the inspector changes the editor text.
- [ ] axe reports no violations on the gallery and the playground; screenshots
      in light and dark attached.
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication`,
      `npm test` pass.

## How to verify

```bash
npm run build --workspace @link-foundation/ui-site
node --test packages/site/tests/*.test.js
npm run preview --workspace @link-foundation/ui-site
npm test
npm run lint && npm run format:check && npm run check:duplication
```

Open `/ui/en/playground/` in the preview, edit the example, copy the link and
open it in a private window.
