## Context

The "Checks and release" workflow runs `scripts/preflight-credentials.sh`
("Release Preflight" job) on `main`. On commit `428ee07` (run 41299671735) it
fails:

```text
FAIL: npm has no package @link-foundation/example-package-name yet, and npm
configures trusted publishing only for published packages. Add an NPM_TOKEN
repository secret (a granular token allowed to publish
@link-foundation/example-package-name) at
https://github.com/link-foundation/ui/settings/secrets/actions for the first
release, then add a trusted publisher for link-foundation/ui, workflow
release.yml, at https://www.npmjs.com/package/@link-foundation/example-package-name/access
and delete the secret
```

The log is stored in
[`ci-logs/main-41299671735.log`](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/ci-logs/main-41299671735.log).

The package name in the message is still the template name. {{B01}} renames
the package (or makes the root private), so the credentials must be set up for
the **new** name. That is why this bug is blocked by {{B01}}.

## Goal

After {{B01}}, the release preflight on `main` passes, and the first release of
the framework packages can be published with npm trusted publishing.

## Scope

### In scope

- **Maintainer action (cannot be done by an agent):** create a granular npm
  token that can publish the new package name(s) under `@link-foundation`,
  and store it as the `NPM_TOKEN` secret at
  https://github.com/link-foundation/ui/settings/secrets/actions.
- After the first successful publish, add a trusted publisher
  (repository `link-foundation/ui`, workflow `release.yml`) for each published
  package on npmjs.com and delete the `NPM_TOKEN` secret, as the preflight
  message says.
- If {{B01}} makes the root package private and no package is published yet,
  confirm that the preflight skips npm checks for private packages; if it does
  not, fix `scripts/preflight-credentials.sh` and add a test for it.

### Out of scope

- Renaming the package: that is {{B01}}.
- Creating the workspace packages: that is {{F01}}.

## Dependencies

- {{B01}}: the package name must be final before a token is scoped to it.

## Step-by-step plan

1. Read `scripts/preflight-credentials.sh` and its tests (`grep -rln
preflight tests/`).
2. With the name from {{B01}}, run the preflight locally the way the workflow
   does (see the "Release Preflight" job in `.github/workflows/release.yml`)
   and record the output.
3. If the root package is private and the script still fails, change the
   script to skip private packages, add a test, and open a pull request.
4. Otherwise, comment on this issue asking a maintainer to add `NPM_TOKEN`,
   with the exact package name(s).
5. After the first release, ask the maintainer to configure trusted publishing
   and remove the secret.

## Files to create or change

- `scripts/preflight-credentials.sh` and `tests/` (only if step 3 applies)

## Acceptance criteria

- [ ] The "Release Preflight" job on `main` is green.
- [ ] Each published package has a trusted publisher for
      `link-foundation/ui` / `release.yml`
