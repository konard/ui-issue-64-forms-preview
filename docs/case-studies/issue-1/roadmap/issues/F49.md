## Context

Issue #1 asks to "record and replay any animations and interactions in the
Links Notation format" (R4) and for a WYSIWYG editor like Visual Studio (R5,
R10). Animations and recordings are links
([`samples/animation.lino`](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/samples/animation.lino)):

```lino
(press-feedback: animation
  (target ok)
  (duration (token motion.duration.short))
  (easing standard)
  (track scale (key 0 1) (key 0.5 0.96) (key 1 1)))
(recording-1: recording
  (started '2026-11-01T12:00:00Z')
  (event 0ms (set ok label 'OK'))
  (event 840ms (input pointer down ok))
  (event 990ms (set ok label 'Saved')))
```

A `track` has a property name and `(key <offset> <value>)` links, where the
offset is a fraction from 0 to 1 of the duration. A `recording` has
`(event <time>ms <action>)` links. {{F44}} plays animations, {{F45}} records
and replays interactions. This issue adds the visual editor for both, as a
panel of the designer from {{F48}}, as planned in
[`docs/ARCHITECTURE.md`](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md).

Research
([existing-solutions.md section 6](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)):
Theatre.js core is Apache-2.0 but **Theatre.js Studio (the timeline UI) is
AGPL-3.0**: use it for ideas only, copy no code and add no dependency. GSAP is
not allowed. Motion Canvas (MIT) and Anime.js (MIT) are good references for
timeline UX and keyframe models.

## Goal

A **Timeline** panel in `@link-foundation/ui-designer` that shows the
animations and recordings of the open document as tracks with keyframes and
events, lets the user scrub, play, add, move and delete keyframes and events,
and writes every change back to the LiNo source through the designer's
source-preserving sync, with undo/redo.

## Scope

### In scope

- Timeline panel docked at the bottom of the designer (next to Source),
  listing: one row per `animation` (expandable to one lane per `track`) and
  one row per `recording` (one lane of events).
- Time ruler in milliseconds, zoom (Ctrl/Cmd+wheel and buttons), horizontal
  scroll, playhead scrubbing that seeks the {{F44}} player (or the {{F45}}
  replayer for recordings) so the canvas shows that moment.
- Play, pause, stop, loop toggle; playback respects `prefers-reduced-motion`
  only for the preview of the designer chrome, not for the edited animation.
- Keyframes: select (click, Shift+click), move by drag with snapping to the
  playhead, other keyframes and a frame grid (default 60 fps), add at the
  playhead (`K` key or button), delete (`Delete`), edit value and easing in the
  Properties panel of {{F46}}/{{F48}}.
- Recording events: move in time, delete, edit the action in Properties.
- Duration: drag the end handle of an animation; when the duration is a token
  (as in the sample), dragging asks to replace it with a literal value.
- Keyboard: arrow keys move the selected keyframe by one frame, Shift+arrows
  by 10 frames; `Home`/`End` move the playhead; space toggles play.
- Every edit is one store transaction ({{F08}}) and is written to the source
  through the designer sync ({{F48}} M4, {{F14}}).
- Timeline layout described in LiNo (`src/timeline/timeline.lino`) and
  rendered with the framework.

### Out of scope

- Curve (graph) editor for easing; easing is chosen from a list. Follow-up.
- Recording itself (capturing input) is {{F45}}.
- Exporting animations to Lottie: {{F53}}.

## Dependencies

- {{F48}} (blocker): designer shell, docked panels, selection, Properties
  panel, the transaction commands and the two-way source sync.
- {{F45}} (blocker): recording model, `recording` parsing and the replayer
  with seek; through it the {{F44}} player (`seek(ms)`, `play()`, `pause()`).
  Use the names merged in those issues; this issue only names the needs.
- Related: {{F11}} (duration tokens), {{F26}} (buttons, slider, select),
  {{F05}} (Playwright tests).
- The pure modules (steps 2–4) can be built and tested before {{F48}} merges.

## Step-by-step plan

1. Create `packages/ui-designer/src/timeline/`.
2. `model.js` (pure):
   - `readTimeline(tree)` returns
     `{ animations: [{ id, target, durationMs, tracks: [{ property, keys: [{ offset, value }] }] }], recordings: [{ id, events: [{ timeMs, action }] }] }`;
     a token duration is resolved through the token resolver passed in.
   - `moveKeyframe(track, index, offset)` clamps to `0..1`, keeps the keys
     sorted and never puts two keys at the same offset (returns a new track).
   - `insertKeyframe(track, offset, value)`, `deleteKeyframe(track, index)`;
     the first and last keys may be deleted only if two or more remain.
   - `moveEvent(recording, index, timeMs)` (clamped to `>= 0`, sorted).
3. `scale.js` (pure): `timeToX(ms, { zoom, scroll })`,
   `xToTime(x, { zoom, scroll })`, `snapTime(ms, { fps, candidates, threshold })`.
4. `commands.js`: wrap the model operations into designer commands that emit
   the matching LiNo edits, e.g. moving the middle key of the sample to 0.4
   changes only that link to `(key 0.4 0.96)`.
5. `timeline.lino`, `timeline.js`: the panel (ruler, rows, lanes, keyframe
   diamonds as focusable buttons with `aria-label` such as
   `scale key at 40%, value 0.96`), playhead, toolbar.
6. Wire the playhead to the player/replayer seek and the canvas.
7. Add the panel to the designer layout and a timeline example to
   `packages/ui-designer/examples/`.
8. Tests: unit tests for steps 2–4; Playwright test for scrubbing and dragging.

## Acceptance criteria

- [ ] `readTimeline` on the sample returns one animation with one `scale`
      track of three keys and one recording with three events (unit test).
- [ ] `moveKeyframe` keeps keys sorted, clamps to `0..1` and refuses
      duplicate offsets (unit tests).
- [ ] `timeToX(xToTime(x)) === x` within 0.5 px for several zoom levels.
- [ ] Moving the middle key to 0.4 in the panel changes only that link in the
      source; all other lines of the fixture are unchanged (diff test).
- [ ] Dragging an event of `recording-1` from 840 ms to 900 ms writes
      `(event 900ms (input pointer down ok))`.
- [ ] Every edit is undone by one `Ctrl/Cmd+Z`.
- [ ] Scrubbing the playhead to 50% of `press-feedback` shows the `ok` button
      at scale 0.96 on the canvas (Playwright, computed transform).
- [ ] All keyframe actions work with the keyboard; axe has no violations on
      the timeline example; screenshot attached.
- [ ] No Theatre.js Studio or GSAP code or dependency (`npm ls` reviewed).
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication`,
      `npm test` pass.

## Prior art and libraries

- Theatre.js Studio: sequence editor, keyframe lanes (ideas only, AGPL).
- Motion Canvas (MIT): timeline with scrubbing and time events.
- Anime.js (MIT) timeline API; Web Animations API keyframe offsets (the same
  0..1 offset model as our `key` links).
- Browser DevTools Animations panel (scrub, slow down, replay).
- rrweb (MIT) player: event timeline for recordings.
- Avoid: GSAP, any AGPL timeline UI.
