## Context

Two of our sites already have mature, hand-written settings engines. The
framework should generalise them so that every app gets the same behaviour
from one LiNo schema (R2, R9, R11), and the settings panel ({{F37}}) can be
built on top.

immortality (`app/src/settings.ts`, 1560 lines, Unlicense — code may be
ported) has 49 typed settings (choice, toggle, range with
`min`/`max`/`step`/`unit`) in 8 groups, `coerceAxisValue`, `mergeSettings`
for untrusted input, `diffFromDefaults`, `migrateLegacySettings` (keeps only
values the user changed in v1), 12 presets, `randomizeSettings` with an
injected random function and locked keys, a diff-only share hash
`#ui=<JSON {v:2,...}>`, and `applySharedLook`, which keeps the viewer's
comfort settings (animations, sound, volume). Known bugs: `isPresetActive`
compares with `JSON.stringify` (key order matters) and the list of CSS axes is
duplicated by hand in a test
([immortality-and-anime-avatar.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md)).

konard.github.io (no licence — **ideas only, do not copy code**) uses flat
dotted keys (`liquid.blur`, `skin.name`), a rule table (`d`, `min`, `max`,
`u`, `o`, `c`), diff-only persistence in `localStorage`, CSS variables and
`data-*` attributes applied **before first paint** by an injected script,
`#settings=<JSON>` share links, comfort keys (`motion.mode`, `sound.on`,
`sound.volume`, ...) and a test (`applied.test.js`) that every setting is used
([konard-github-io-and-links-visuals.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md)).

## Goal

`packages/ui-settings` (`@link-foundation/ui-settings`) reads a settings schema
written in LiNo and provides pure functions for coercion, untrusted merging,
diffing, migration, presets, randomisation and share links, plus DOM
application before first paint and a test helper that proves every setting is
used.

## Scope

### In scope

- Schema format (agreed with {{F37}}):
  ```lino
  (settings-schema: schema (version 2))
  (appearance: section (label 'Appearance'))
  (liquid.blur: (type range) (default 18) (min 0) (max 40) (step 1) (unit px)
    (section appearance) (label 'Blur') (apply (css-var --liquid-blur)))
  (theme.mode: (type choice) (default auto) (options auto light dark)
    (section appearance) (apply (data-attr theme-mode)))
  (motion.reduce: (type toggle) (default false) (section appearance) (comfort))
  (accent: (type color) (default '#3390EC') (apply (css-var --accent)))
  (preset calm (label 'Calm') (set liquid.blur 24) (set theme.mode dark))
  (migration (from 1) (to 2) (rename blur liquid.blur) (old-default liquid.blur 12))
  ```
- Field types `range`, `number`, `toggle`, `choice`, `color`, `text`, and
  `defineFieldType(name, { coerce, equals, random, format })` so apps can add
  `vector3`, `map` or `asset` (requested by {{F63}}).
- Values document (diff-only): `(settings (version 2) (liquid.blur 24))`.
- Share links `#settings=<encodeURIComponent(values LiNo)>`, plus readers for
  the old JSON formats (`#ui=` of immortality, `#settings=` of konard.github.io).
- `(comfort)` fields: kept from the viewer when applying presets or shared
  looks, and never randomised.
- Binding to {{F10}}: values are overrides of element `settings` in the
  `user` layer (diff-only by construction).

### Out of scope

- The settings panel UI ({{F37}}); per-site migrations ({{F58}}, {{F64}}).

## Dependencies

- {{F10}} (blocker): `createConfig`, `set('user', 'settings', key, [value])`,
  `persistLayer`, `exportPatch`. Before it merges, keep values in a plain
  object and add `bindConfig` last.
- Related: {{F06}} (`parse`), {{F07}} (colour/dimension coercion), {{F37}}
  (expects `SettingsSchema`, diff, presets, share encoding), {{F46}}, {{F57}}
  (JSON reader kept one release), {{F58}}, {{F63}}, {{F64}}.

## Step-by-step plan

1. Create `packages/ui-settings/package.json`
   (`"name": "@link-foundation/ui-settings"`), dependencies `ui-core`,
   `ui-config` (workspace).
2. `src/schema.js`: `readSchema(text) → { schema, diagnostics }`;
   ```js
   /** @typedef {{ key: string, type: string, default: unknown, label?: string, section?: string,
    *   min?: number, max?: number, step?: number, unit?: string, options?: string[],
    *   comfort: boolean, apply: Array<{ cssVar?: string, dataAttr?: string }> }} SettingField */
   /** @typedef {{ version: number, fields: Map<string, SettingField>, sections: Section[],
    *   presets: Map<string, Preset>, migrations: Migration[] }} SettingsSchema */
   ```
   Report unknown types, defaults that fail their own coercion, duplicate keys.
3. `src/coerce.js`: `coerce(field, raw) → { ok, value }` — clamp ranges, round
   to `step`, choices must be members, colours must be `#rrggbb`, toggles accept
   `true`/`false`. Port from immortality `coerceAxisValue`.
4. `src/values.js`: `defaults(schema)`, `merge(schema, base, untrusted) →
{ values, rejected: string[] }` (drops unknown keys and invalid values, never
   throws), `diff(schema, values)`, `isDefault`, `reset(schema, values, keys?)`,
   `countCustomized`, `equalValues` (structural, order-independent).
5. `src/presets.js`: `applyPreset(schema, values, id)` (keeps comfort fields),
   `activePreset(schema, values)` using `equalValues` (fixes the key-order bug).
6. `src/random.js`: `randomize(schema, values, { random, locked = new Set() })`;
   `random` is required (no `Math.random` inside); comfort and locked fields
   are unchanged.
7. `src/migrate.js`: `migrate(schema, stored)` applies `rename`, then drops
   values equal to the `old-default` of their version (so users get new
   defaults, as immortality does), then `merge`.
8. `src/codec.js`: `toLino(schema, values)` (diff only, sorted by schema
   order), `fromLino(schema, text)`, `fromLegacyJson(schema, json)`,
   `toShareHash(schema, values)`, `fromShareHash(schema, hash, viewerValues)`
   — rejects input over 8 KiB, merges as untrusted, keeps viewer comfort
   values.
9. `src/dom.js`: `applyToRoot(schema, values, root)` sets
   `--liquid-blur: 18px` and `data-theme-mode="auto"`;
   `beforePaintScript(schema, { storageKey })` returns the source of a small
   inline script that reads stored values, validates them with the serialised
   rule table and applies them before first paint; `beforePaintScriptHash()`
   returns its `sha256-...` for a Content Security Policy.
10. `src/testing.js`: `assertEverySettingUsed(schema, { css, sources })` —
    each field has an `apply` target found in the CSS text, or its key appears
    in one of the given source strings; the error lists unused keys.
11. `src/config.js`: `bindConfig(config, schema, { target = 'settings' })`.
12. README with the schema grammar and a migration guide from both sites.

## Acceptance criteria

- [ ] `schema.test.js`: the schema above gives 4 fields, 1 section, 1 preset,
      1 migration and no diagnostics.
- [ ] `coerce.test.js`: `liquid.blur` 99 → 40, -3 → 0, `'abc'` rejected;
      `theme.mode` `sepia` rejected; `accent` `red` rejected.
- [ ] `values.test.js`: `merge` of `{ "liquid.blur": 24, "evil": "x", "theme.mode": 7 }`
      keeps only `liquid.blur`; `toLino(diff(...))` is
      `(settings (version 2) (liquid.blur 24))`.
- [ ] `presets.test.js`: `activePreset` returns `calm` for values built in either
      key order; applying it keeps `motion.reduce: true`.
- [ ] `random.test.js`: the same seeded `random` gives identical results twice;
      comfort and locked keys never change over 100 runs.
- [ ] `migrate.test.js`: a v1 value equal to the old default (12) is dropped;
      a changed v1 `blur` 30 becomes `liquid.blur` 30.
- [ ] `codec.test.js`: `fromShareHash(toShareHash(v))` equals `v`; a legacy
      `#ui=` JSON hash and a `#settings=` JSON hash are read; a 9 KiB hash is
      rejected; viewer comfort values win.
- [ ] `dom.test.js` (jsdom): `applyToRoot` sets the variable and attribute;
      the before-paint script, run in jsdom with corrupted storage, does not
      throw and applies defaults.
- [ ] `assertEverySettingUsed` fails when a field's CSS variable is missing.
- [ ] `npm test`, `npm run lint`, `npm run format:check`,
      `npm run check:duplication` pass.
