## Context

The WYSIWYG editor (R5) always shows the Links Notation source next to the
visual canvas, dev mode lets users edit LiNo overrides, and the links network
converter ({{F35}}) needs a text pane. We need one text editor component with
LiNo highlighting and validation.

deepcase is our prior art
([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/deepcase.md)):

- `imports/cyto/editor.tsx` `CytoEditor` (656 lines) is a Monaco editor in a
  modal with tabs stored in the local store key `editor-tabs`, drafts in
  `editor-values` with a 500 ms debounce, and an unsaved dot;
  `editor/editor-grid.tsx` splits it with a `VerticalSash`;
  `editor-switcher.tsx` switches Preview, Handlers and Results.
- The perception app uses Monaco and CodeMirror (`@uiw/react-codemirror`) for
  mobile.
- Bugs to avoid: code is lost when switching tabs
  (https://github.com/deep-foundation/deepcase/issues/43), no warning before an
  external update overwrites a draft
  (https://github.com/deep-foundation/deepcase/issues/44), an empty string
  cannot be saved (https://github.com/deep-foundation/deepcase/issues/35),
  clicking a code file runs it (https://github.com/deep-foundation/deepcase/issues/3),
  the splitter position is not remembered
  (https://github.com/deep-foundation/deepcase/issues/54), plus other editor bugs listed in the research:
  https://github.com/deep-foundation/deepcase-app/issues/243,
  https://github.com/deep-foundation/deepcase-app/issues/238,
  https://github.com/deep-foundation/deepcase-app/issues/231,
  https://github.com/deep-foundation/deepcase-app/issues/178,
  https://github.com/deep-foundation/deepcase-app/issues/171,
  https://github.com/deep-foundation/deepcase-app/issues/170,
  https://github.com/deep-foundation/deepcase-app/issues/138,
  https://github.com/deep-foundation/deepcase-app/issues/137,
  https://github.com/deep-foundation/deepcase-app/issues/240.

doublets-web also has a Monaco playground with a graph view
([links-notation ecosystem](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)).

## Goal

A `code-editor` element edits text in several documents (tabs), highlights
Links Notation, shows parse diagnostics from the official `links-notation`
parser, keeps drafts per document id, warns before external changes replace a
draft, and is built on CodeMirror 6 by default with an optional Monaco
adapter.

## Scope

### In scope

- `editor-engine.js` interface with a CodeMirror 6 implementation (default,
  lazily loaded) and an optional Monaco implementation.
- LiNo language support: highlighting of parentheses, ids before `:`, quoted
  strings, references and comments; bracket matching; folding by link.
- Diagnostics: parse errors with line and column from the `links-notation`
  parser, shown inline and in a list.
- Documents and tabs: `editor-tabs` and drafts keyed by document id in an
  injected storage, dirty marker, close with "unsaved changes" prompt.
- External update while dirty: show a bar "The source changed. Keep mine /
  Load theirs / Compare".
- Other languages through engine packages: JavaScript, CSS, JSON, Markdown.

### Out of scope

- Formatting LiNo (parsing drops comments and layout; it needs {{F14}}).
- The visual designer ({{F48}}) and running code.
- A diff viewer beyond a simple side-by-side "Compare" view.

## Dependencies

- **Blocked by {{F26}}**: buttons, icon buttons and the text field used in the
  toolbar, tabs bar and the "source changed" bar.
- **Related:** {{F06}} (ui-core parsing and error positions; until it exists,
  call `links-notation` directly behind `validateLino(text)`), {{F14}}
  (source-preserving edits), {{F27}} (tabs and dialogs), {{F28}} (split pane
  with remembered size), {{F35}}, {{F46}}, {{F48}}, {{F62}}.

## Step-by-step plan

1. Create `packages/ui-components/src/editor/` and export it.
2. Write `validate-lino.js`:
   ```js
   /**
    * @param {string} text
    * @returns {{ ok: boolean, diagnostics: { line: number, column: number, message: string, severity: 'error'|'warning' }[] }}
    */
   export function validateLino(text) {}
   ```
   It uses the `links-notation` `Parser` (error positions, for example from
   `StreamParser`'s `position()`; check the current API). Never use regular
   expressions to validate.
3. Write `lino-highlight.js`: a lexical token stream for colouring only
   (`paren`, `id`, `colon`, `string`, `comment`, `word`). It never builds links;
   structure, folding and errors come from the parser. Remember that `#` starts
   a comment only after whitespace, so `'#6750A4'` in quotes is a string.
4. Write `editor-engine.js` (interface) and `engines/codemirror.js` (lazy
   `import()` of CodeMirror 6 packages; check current versions and licences)
   and `engines/monaco.js` (optional peer dependency).
5. Write `documents-model.js` (pure): open, close, switch, edit, save,
   `externalUpdate(id, text)` returning `conflict` when the draft is dirty.
   Saving an empty string is valid. Drafts debounce at 500 ms with an
   injected clock.
6. Write `code-editor.js` (element): tabs bar, editor area, diagnostics list,
   "source changed" bar; opening a document never executes it.
7. Accessibility: the editor has a label; Escape then Tab leaves the editor
   (do not trap focus); diagnostics are announced with `aria-live="polite"`;
   tabs follow the APG tabs pattern.
8. Example `packages/ui-components/examples/editor.html`: the sample
   `document.lino` in one tab and `tokens.lino` in another, with a live
   diagnostics list.

Input example with an error and the expected diagnostic:

```text
(app: document
  (title 'Links UI demo')
```

Expected: one error saying the link is not closed, positioned at the end of
the input. Check the exact line, column and message the parser gives and pin
them in the test.

## Acceptance criteria

- [ ] `validateLino` returns `ok: true` for every file in
      `docs/case-studies/issue-1/samples/` and a positioned error for the
      unclosed example (tests).
- [ ] `lino-highlight` marks `'#6750A4'` as a string and `# note` after a space
      as a comment (tests).
- [ ] Switching tabs keeps unsaved text in each tab (Playwright; regression
      for deepcase issue 43).
- [ ] An external update to a dirty document shows the conflict bar and does
      not change the text until the user chooses (Playwright; deepcase issue 44).
- [ ] Saving an empty document stores `''` (test; deepcase issue 35).
- [ ] Monaco is not loaded unless the Monaco engine is selected (Playwright
      watches requests).
- [ ] Keyboard users can leave the editor with Escape then Tab (Playwright).
