## Context

[meta-sovereign](https://github.com/link-foundation/meta-sovereign) is the
largest UI codebase in the organisation, at v1.2.0. The facts below come
from the
[research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/meta-sovereign-chat.md).

- **React without JSX.** It uses React 19 with `el(...)` instead of JSX, and
  no component library.
- **Large bundle.** The 4.6 MB bundle `js/src/web/app.min.js` is committed.
- **One huge stylesheet.** `js/src/web/app.css` has 13,794 lines, about 60
  custom properties and about 200 `!important` lines.
- **Many chat files.** `js/src/web/` holds 409 JS files; 215 of them are
  `chat-*.js`.
- **Data stored as links.** `js/src/storage/lino-store.js` stores the data as
  links.

Issue https://github.com/link-foundation/meta-sovereign/issues/27 asks to
"simplify the UI, and reduce repeating ourselves (DRY in code and UI/UX)".
Issue https://github.com/link-foundation/meta-sovereign/issues/25 asked for
Chakra UI, which was never adopted. {{F30}} builds the chat kit from this code.
This issue moves meta-sovereign onto it. The deliverable is a pull request
in meta-sovereign, plus new link-foundation/ui issues for any missing pieces.

## Goal

meta-sovereign renders its chat screen with `@link-foundation/ui-components`
(chat kit), themes and i18n. The four skins become LiNo theme files, and the
settings become one LiNo settings link. The duplicated chat modules are
deleted, while all quality gates keep passing.

### Out of scope

- These modules stay in meta-sovereign:
  - Telegram-specific adapters, such as entities, topics and `.tgs`
    stickers;
  - `chat-voice.js`, `chat-round-record.js`, `chat-emoji.js` and
    `chat-stickers.js`, until {{F30}} follow-ups exist.
- The Rust server, Electron and Capacitor packaging (beyond rebuilding the
  bundle).
- Contacts, CRM and operator screens. Migrate them later with the same
  playbook.

## Step-by-step plan

This follows the research's 8-step migration. Each step is one pull request
and leaves the app deployable.

1. Copy the {{F57}} checklist template into the tracking pull request.
2. **Freeze the contracts.** Add tests for:
   - `data-theme-mode`, `data-theme`, `data-skin` on `<html>`;
   - the token names `--bg --bg-elev --text --accent --control-h --radius
--chat-bg --bubble-in --bubble-out --bubble-radius`;
   - `--bubble-radius` of 15px (telegram), 7.5px (whatsapp) and 18px
     (signal);
   - localStorage `metaSovereignTheme` and `metaSovereignSkin`.
3. **Baseline screenshots.** Use the existing Playwright Chromium and WebKit
   suites, axe-core `stepAxeAudit`, and the pixel and contrast checks in
   `docs/DELIVERY-AUDIT.md`. Cover four skins × light/dark × three widths
   (≤640, 641–1023, ≥1024).
4. **Tokens, with zero visual change.** Write `themes/{t3,telegram,whatsapp,signal}.lino`
   with unchanged token names, for example
   `(telegram: theme (extends t3) (token bubble-radius 15px))`. Generate the
   `:root[data-skin=...][data-theme=...]` CSS from them. Delete the old skin
   blocks, including the out-of-place override near `app.css` line 13,589.
5. **Settings as LiNo.** Store one settings link (theme, skin, scale,
   effects, locale) in the existing lino store. Keep localStorage as a cache,
   and read the old keys once.
6. **Leaf modules.** Replace `message-text.js`, `chat-model.js` and
   `panel-resize.js`, the virtual list and `menuPlace` with the framework
   versions. Use thin re-exports, so imports elsewhere do not change in the
   same pull request.
7. **Bubble and composer.** Put them behind the provider-neutral contract.
   Telegram specifics move into an adapter in meta-sovereign. The composer
   must keep the reserved-space contract (`--composer-space`) and the
   WebKit-safe `ResizeObserver` deferral.
8. **i18n.** Convert `locales/*` to lino-i18n catalogs with its CLI. Keep the
   `t()` signature.
9. **Screens.** Declare the shell and chat layout in LiNo, for example
   `(chat: split (list chat-list) (stream message-stream) (behavior chat-window))`,
   rendered by `@link-foundation/ui-react`.
10. **Constraints check, after every step:**
    - no JSX required and no `eval` (CSP);
    - axe passes;
    - Chromium and WebKit e2e pass;
    - reduced-motion, transparency and effects switches still work;
    - rem scaling at 100–200 %;
    - offline-first behaviour.
11. **Delete** the replaced modules and CSS. Record the line counts of
    `app.css` and of `chat-*.js` before and after.

## Acceptance criteria

- [ ] The contract tests from step 2 pass before and after every step.
- [ ] Screenshot diffs (four skins × two modes × three widths) are below 0.1 %,
      or each difference is explained in the pull request.
- [ ] axe-core reports no new violations; the Chromium and WebKit e2e pass.
- [ ] `app.css` is shorter than its starting 13,794 lines (`wc -l`, both
      numbers in the pull request), and the skin token values live only in
      `themes/*.lino`.
- [ ] No module under `js/src/web/` duplicates a {{F30}} module (checked with
      `npm run check:duplication` or the target repository's equivalent).
- [ ] No Telegram-specific import remains in the framework-facing components
      (grep).
- [ ] Old localStorage values are migrated on first load (e2e).

## How to verify

```bash
npm ci && npm test
npx playwright test --project=chromium --project=webkit
wc -l js/src/web/app.css js/src/web/chat-*.js | tail -1
grep -rn "data-skin=" js/src/web/app.css | wc -l
```

Compare the screenshots with the baseline, and run `stepAxeAudit` on the chat
screen in each skin.
