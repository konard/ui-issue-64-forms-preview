## Context

{{F06}} gives an immutable `UiDocument` tree. Renderers ({{F16}}), dev mode
({{F46}}), the WYSIWYG designer ({{F48}}) and the recorder ({{F45}}) need a
**mutable** network that changes on the fly (R9), keeps the identity of every
element across edits (so a DOM node, a selection or an animation target stays
attached), notifies subscribers, groups edits into transactions and supports
undo/redo (R5).

Prior art in our repositories:

- formal-ai keeps an append-only LiNo event log (`js/memory.js`) and the
  research recommends that "every WYSIWYG edit is an appended event", which
  gives undo/redo and replay for free
  ([formal-ai.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md)).
- meta-sovereign-chat stores one `lino-objects-codec` record per line in an
  append-only log with tombstones and compaction
  (`js/src/storage/lino-store.js`,
  [meta-sovereign-chat.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/meta-sovereign-chat.md)).

## Goal

`packages/ui-store` (`@link-foundation/ui-store`) holds a UI document as a
mutable links network with stable IDs, emits change events, supports nested
transactions and undo/redo, and exports back to LiNo. Persistence is {{F09}}.

## Scope

### In scope

- `createStore({ document, text, historyLimit })` from a `UiDocument` or LiNo.
- Stable IDs: named elements keep their name (`ok`); anonymous elements get a
  generated ID that never changes while the store lives.
- Operations: `insert`, `remove`, `move`, `setProp`, `removeProp`, `rename`.
- Change events and `subscribe`; transactions; undo/redo; an ordered
  operation log that {{F09}} persists and {{F45}} replays.
- `toDocument()` and `toLino()` (via {{F06}} `format`).

### Out of scope

- IndexedDB or any storage ({{F09}}); configuration layers ({{F10}}).
- Collaboration or CRDT merging (a later issue may add it).
- Keeping comments and layout of the source text ({{F14}}).

## Dependencies

- {{F06}} (blocker): `parse`, `format`, `UiNode`. Consumed: the initial tree
  and the formatter. Until it merges, build stores from hand-written `UiNode`
  objects in tests.
- Related: {{F09}}, {{F10}}, {{F16}} (assumes events shaped
  `{ type, id, parentId, index, props }`), {{F45}}, {{F46}}, {{F48}}.

## Step-by-step plan

1. Create `packages/ui-store/package.json`
   (`"name": "@link-foundation/ui-store"`, `"type": "module"`), dependency
   `@link-foundation/ui-core` (workspace). No other runtime dependencies.
2. `src/ids.js`: `createIdGenerator(usedIds)` returns `_1`, `_2`, ... skipping
   IDs already used in the document. If {{F03}} reserves a prefix for
   generated IDs, use that instead.
3. `src/model.js`: internal maps `nodes: Map<id, {kind, positional, properties, parentId}>`
   and `children: Map<id, id[]>`. Reads return frozen snapshots; nobody gets a
   mutable reference.
4. `src/ops.js`: each operation is plain data with its inverse:
   ```js
   /** @typedef {{ op: 'insert', parentId: string, index: number, node: UiNode }
    *   | { op: 'remove', id: string }
    *   | { op: 'move', id: string, parentId: string, index: number }
    *   | { op: 'setProp', id: string, name: string, values: unknown[] }
    *   | { op: 'removeProp', id: string, name: string }
    *   | { op: 'rename', id: string, to: string }} Op */
   /** @returns {{ event: ChangeEvent, inverse: Op }} */
   export function applyOp(model, op) {}
   ```
   `setProp` replaces the **last** prop with that name (duplicate key: last
   wins, as recommended in the ecosystem research, section 5) or appends one.
5. `src/store.js`: public API
   ```js
   /** @param {{ document?: UiDocument, text?: string, historyLimit?: number }} options */
   export function createStore(options) {}
   // store.get(id), store.roots(), store.children(id), store.parentOf(id)
   // store.insert(parentId, index, node), store.remove(id), store.move(id, parentId, index)
   // store.setProp(id, name, values), store.removeProp(id, name), store.rename(id, to)
   // store.transaction(label, fn, { origin }) -> result of fn
   // store.undo(), store.redo(), store.canUndo(), store.canRedo()
   // store.subscribe(listener) -> unsubscribe
   // store.log() -> LogEntry[]; store.toDocument(); store.toLino(options)
   ```
   An operation outside `transaction` is its own transaction.
6. Events: `{ seq, tx, origin, type: 'insert'|'update'|'remove'|'move'|'rename', id, parentId, index, props, before, after }`.
   Listeners are called once per committed transaction with the array of
   events (so {{F16}} can batch). A listener that throws does not break the
   store or other listeners; the error is reported via
   `options.onListenerError`.
7. Transactions: nested calls join the outer one; if `fn` throws, apply the
   collected inverses in reverse order, emit nothing, and rethrow.
8. Undo/redo (`src/history.js`): undo applies the inverses of the last
   transaction as a **new** transaction with `origin: 'undo'` (append-only,
   like formal-ai); redo re-applies. A new user transaction clears the redo
   stack. Keep at most `historyLimit` (default 500) transactions.
9. Operation log as LiNo (`src/log-lino.js`), one entry per transaction:
   ```lino
   (tx 4 (origin devmode) (label 'Edit label')
     (setProp ok label 'Cancel'))
   (tx 5 (origin undo) (undoes 4)
     (setProp ok label 'OK'))
   ```
   `logToLino(entries)` / `logFromLino(text)` use `ui-core`, never regex.
10. README with the API, the event shape and the ID rules; changeset.

## Acceptance criteria

- [ ] `roundtrip.test.js`: `createStore({ text }).toLino()` re-parses to a tree
      deep-equal to `parse(text)` for every file in
      `docs/case-studies/issue-1/samples/` that `ui-core` accepts.
- [ ] `ids.test.js`: after 100 random (seeded) inserts, moves and removes, every
      surviving node keeps the ID it had when created; generated IDs never
      collide with named ones.
- [ ] `transactions.test.js`: a transaction of 1,000 `setProp` calls emits one
      listener call with 1,000 events; a throwing transaction leaves
      `toLino()` unchanged and emits nothing.
- [ ] `undo.test.js`: for a seeded sequence of 200 random operations, undoing
      all of them restores the original `toLino()` text exactly, and redoing all
      gives the final text exactly.
- [ ] A throwing listener does not prevent the other listeners from running.
- [ ] `log-lino.test.js`: `logFromLino(logToLino(log))` deep-equals `log`;
      replaying the log on the initial document gives the current document.
- [ ] `npm test`, `npm run lint`, `npm run format:check`,
      `npm run check:duplication` pass.
