## Context

Every screen we build needs a small set of layout primitives: a stack, a grid,
resizable split panes, tab groups, docked panels, floating windows and an app
shell that adapts to the viewport. Today each of our projects writes them again:

- meta-sovereign has `shell/app-shell.js` (bottom bar up to 640 px, navigation
  rail from 641 to 1023 px, drawer from 1024 px, Material 3) and
  `panel-resize.js` (97 lines: draggable dividers with keyboard control and
  saved widths) under `js/src/web/` of
  https://github.com/link-foundation/meta-sovereign
  ([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/meta-sovereign-chat.md)).
- deepcase opens handler and editor windows that float above the links
  network (`imports/cyto/react.tsx` `CytoReactLayout`, `opened.tsx`
  `useOpenedMethods()`), and its editor has a `VerticalSash` split
  (`editor/editor-grid.tsx`). Known bugs: a handler window is drawn above a
  modal (https://github.com/deep-foundation/deepcase-app/issues/290), a
  handler is not fully visible
  (https://github.com/deep-foundation/deepcase-app/issues/297), a window header
  cannot be dragged (https://github.com/deep-foundation/deepcase-app/issues/198)
  and the splitter position is not remembered
  (https://github.com/deep-foundation/deepcase/issues/54)
  ([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/deepcase.md)).
- The WYSIWYG designer ({{F48}}) needs Visual Studio-like docked panels:
  Toolbox, Properties, Document Outline and the canvas as the document area
  ([existing solutions](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)).
  The classic themes ({{F43}}) need the same docking to reproduce older UIs
  (R14).

## Goal

`@link-foundation/ui-components` provides the layout elements `stack`, `grid`,
`split`, `tab-group`, `dock`, `window` and `app-shell`, described in Links
Notation, rendered by `@link-foundation/ui-dom`, keyboard accessible, with one
layer manager that decides the stacking order of every floating surface and a
dock layout that is saved and restored as Links Notation.

## Scope

### In scope

- `stack` (direction, gap, align, justify, wrap) and `grid` (columns, rows,
  areas, gap) as thin wrappers over CSS flexbox and grid.
- `split` with two or more panes, draggable dividers, keyboard resizing
  (WAI-ARIA window splitter pattern), min and max sizes, collapse, and
  `remember-size` persistence through an injected storage object.
- `tab-group` used inside docks (tab strip, close, reorder by drag and by
  keyboard, overflow menu).
- `dock`: regions left, right, top, bottom and centre; panels can be moved
  between regions, stacked as tabs, floated, closed and restored.
- `window`: a floating, movable, resizable surface with a draggable header,
  kept inside the viewport.
- `app-shell`: bottom bar, rail or drawer selected by breakpoints.
- The layer manager (`createLayerManager`) used by windows, docks and later by
  overlays ({{F27}}).

### Out of scope

- Dialogs, popovers, menus and toasts (they are {{F27}}; they only register
  with the layer manager from this issue).
- Lists, trees and tables ({{F29}}).
- Theme visuals of classic UIs ({{F43}}).

## Dependencies

- **Blocked by {{F16}}** (ui-dom): we consume the element registry, the
  custom-element base class and incremental updates to render the layout
  elements. Before {{F16}} lands, the pure model files (`layer-manager.js`,
  `dock-model.js`, `split-model.js`) can be written and tested without a DOM.
- **Related:** {{F25}} (behaviour state machines; move the keyboard logic there
  when it exists), {{F27}} (overlays register with the layer manager), {{F10}}
  (the configuration layers that will store remembered sizes), {{F43}},
  {{F48}}, {{F30}} (chat uses `split` and `app-shell`), {{F60}}.

## Step-by-step plan

1. Create `packages/ui-components/src/layout/` and export it from
   `packages/ui-components/src/index.js`.
2. Write `layer-manager.js`:
   ```js
   /**
    * @param {{ base?: number, step?: number }} [options]
    * @returns {{
    *   register(id: string, layer: 'base'|'dock'|'window'|'popover'|'modal'|'toast'): void,
    *   raise(id: string): void,
    *   zIndexOf(id: string): number,
    *   unregister(id: string): void,
    *   subscribe(listener: () => void): () => void
    * }}
    */
   export function createLayerManager(options) {}
   ```
   Layers have a fixed order, so a raised `window` can never be above a
   `modal`. Test `layer-manager.test.js` reproduces deepcase-app issue 290.
3. Write `split-model.js`: `resizeSplit(sizes, index, delta, limits)` returns
   new sizes that respect min, max and the total; `collapsePane`,
   `restorePane`. Test `split-model.test.js`.
4. Write `dock-model.js`, a pure model of the dock tree with
   `movePanel(layout, panelId, target)`, `floatPanel`, `closePanel`,
   `restorePanel`, `dockLayoutFromLinks(links)` and
   `dockLayoutToLino(layout)`. Use the `links-notation` package for parsing;
   never a regular expression. Test `dock-model.test.js` with a round trip.
5. Register the custom elements with {{F16}}: `stack.js`, `grid.js`,
   `split.js`, `tab-group.js`, `dock.js`, `window.js`, `app-shell.js`.
6. Keyboard: split dividers use `role="separator"` with `aria-valuenow`,
   arrow keys move by 1 %, Home and End collapse and expand; tab strips follow
   the APG tabs pattern; `Ctrl+F6`/`Ctrl+Shift+F6` cycle dock panels; a window
   can be moved with Alt+arrow keys.
7. Windows: header is the drag handle (pointer events with
   `setPointerCapture`), clamp the window to the viewport on drag and on
   `resize`, focus returns to the opener when it closes.
8. `app-shell`: breakpoints are data, default `640px` and `1024px` as in
   meta-sovereign; content uses `bottom-bar`, `rail` and `drawer` slots.
9. Add the gallery page `packages/ui-components/examples/layout.html` with the
   designer-like layout below, and Playwright tests.

Input example (working names; the dialect is fixed in {{F03}}):

```lino
(designer-shell: dock
  (persist 'designer.layout')
  (left: region (size 16rem) (panels toolbox outline))
  (right: region (size 20rem) (panels properties))
  (center: region (panels canvas))
  (bottom: region (size 12rem) (collapsed true) (panels problems)))
(chat-screen: split
  (direction row)
  (resizable true)
  (remember-size 'chat.columns')
  (children chat-list conversation))
```

`dockLayoutToLino` must give back the same structure after a panel moves, for
example `(right: region (size 20rem) (panels properties outline))`.

## Acceptance criteria

- [ ] `createLayerManager` keeps every `modal` above every `window`, even after
      `raise()` of the window (test `layer-manager.test.js`).
- [ ] `resizeSplit` never returns a size below `min` or above `max`, and the
      sum of sizes stays constant (test `split-model.test.js`).
- [ ] A dock layout parsed from LiNo, changed by `movePanel`, and written with
      `dockLayoutToLino` parses back to an equal model (test
      `dock-model.test.js`).
- [ ] A split remembers its sizes through the injected storage after reload
      (Playwright).
- [ ] Every divider, tab strip and window can be operated with the keyboard
      only (Playwright test without mouse events).
- [ ] A floating window cannot be dragged outside the viewport (Playwright).
- [ ] `app-shell` shows a bottom bar at 600 px, a rail at 800 px and a drawer
      at 1280 px width (three screenshots).
- [ ] axe reports no violations on `examples/layout.html`.

after moving `outline` to the right region; then the app shell at the three
widths.

## Prior art and libraries

- meta-sovereign `shell/app-shell.js`, `panel-resize.js` (Unlicense, can be
  ported).
- deepcase floating windows and their bugs (learn only).
- WAI-ARIA APG "Window Splitter" and "Tabs" patterns.
- dockview and golden-layout are well-known docking libraries; they are not in
  our research, so check their licence and current version before even
  learning from them. Prefer our own small model, because the layout must be
  stored as LiNo.
- Floating UI (MIT) can position windows relative to anchors if needed.
