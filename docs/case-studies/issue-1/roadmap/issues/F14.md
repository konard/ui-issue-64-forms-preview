## Context

The WYSIWYG designer ({{F48}}) and dev mode ({{F46}}) edit LiNo documents that
people and AI agents also edit by hand (R5, R7). If every edit goes through
`parse` → change → `format`, all comments, blank lines, indentation choices and
the choice between one-line, multi-line and indented forms are lost, and the
diff that an agent has to review (R12) becomes the whole file.

The ecosystem research names this "gap 4: comments and layout are lost on round
trip" and lists three options: (a) a concrete syntax tree (CST) upstream,
(b) comments as links such as `(note '...')`, (c) patch-in-place using source
positions
([links-notation-ecosystem.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md),
section 5). Facts checked with `links-notation` 0.27.1 during planning:

- Parsed `Link` objects have only `id` and `values` — **no source positions**.
- `ParseError` has `offset`, `line`, `column` and `location { start, end }`.
- `stripComments(text)` blanks comments but keeps every offset, so positions
  in the stripped text equal positions in the original.
- `StreamParser` reports positions only coarsely (a link is emitted when the
  next record starts), so it cannot give exact spans.
- A bare `#` starts a comment; `//` does not (it is a normal reference).
- The formatter does not reflow nested links to fit `maxLineLength`.

## Goal

A JavaScript module that applies structural edits (set a prop, change text,
insert/remove/move a child, rename an id) to the **original text** with the
smallest possible text change, keeping comments and layout everywhere else,
plus an upstream proposal for real source positions.

## Scope

### In scope

- `indexSource(text)` → span tree that maps every element and prop of the
  {{F06}} tree to `{ start, end }` offsets, for all three document forms.
- Edit functions that return the new text and the list of text edits.
- `applyOpsToSource(text, ops)` for the {{F08}} operation shape.
- Self-check after every edit: the new text must parse to the expected tree;
  otherwise return an error and leave the text unchanged.
- Convention (b): `(note '...')` props are kept as data by `ui-core` and the
  store, so comments that must survive any tool can be written as links.
- Upstream issue draft (option a).

### Out of scope

- Writing our own full LiNo parser. The scanner below only finds delimiters;
  all structure comes from the official `Parser` and is cross-checked.
- Merging concurrent edits; pretty-printing whole files (that is `format`).

## Dependencies

- {{F06}} (blocker): `parse`, the tree projection and `UiNode`. Consumed: the
  expected tree that every span is checked against. Before it merges, check
  spans against raw `Link` objects with `Link.equals`.
- Related: {{F08}} (operation shape `{ op: 'setProp', id, name, values }` etc.),
  {{F10}} (patches applied to site files), {{F46}}, {{F47}}, {{F48}}.

## Step-by-step plan

1. Location: `packages/ui-core/src/source/`, exported as the subpath
   `@link-foundation/ui-core/source` (add it to `package.json` `exports`).
2. `scan.js`: `scanDelimiters(stripped)` walks the output of
   `stripComments(text)` character by character and records parentheses,
   quoted runs, line starts and indentation. Follow the quoting rules of the
   `links-notation` grammar (read its grammar file in
   https://github.com/link-foundation/links-notation; single, double and
   backtick quotes and the repeated-quote forms). No regular expressions.
3. `index.js`: `indexSource(text) → { root: SpanNode, form: 'inline'|'multiline'|'indented' }`
   where
   ```js
   /** @typedef {{ start: number, end: number, kind: 'element'|'prop'|'value',
    *   id?: string, name?: string, children: SpanNode[], indent?: string }} SpanNode */
   ```
   Validate **every** span: `new Parser().parse(text.slice(start, end))` must
   `.equals()` the link from the full parse at the same path (for indented
   blocks, compare `parseGroups` results). Any mismatch throws
   `SourceIndexError` naming the path — never guess.
4. `edit.js` (all functions return `{ ok: true, text, edits: Array<{ start, end, insert }> } | { ok: false, error }`):
   ```js
   export function setProp(text, id, name, values) {} // replaces the value span only
   export function setPositional(text, id, values) {} // greeting: text 'Hello, agents'
   export function insertChild(text, parentId, index, childLino) {}
   export function removeNode(text, id) {} // also removes its now-empty line
   export function moveNode(text, id, parentId, index) {}
   export function renameId(text, from, to) {} // definition only; references are reported
   ```
   Rules: reuse the indentation of the nearest sibling; in the one-line form
   insert inline with one space; quote new values with `escapeReference`;
   a comment directly above a removed or moved node moves with it.
5. `apply.js`: `applyOpsToSource(text, ops)` applies {{F08}} ops in order and
   checks after each op that `parse(newText)` deep-equals the tree obtained by
   applying the same op to `parse(oldText)`.
6. `note` convention: declare `note` as a property allowed on every kind in
   `docs/spec/vocabulary.lino` ({{F03}}; otherwise it is reported as
   `unknown-sublink`), document in the README that `(note 'Why this is red')`
   is a property like any other, and add a test that it survives
   `parse` → `format` and store round trips.
7. Upstream proposal: first search existing issues
   (`gh issue list -R link-foundation/links-notation --search "position" --state all`).
   If none fits, put a draft in the pull request description and give the URL
   to file it:
   https://github.com/link-foundation/links-notation/issues/new?title=Optional+source+positions+and+comments+in+parsed+links+(CST)
   Draft content: an option `new Parser({ positions: true })` that adds
   `location { start, end }` (as `ParseError` already has) to every `Link`,
   and an option to return comments and whitespace as trivia so tools can
   rewrite text losslessly. Do not create the issue yourself.
8. Mark this module as the stopgap in the README; when upstream positions
   exist, `index.js` uses them and `scan.js` is deleted.

Example: `setProp(text, 'ok', 'label', ['Cancel'])` on

```lino
# primary action
(ok: button
  (label 'OK')   # shown on the button
  (variant filled))
```

changes exactly the 4 characters `'OK'` to `'Cancel'`; both comments and the
layout stay.

## Acceptance criteria

- [ ] `source-index.test.js`: every sample in `docs/case-studies/issue-1/samples/`
      and every fixture indexes without error, and every span passes the
      reparse check.
- [ ] `source-edit.test.js`: the example above produces exactly one edit
      `{ start, end, insert: "'Cancel'" }`; text before `start` and after `end`
      is byte-identical to the input.
- [ ] Insert, remove, move and rename each have tests in all three forms; all
      `#` comments in the fixture are still present after each edit (counted).
- [ ] `source-fuzz.test.js`: 300 seeded random ops on the fixtures; each result
      either passes the tree check or returns `{ ok: false }` with the input
      unchanged; zero silent mismatches.
- [ ] `grep -rn "RegExp\|\.match(\|/.*/[gimsuy]*\.test(" packages/ui-core/src/source`
      finds nothing.
- [ ] The pull request contains the upstream draft and the URL from step 7.
- [ ] `npm test`, `npm run lint`, `npm run format:check`,
      `npm run check:duplication` pass.

## Prior art and libraries

- `recast` (MIT) and `jsonc-parser` `modify` (MIT): edit source while keeping
  formatting — the same idea for JavaScript and JSON with comments.
- Rust `rowan` / Roslyn red-green trees as the CST model for the upstream
  proposal.
- `links-notation` 0.27.1 `stripComments`, `escapeReference`, `ParseError.location`.
