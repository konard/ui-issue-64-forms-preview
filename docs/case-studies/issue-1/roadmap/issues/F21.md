## Context

The SwiftUI renderer ({{F22}}) must read the same LiNo documents as the JavaScript core (R21: Swift support; R8: prefer links theory and LiNo). ARCHITECTURE.md says the Swift package reads LiNo "with a Swift parser (an upstream `links-notation` port, or a port created by the roadmap if none exists)" ([`docs/ARCHITECTURE.md`](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md), "Platforms").

State of upstream (https://github.com/link-foundation/links-notation, checked for this roadmap; re-check before starting):

- There are implementations for JS, Rust, C#, Python, Go, C++, Java and PHP. There is **no Swift** port, and no upstream issue asks for one.
- `parity/README.md` defines the cross-language contract:
  - `parity/text-fixtures.json` is the golden corpus. It has 14 cases (core text, named and nested links, indentation, nested contexts, quoted and empty references, Unicode, comments, quote runs, multiline references, reference literals). Each case is `{id, feature, input, expected: [{id, values}], format}`, and `id: null` marks an anonymous link.
  - `parity/language-features.json` lists every binding with evidence per feature.
  - `node scripts/ci/check-parity.mjs` rejects missing languages or evidence. Differences must be explicit exceptions in `parity/README.md`.
- Upstream policy: JavaScript defines behaviour first, and all libraries are hand-written. The JS grammar is `js/src/grammar.pegjs`, used by `js/src/Parser.js`.

See section 2 of [links-notation-ecosystem.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md) for the JS API (`Parser`, `Link`, `formatLinks`, `maxDepth` default 64).

## Goal

Deliver a hand-written Swift package `LinksNotation` (SwiftPM) that parses and formats LiNo. It must pass the upstream parity corpus and the parser-level vectors derived from the {{F03}} conformance fixtures, on macOS and Linux.

## Scope

### In scope

- `Link`, `Parser`, `ParseError`, `formatLinks` and `ParserOptions` (`maxDepth`, `maxInputSize`).
- Parity tests over `parity/text-fixtures.json`: parse, format and round trip.
- The parser vectors of the F03 fixtures, generated from the JS reference.
- A CI job on Linux and macOS.
- The decision record: contribute upstream (preferred) or vendor here temporarily.

### Out of scope

- The UI element tree projection and the SwiftUI renderer ({{F22}}).
- Streaming, the binary protocol, `LinksGroup` and `parseIndentedDocument`. List them as explicit exceptions in the upstream manifest, as Python, PHP and Go already do for `LinksGroup`.

## Dependencies

- **{{F03}}** (blocker) provides `docs/spec/fixtures/**/*.lino` and the decisions on limits (`maxDepth`, `maxInputSize`). You can start with the upstream corpus only, and add the F03 vectors when F03 merges.

Related:

- {{F22}} consumes this package and decides the `ui-swift` folder layout.
- {{F23}} is the Kotlin twin; share the vector generator with it.
- {{F06}} is the JS reference projection.

Upstream: https://github.com/link-foundation/links-notation/issues/192 tracks publishing of Java and Go and shows the release expectations for new bindings.

## Step-by-step plan

1. **Decide where the code lives.**
   - Search https://github.com/link-foundation/links-notation/issues for "swift". If no issue exists, open one titled "Add Swift implementation". It should propose a `swift/` folder, a `swift` entry in `parity/language-features.json`, and SwiftPM distribution, and link this issue.
   - Preferred option: open the upstream PR.
   - If the maintainer does not accept a Swift folder upstream, or the PR stalls, vendor the code in this repository under `native/swift/LinksNotation/` with the same layout, so that it can move upstream later. Coordinate the folder with {{F22}}.
   - Record the decision and the links in `docs/native-parsers.md`.
2. **Mind the SwiftPM layout.** A package consumed by repository URL needs `Package.swift` at the repository root. Upstream would need a root `Package.swift` whose targets use `path: "swift/Sources/LinksNotation"`, or a separate repository. Ask the maintainer which one; check the current SwiftPM docs.
3. Create the package with `swift-tools-version` 5.9 or newer (check the current stable toolchain). Platforms: macOS 13+, iOS 16+, Linux. No dependencies.
4. Implement the public API:

   ```swift
   public struct Link: Equatable, Sendable {
     public var id: String?          // nil = anonymous link
     public var values: [Link]
     public func format() -> String  // same text as JS Link.format()
   }
   public struct ParserOptions: Sendable { public var maxDepth = 64; public var maxInputSize: Int? = nil }
   public enum ParseError: Error, Equatable {
     case syntax(line: Int, column: Int, message: String)
     case depthExceeded(Int), inputTooLarge(Int)
   }
   public struct Parser { public init(options: ParserOptions = .init())
     public func parse(_ text: String) throws -> [Link] }
   public func formatLinks(_ links: [Link]) -> String
   ```

5. Port the grammar by hand from `js/src/grammar.pegjs`, as a recursive-descent parser over `String.UnicodeScalarView`, so that Unicode fidelity holds. It must cover:
   - `id:` definitions, parentheses, and indentation-based nesting;
   - quote runs (`'`, `"`, `` ` `` and their repeated forms);
   - multiline references and empty references;
   - comments (`#` after whitespace);
   - reference literals.

   Keep the JS shapes exactly, including the multi-line path expansion described in ARCHITECTURE.md, "Links Notation parse shapes".

6. Port the formatter (`Link.format()`, `formatLinks`), including the minimal quoting rules (`references.js`, `quotes.js` in upstream JS).
7. Write `Tests/LinksNotationTests/ParityTests.swift`. It locates `parity/text-fixtures.json` relative to `#filePath`, and for every case asserts:
   - `parse(input)` equals `expected`;
   - `formatLinks(parse(input)) == format`;
   - `parse(format)` equals `expected`.
8. Write `scripts/generate-parser-vectors.mjs` in this repository. It runs JS `links-notation` (the version pinned in `package.json`) over every `docs/spec/fixtures/**/*.lino` and writes `docs/spec/parser-vectors.json` in the same `{id, input, expected, format}` shape. Fixtures named `syntax-*` get `"error": true`. Add a test that fails when the file is stale. Whichever of this issue and {{F23}} lands first creates this generator; the other reuses it.
9. Write `Tests/LinksNotationTests/SpecVectorsTests.swift`, which runs the same assertions over `parser-vectors.json`. `error: true` cases must throw `ParseError.syntax`.
10. Write `LimitsTests.swift`. It checks that nesting 65 levels deep throws `.depthExceeded(64)`, and that an input over `maxInputSize` throws `.inputTooLarge`.
11. Add CI:
    - upstream, follow their workflow conventions;
    - if vendored here, add `.github/workflows/swift.yml` with `swift test` on `ubuntu-latest` (an official `swift` container image; check the current tag) and on `macos-latest`. Trigger on changes to the Swift folder and to `docs/spec/**`.
12. If upstream: add `swift` to `parity/language-features.json` with evidence paths, add exceptions to `parity/README.md`, and run `node scripts/ci/check-parity.mjs`.

## Files to create or change

- Upstream (preferred): `Package.swift`, `swift/Sources/LinksNotation/{Link,Parser,Formatter,ParseError}.swift`, `swift/Tests/LinksNotationTests/*.swift`, `parity/language-features.json`, `parity/README.md`, a CI workflow
- Fallback: the same sources under `native/swift/LinksNotation/`, plus `.github/workflows/swift.yml`

## Acceptance criteria

- [ ] An upstream issue (or PR) for the Swift port exists and is linked from `docs/native-parsers.md`, with the decision (upstream or vendored) recorded.
- [ ] `swift test` passes on Linux and macOS in CI.
- [ ] `ParityTests` covers all cases of `parity/text-fixtures.json` (14 at the time of writing) for parse, format and round trip.
- [ ] `SpecVectorsTests` passes every entry of `docs/spec/parser-vectors.json`, and `node --test tests/parser-vectors.test.js` confirms that the file is fresh.
- [ ] `LimitsTests` proves the `maxDepth` and `maxInputSize` errors.
- [ ] If upstream: `node scripts/ci/check-parity.mjs` passes with the `swift` entry.
