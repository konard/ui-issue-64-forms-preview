## Context

R15 asks us to follow the Apple guidelines as well as Google's and
Microsoft's. Apple handles this differently from the other two: the Human
Interface Guidelines (HIG) are published as **guidance only**, and Apple's
fonts and symbols carry restrictive licences. The research files the HIG
under LEARN. It says never to bundle SF Pro or SF Symbols, and on Apple
platforms to use system fonts and symbols at runtime
([existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)).

This issue therefore builds a **HIG-guided** theme with our own values. It
does not copy Apple assets. Its job is to make web and cross-platform UIs
feel at home on iOS and macOS, and to give the Swift renderer ({{F21}},
{{F22}}) a theme whose semantics match SwiftUI's. Material 3 ({{F40}}) and
Fluent 2 ({{F41}}) are the sibling themes.

## Goal

Ship `hig`, a theme package with two platform variants, `hig-ios` and
`hig-macos`, and light, dark and increased-contrast modes. It must:

- follow the HIG section of the {{F04}} digest, covering semantic colours,
  text styles that scale like Dynamic Type, hit targets, materials and
  motion;
- use only the system font stack and no Apple-owned assets;
- include a mapping table from SwiftUI views to our kinds.

## Scope

### In scope

- `packages/ui-themes/themes/hig/` with:
  - semantic colour roles: label, secondary label, background, grouped
    background, separator, tint, and the system accent colours;
  - text styles: large title, title 1–3, headline, body, callout,
    subheadline, footnote and caption 1–2;
  - corner radii, spacing, minimum hit target, and motion durations and
    springs.
- Variants `hig-ios` and `hig-macos`, each declared with `(extends hig)`.
  They differ in base text size, control height and density, with values
  taken from the {{F04}} digest.
- Modes `dark`, `high-contrast` (the analogue of "Increase Contrast") and
  `motion reduced`, which turns movement into cross-fades as the HIG
  recommends.
- Text that scales with the user's preferred text size. On the web, text
  sizes are `rem`-based from the root font size.
- Translucent materials as an optional style,
  `(material regular | thin | thick)`. It uses `backdrop-filter` and falls
  back to an opaque surface under `prefers-reduced-transparency: reduce` and
  under the user's transparency comfort key from {{F39}}.
- Style rules and templates for the {{F26}} controls: button (bordered,
  borderless, prominent), toggle (switch), text field, slider, stepper,
  segmented control and picker.
- `swiftui-mapping.lino`, which maps SwiftUI view names and modifiers to our
  kinds and props.

### Out of scope

- SF Pro, SF Mono, New York, SF Symbols, or any Apple font or image file.
  Nothing is bundled or downloaded, and no URL points to Apple-hosted fonts.
- Native SwiftUI rendering and native symbol lookup, which belong to {{F21}}
  and {{F22}}.
- Copying HIG text or images into the repository. Link to the HIG instead.
- Any claim of Apple endorsement. The README states that the theme is
  "guided by" the HIG and not affiliated with Apple.

## Dependencies

- {{F39}} (blocker). Supplies the theme format, `extends`, the modes, the
  comfort keys (transparency, motion), contrast pairs and templates.
- {{F04}} (blocker). Supplies the HIG section of the digest: colour roles,
  text-style sizes, hit-target size, motion guidance and accessibility
  settings, each with a source link. To start before {{F04}} merges, read
  https://developer.apple.com/design/human-interface-guidelines and record
  the URLs. Choose our own colour values that meet the stated contrast.
- Related: {{F21}}, {{F22}} (native consumers of the SwiftUI mapping), {{F26}},
  {{F36}} (icons; this theme uses our own icon set), {{F40}}, {{F41}}, {{F57}}.

## Step-by-step plan

1. Write `themes/hig/type.lino`. The font stack is:

   ```lino
   (hig-type: theme
     (token font.family.text 'system-ui, -apple-system, BlinkMacSystemFont, sans-serif')
     (token font.family.mono 'ui-monospace, monospace')
     (token text.body.size 1rem)
     (token text.headline.weight 600))
   ```

   - The stack is a quoted string, because `,` and `-` must stay intact.
   - Express each text style relative to `body`, so that changing the root
     size scales all of them, as Dynamic Type does.
   - Take the ratios from the {{F04}} digest.

2. Write `themes/hig/colors.lino`.
   - Name the roles with our semantic names (`color.surface`,
     `color.on-surface`, `color.on-surface-variant`, `color.separator`,
     `color.primary` for the tint) and record the HIG role name, for example
     `(hig label)`.
   - Pick values that are our own and pass the {{F39}} contrast pairs in
     light, dark and high contrast.
   - `system` is the default scheme, because the HIG follows the device
     appearance.
3. Write `themes/hig/{shape,spacing,motion,materials}.lino`.
   - The minimum hit target is a token, `size.target.min` (check the value
     against the digest), and the {{F26}} templates enforce it with
     `min-width` and `min-height`.
   - Motion uses springs, for example
     `(token motion.spring.default (spring (response 0.35s) (damping 0.85)))`.
     {{F44}} consumes that format. Until {{F44}} lands, compile springs to a
     CSS `linear()` easing approximation.
4. Write `themes/hig-ios/theme.lino` and `themes/hig-macos/theme.lino` with
   `(extends hig)`. Each overrides only density tokens: base text size,
   control height and list row height.
5. Write `styles.lino` and `templates.lino` for the in-scope controls.
   - The segmented control and stepper templates use {{F26}} parts. If
     {{F26}} has no segmented control, implement it as a `radio-group`
     template with `(appearance segmented)`.
   - Under `(motion reduced)`, the switch thumb fades instead of sliding.
6. Implement `(material ...)` in `styles.lino`, using `backdrop-filter`
   with a fallback rule. Add a test that sets the transparency comfort key to
   `off` and asserts an opaque background.
7. Write `themes/hig/swiftui-mapping.lino` in the {{F40}} row format, using
   the shared loader in `src/mapping.js`:
   ```lino
   (map Toggle (kind switch) (status mapped))
   (map VStack (kind stack) (prop axis vertical (direction column)) (status mapped))
   (map NavigationStack (kind navigation) (status none))
   ```
   Cover at least Button, Toggle, TextField, SecureField, Slider, Stepper,
   Picker, List, Form, Section, VStack, HStack, ZStack, ScrollView,
   TabView, NavigationStack, Sheet, Alert, Menu, ProgressView, Label and
   Image.
8. In `examples/themes/hig.html`, build a gallery showing iOS and macOS
   variants in light, dark and high contrast. Add Playwright screenshots,
   `docs/themes/hig.md` (with the non-affiliation note), tests and a
   changeset.

## Acceptance criteria

- [ ] `hig-theme.test.js`: `hig`, `hig-ios` and `hig-macos` load with no
      error diagnostics, and every `pair` passes in light, dark and high
      contrast.
- [ ] `hig-ios` differs from `hig` only in density tokens, which the test
      checks against an allow-list.
- [ ] No file in the repository contains SF font or SF Symbols binaries or
      URLs: `git ls-files | grep -iE '\.(otf|ttf|woff2?)$'` adds nothing for
      this theme, and `grep -riE 'sf-pro|sfsymbols|SF Symbols' packages/ui-themes/themes`
      is empty.
- [ ] With the root font size set to 200 percent, every text style doubles
      (Playwright measures `body` and `caption` text).
- [ ] Every interactive control in the gallery measures at least the
      `size.target.min` value in both dimensions (Playwright bounding boxes).
- [ ] `hig-materials.test.js`: under `prefers-reduced-transparency: reduce`
      or the transparency comfort key set to `off`, the compiled style has no
      `backdrop-filter` and uses an opaque background.
- [ ] `swiftui-mapping.test.js`: every listed SwiftUI view has a row, and
      `docs/themes/hig.md` is regenerated and up to date.
- [ ] Gallery screenshots in light, dark and high contrast for both variants
      are attached to the pull request, and axe reports no violations.
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication` and
      `npm test` pass.
