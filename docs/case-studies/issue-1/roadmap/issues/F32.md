## Context

R13 asks for diagrams as part of the framework. formal-ai already renders
Mermaid: `js/app/markdown-render.jsx` uses Mermaid with
`securityLevel: 'strict'`, Mermaid 12.2.0 is loaded only when needed
(`mermaid.bundle.js`), and `debugger-view.jsx` shows a Mermaid recipe diagram
beside source panes (https://github.com/link-assistant/formal-ai/issues/667).
An open bug says rich Mermaid display fails on GitHub
(https://github.com/link-assistant/formal-ai/issues/1190)
([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md)).

The library survey
([existing solutions](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md))
says: Mermaid (MIT) for interoperability; Dagre (MIT) as the default layered
layout; ELK.js (EPL-2.0) and Graphviz via `@hpcc-js/wasm-graphviz` (EPL) only
as optional plugins; xyflow (MIT) and maxGraph (Apache-2.0) to learn from;
GoJS and yFiles are avoided.

## Goal

A diagram is described in Links Notation (nodes, edges, groups, kind), laid out
by Dagre by default, rendered as accessible SVG by our own code, and can be
exported to Mermaid text or rendered by a lazily loaded Mermaid adapter. A
Mermaid source can also be shown directly.

## Scope

### In scope

- The diagram dialect: `diagram` with `kind` (`flowchart`, `sequence`,
  `state`, `class`), `direction`, `node`, `edge`, `group`.
- `diagram-model.js` (pure) and `layout-dagre.js`.
- `svg-diagram.js` (our renderer for flowchart and state kinds).
- `mermaid-export.js`: diagram model to Mermaid text.
- `mermaid-view` element: lazy `import('mermaid')` with
  `securityLevel: 'strict'`, and a text fallback when loading fails.
- A layout plugin interface so ELK or Graphviz can be added by the app.

### Out of scope

- Mermaid text to LiNo import (in `@link-foundation/ui-convert`, see {{F53}}).
- Links network visualisation ({{F33}}, {{F34}}).
- Shipping ELK or Graphviz in our packages (EPL, plugins only).

## Dependencies

- **Blocked by {{F16}}**: the custom elements base used by `diagram` and
  `mermaid-view`. The pure model, layout and export can be written first.
- **Related:** {{F11}} (colours from tokens), {{F31}} (shares the SVG helper
  style), {{F38}} (an editor next to a live diagram), {{F53}} (import),
  {{F61}} (formal-ai replaces its own Mermaid loader).

## Step-by-step plan

1. Create `packages/ui-components/src/diagrams/` and export it.
2. Write `diagram-model.js`:
   ```js
   /** @returns {DiagramModel} { kind, direction, nodes, edges, groups } */
   export function diagramFromLinks(links) {}
   /** @returns {string} LiNo text */
   export function diagramToLino(model) {}
   ```
   Parse with the `links-notation` package; an edge with an unknown node id is
   an error with the link position.
3. Write `layout-dagre.js`:
   `layoutDiagram(model, { nodeSize, rankSep, nodeSep }) → { nodes: [{id, x, y, width, height}], edges: [{id, points}] }`.
   Bundle and pin Dagre (check the current maintained package name and
   version).
4. Define the plugin interface in `layout-plugins.js`:
   `registerLayout(name, (model, options) => Promise<Layout>)`. Document an
   example that wraps ELK.js in the app, not in this repository.
5. Write `svg-diagram.js` (`renderDiagramSvg(model, layout, tokens) → string`,
   deterministic) and the `diagram` element: `role="img"`, `aria-label`, and a
   visually hidden list of nodes and edges ("A leads to B") for screen readers.
6. Write `mermaid-export.js`: `toMermaid(model) → string` for `flowchart` and
   `state`, escaping labels.
7. Write `mermaid-view.js`: the first render calls `import('mermaid')`, then
   `mermaid.initialize({ startOnLoad: false, securityLevel: 'strict' })`; if
   the import or render fails, show the source text in a `pre` with an error
   message (this covers the formal-ai issue 1190 kind of failure).
8. Add `(renderer mermaid)` to a `diagram` to render via Mermaid instead of our
   renderer.
9. Gallery page `packages/ui-components/examples/diagrams.html`.

Input example and expected Mermaid output:

```lino
(login-flow: diagram
  (kind flowchart)
  (direction down)
  (start: node (label 'Start'))
  (check: node (label 'Signed in?') (shape diamond))
  (home: node (label 'Home'))
  (edge (from start) (to check))
  (edge (from check) (to home) (label 'yes')))
```

```text
flowchart TD
  start["Start"]
  check{"Signed in?"}
  home["Home"]
  start --> check
  check -->|yes| home
```

## Acceptance criteria

- [ ] `diagramFromLinks(parse(diagramToLino(m)))` equals `m` for every
      fixture.
- [ ] `toMermaid` for the login flow above returns exactly the text above
      (test).
- [ ] `layoutDiagram` gives the same coordinates on two runs and no two nodes
      overlap (test).
- [ ] `mermaid` is not imported until a `mermaid-view` or `(renderer mermaid)`
      is on the page (Playwright watches network requests).
- [ ] When Mermaid fails to load, the source text and an error are shown
      (Playwright with the request blocked).
- [ ] No EPL package is listed in `dependencies` of any package (test that
      reads `package.json` files).
- [ ] axe reports no violations on `examples/diagrams.html`.

## How to verify

Expected screenshots: the login flow drawn by our renderer, the same flow drawn
by Mermaid, and the fallback text when Mermaid is blocked.

## Prior art and libraries

- Mermaid (MIT): interoperability and optional renderer; check the current
  version (formal-ai uses 12.2.0).
- Dagre (MIT): default layered layout.
- ELK.js (EPL-2.0) and `@hpcc-js/wasm-graphviz` (EPL): optional plugins only.
- xyflow (MIT), maxGraph (Apache-2.0), Penrose (MIT): learn.
- GoJS, yFiles: avoid.
