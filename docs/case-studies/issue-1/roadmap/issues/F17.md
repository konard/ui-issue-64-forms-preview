## Context

Issue #1 asks that "any other UI/UX framework is just a Links Notation
document" (R6), that every website can be modified on the fly (R9) and that
existing projects are easy to migrate (R23). Two later features need to turn
existing HTML into the UI dialect:

- dev mode on pages that were not built with the framework ({{F50}}) must
  import the live DOM, keep a map from link IDs to DOM nodes and show it in the
  inspector;
- migration of our projects ({{F57}}–{{F65}}) and the JSX/Vue importers
  ({{F51}}) start from HTML.

`meta-language` (npm 0.46.0) already has a native HTML import (tag stack, raw
`script`/`style` text) and a CSS import with a lossless CST (trivia and spans)
([links-notation-ecosystem.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)
section 3). The ARCHITECTURE puts importers in `@link-foundation/ui-convert`.

## Goal

Create `packages/ui-convert/` with an HTML/DOM importer that turns an HTML
string or a live DOM subtree into a UI dialect LiNo document, plus a map from
generated link IDs back to source nodes and source spans.

## Scope

### In scope

- `importHtml(text, options)` for HTML strings (Node and browser), using the
  `meta-language` HTML import for source spans.
- `importDom(root, options)` for a live DOM subtree (browser and jsdom), which
  returns `nodeMap: Map<string, Node>` for dev mode.
- One shared intermediate form `{ tag, attrs, children, text, span }` and one
  mapping step from it to dialect elements.
- A mapping table from semantic HTML to dialect kinds, with a lossless
  fallback element for everything else.
- Inline `style` attributes to `(style ...)` links; classes and other
  attributes preserved.
- Deterministic link IDs.
- Security: scripts and `on*` attributes are dropped with a diagnostic.

### Out of scope

- Importing stylesheets and `<style>` rules into `ui-style` rules (follow-up
  through the `meta-language` CSS import; keep `<style>` text as a raw link).
- Computed styles, JSX, MUI and Vue SFC ({{F51}}).
- The dev mode UI for foreign pages ({{F50}}).
- Exporting LiNo back to HTML (that is `renderToHTML` in {{F16}}).

## Dependencies

- {{F06}} (blocker): the element tree types and `parse`, used to check that
  every import result is a valid dialect document (round trip:
  import, format, parse, compare trees).
- Related: {{F03}} (dialect vocabulary: use its kind and prop names in the
  mapping table), {{F07}} (typed values: units and colours in inline styles),
  {{F16}} (reverse direction), {{F50}}, {{F51}}, {{F57}}.

## Step-by-step plan

1. Create `packages/ui-convert/` (`@link-foundation/ui-convert`, ES module)
   with `src/html/` and `tests/html/`. If {{F51}} or another issue already
   created the package, add the `html` folder to it. Dependencies:
   `links-notation`, `meta-language` (check the current version and licence
   in its `package.json`; it is a link-foundation package), and
   `@link-foundation/ui-core`. Dev dependency: `jsdom` (MIT).
2. Read the `meta-language` README and exports and find its HTML import entry
   point and the node shape it returns (tags, attributes, text, spans). Write
   `src/html/from-meta-language.js` that converts that result into the
   intermediate form:
   ```js
   /** @typedef {{ tag: string, attrs: [string, string][], children: HtmlNode[],
    *   text?: string, span?: { start: number, end: number } }} HtmlNode */
   ```
   If the HTML import is not usable from the npm package, stop and open an
   issue in https://github.com/link-foundation/meta-language instead of writing
   a regex HTML parser.
3. `src/html/from-dom.js`: walk a DOM `Node` into the same intermediate form,
   skipping comment nodes unless `options.comments` is true and recording
   `Node` references for `nodeMap`.
4. `src/html/mapping.js`: a table, kept as data, for example:

   | HTML                                  | Dialect kind                     |
   | ------------------------------------- | -------------------------------- |
   | `button`, `input[type=button]`        | `button` (`label` from text)     |
   | `a[href]`                             | `link` (`href` quoted)           |
   | `p`, `span`, `h1`–`h6`, `label`       | `text` (`level` for headings)    |
   | `img`                                 | `image` (`src`, `alt`)           |
   | `input[type=checkbox]`                | `checkbox`                       |
   | `input[type=text]`, `textarea`        | `text-field`, `text-area`        |
   | `ul`, `ol`                            | `list`                           |
   | `div`, `section`, `main`, `nav`, etc. | `html` fallback with `(tag ...)` |

   Use the kind names fixed by {{F03}}; when a name is missing there, use the
   `html` fallback, which keeps every attribute:
   `(card-1: html (tag div) (attr class 'card') ...)`.

5. `src/html/ids.js`: ID rules. Use the element's `id` attribute when it is a
   valid LiNo reference and unique; otherwise a path ID from the tag and
   sibling index (`div-0-2-1`). The same input must always give the same IDs.
6. `src/html/style.js`: split inline `style` into declarations and emit
   `(style (padding 8px) (color '#3390ec'))`. Quote any value that contains
   `#`, `:`, `(`, `)`, whitespace or a quote; use `escapeReference` from
   `links-notation`, never hand-made quoting.
7. `src/html/import.js`: build `Link` objects from `links-notation` and format
   them with `formatLinks` (never string concatenation). Return
   `{ text, tree, nodeMap?, spans, diagnostics }` where `spans` maps link ID
   to `{ start, end }` in the source HTML.
8. Security rules: drop `script`, `iframe`, `object`, `embed`, every `on*`
   attribute and `javascript:` URLs, each with a diagnostic
   `{ code: 'dropped-script', id, message }`. Keep `<style>` text as
   `(raw-css '...')` on the parent.
9. Add fixtures and tests (below), a README section and a changeset.

- `.changeset/<name>.md`

Example: input `<button id="ok" class="primary">OK</button>` gives

```lino
(ok: button
  (label 'OK')
  (attr class primary))
```

## Acceptance criteria

- [ ] `importHtml` and `importDom` (jsdom) give the same `text` for every
      fixture (`import-dom.test.js`).
- [ ] Every fixture's output equals its expected `.lino` file.
- [ ] `roundtrip.test.js`: for every fixture, `parse(text)` with `ui-core`
      succeeds without diagnostics and formatting it again gives the same
      links.
- [ ] IDs are deterministic (importing twice gives identical text) and unique
      (duplicate `id` attributes get suffixes, tested).
- [ ] `spans` points at the original source of each element (a test slices the
      HTML with each span and finds the tag name).
- [ ] `importDom` returns a `nodeMap` whose entries are the original DOM nodes.
- [ ] `security.test.js`: `unsafe.html` output contains no `script`,
      `onclick` or `javascript:` text and reports one diagnostic per dropped
      item.
- [ ] Hex colours, URLs and `:`-containing values are quoted; the output of
      `inline-styles.html` parses and keeps `'#3390ec'`.
- [ ] No regex-based HTML or LiNo parser in `src/html/` (review item).
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication` and
      `npm test` pass.

## How to verify

```bash
npm install
node --test packages/ui-convert/tests/html/*.test.js
npm test
npm run lint && npm run format:check && npm run check:duplication
```

Manual check: `node -e "import('@link-foundation/ui-convert').then(m => console.log(m.importHtml('<p>Hi</p>').text))"`
prints a `text` element.
