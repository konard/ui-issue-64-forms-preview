# Component catalogue

One row per framework component kind. Kind names are kebab-case, as in the
dialect samples. Each per-system name links to that system's official page;
`—` means the system has no equivalent, and **(verify)** marks a name that
could not be confirmed on the official page. Keyboard summaries are our own
words (at most 15 words) and link to the APG pattern through the ARIA column.
They are the acceptance criteria for #33.

Groups: actions (`button` … `link`), selection (`checkbox` … `combobox`),
text (`text-field`, `text-area`), containers (`dialog` … `card`), data and
navigation (`list` … `toolbar`), feedback (`progress` … `divider`) and layout
(`stack`, `grid-layout`, `split-pane`).

Owners: #34 basic controls, #35 overlays and navigation, #36 layout, #37 data
display. Owners were assigned from the issue titles and may move when those
issues are planned in detail.

This table is generated from [`catalogue.lino`](catalogue.lino) by
`node scripts/guidelines-tables.mjs`; edit the LiNo file, not the table.

## Notes

- `select` maps to Material 3 menus because M3 has no separate select
  component; the exposed dropdown menu plays that role.
- `popover` uses the APG dialog pattern for its non-modal form, and
  `progress` uses the meter page because APG has no progress bar pattern;
  both are marked (verify) until an APG pattern exists.
- Fluent 2 documents tables and data grids only in the Fluent UI React
  Storybook, so those links are marked (verify).
- MUI `SimpleTreeView` and `DataGrid` come from MUI X, not the core package.
