## Summary

This is the tracking issue for the associative UI framework planned in #1.
Every roadmap issue is attached as a **sub-issue**, and the order between
them is expressed with GitHub's native **"blocked by"** relations. Pick any
open sub-issue that is not blocked.

## Phases

0. **Bugs** — defects found while studying the repository (template identity,
   case-study folder collisions, CI failures on `main`). Bugs come first.
1. **Foundation** — monorepo, licensing records, UI dialect specification,
   design guidelines digest, visual and accessibility test infrastructure.
2. **Core (JavaScript)** — parsing, typed values, links store, persistence,
   layered configuration, tokens, styles, i18n, source-preserving edits,
   settings schema.
3. **Rendering** — DOM reference renderer, HTML importer, React, Vue,
   React Native, Swift and Kotlin parsers and renderers.
4. **Components** — behaviour, controls, overlays, layout and windowing, data
   display, chat, charts, diagrams, links and network visualisation, icons,
   settings panel, code editor.
5. **Themes** — theme engine, Material 3 (with MUI mapping), Fluent 2, Apple
   HIG and classic themes.
6. **Animation** — animation model and player, recorder and replay.
7. **Development mode and designer** — inspector, "make these the defaults"
   agent hand-off, WYSIWYG designer, timeline, dev mode for other pages.
8. **Interoperability** — JSX/MUI/Vue importers, code exporters, A2UI,
   Adaptive Cards, JSON Forms and Lottie.
9. **Documentation and demo site** — GitHub Pages site built with the
   framework, gallery and playground, agent contributor guide.
10. **Migration** — playbook and migration of the existing projects of
    `konard`, `deep-foundation`, `link-foundation` and `link-assistant`.

## Maintainer actions

Some bugs need a repository administrator and cannot be fixed by a pull
request: enabling GitHub Pages ({{B03}}), adding the first `NPM_TOKEN`
({{B05}}) and enabling the dependency graph ({{B06}}).

## How to keep this issue current

When a new roadmap issue is needed, add a file to `roadmap/issues/` and run
`node experiments/issue-1/create-roadmap-issues.mjs` (it is idempotent: it
creates only the missing issues, refreshes bodies, relations and
`docs/ROADMAP.md`).
