## Context

Every control needs the same three things: behaviour (open/closed, checked,
focused item), keyboard and focus handling, and ARIA semantics. The research
recommends describing behaviour as serialisable state machines, as Zag.js
(MIT) does, so that "behaviour and accessibility live once" and only a thin
binding differs per platform; React Aria (Apache-2.0) is the quality bar
([existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)
section 4 and Recommendations A).

Handlers must be data. deepcase stores UI as TSX strings and runs them with
`eval` in `evalClientHandler`; the `require` whitelist does not sandbox
anything ([deepcase.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/deepcase.md)
sections 2.1 and 10). The spec ({{F03}}, `docs/spec/behaviour.md`) already
fixes `(on <event> <action>...)`, with actions from the vocabulary
(`navigate`, `emit`, `set`, `toggle`, `focus`) that are never evaluated.

Our apps re-implement the same accessibility pieces: dialog focus traps and
"shortcuts never steal plain keys from fields" in meta-sovereign
([meta-sovereign-chat.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/meta-sovereign-chat.md)
section 3.4), the APG listbox with typeahead and `numericKeys.js` in
konard.github.io
([konard-github-io-and-links-visuals.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md)
section 4.1), arrow-key tab groups and `aria-live` counters in immortality
([immortality-and-anime-avatar.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md)
section 5).

## Goal

Ship a DOM-free state machine interpreter whose machines are written in LiNo,
an actions registry that maps names to host functions, and DOM accessibility
helpers (focus, roving tabindex, typeahead, key bindings, live region) that
{{F26}} and {{F27}} build on.

## Scope

### In scope

- Machine format in LiNo: `initial`, `context`, flat `state`s, `on` with
  `target`, `do` (action names) and `when` (guard names), `entry`, `exit`,
  `after` (timers with an injected clock).
- Interpreter `createMachine` / `interpret` with no DOM dependency
  (`@link-foundation/ui-components/behavior`, also used later by {{F20}}).
- Part bindings in LiNo: ARIA attributes and keys per part, derived from
  state and context.
- `createActionRegistry()`: register, lookup and dispatch by name; unknown
  names produce diagnostics, never code execution.
- DOM helpers in `src/a11y/`: focus trap and restore, roving tabindex,
  typeahead, key binding map, live-region announcer, `bindMachine`.
- Integration with `ui-dom` ({{F16}}): `(on press ...)` dispatch goes through
  the registry; components declare `(machine ...)`.
- Two reference machines: `toggle` and `disclosure`.

### Out of scope

- Nested and parallel states, history states (record in the README as
  future work).
- The controls themselves ({{F26}}) and overlays ({{F27}}).
- Expressions in guards (`when` takes a guard name only, as the spec defers
  expressions).

## Dependencies

- {{F16}} (blocker): `defineKind`, the `ui-action` event and `onAction`, and
  `handle.nodeFor(id)` used by `bindMachine` to find parts.
- Indirect: {{F06}} `parse` (machines are LiNo documents), {{F03}}
  `behaviour.md` and `vocabulary.lino` (add the `machine` kind there by a
  spec pull request if missing).
- Related: {{F04}} (APG keyboard summaries per kind are the acceptance
  reference), {{F05}} (`expectAccessible(page)` is the axe gate), {{F18}},
  {{F19}}, {{F20}}, {{F28}} (move its keyboard logic onto these helpers).

## Step-by-step plan

1. In `packages/ui-components/` (create the package if {{F28}} has not:
   `@link-foundation/ui-components`, `"type": "module"`), add `src/behavior/`
   and an `exports` entry `"./behavior"` that imports nothing from the DOM or
   `ui-dom`.
2. Machine format (`src/behavior/machines/toggle.lino`):
   ```lino
   (toggle-machine: machine
     (initial off)
     (context (pressed false))
     (state off
       (on toggle (target on) (do set-pressed) (when not-disabled)))
     (state on
       (on toggle (target off) (do clear-pressed) (when not-disabled)))
     (part root
       (attr aria-pressed (context pressed))
       (key Enter toggle)
       (key Space toggle)))
   ```
   `disclosure.lino` adds `(entry focus-content)`, `(exit restore-focus)` and
   `(after 500ms (target closed))` to show timers.
3. `src/behavior/parse-machine.js`:
   `parseMachine(text | UiNode) -> { machine, diagnostics }`; diagnostics for
   unknown targets, duplicate states, missing `initial`.
4. `src/behavior/interpret.js`:
   ```js
   /**
    * @param {Machine} machine
    * @param {{ actions: ActionRegistry, guards?: Record<string, (ctx, event) => boolean>,
    *   clock?: { setTimeout, clearTimeout }, context?: object }} options
    * @returns {{ state: string, context: object, send(event: string | {type: string}): void,
    *   subscribe(fn: (snapshot) => void): () => void, stop(): void, attrs(part: string): object }}
    */
   export function interpret(machine, options) {}
   ```
   Built-in context actions: `(do (set pressed true))` and `(do (toggle pressed))`
   are data operations on context; everything else is a registry lookup.
5. `src/behavior/actions.js`: `createActionRegistry({ onUnknown })` with
   `register(name, fn)`, `has(name)`, `dispatch(name, args, meta)`. The
   vocabulary actions `navigate`, `emit`, `set`, `toggle`, `focus` have
   default implementations; `navigate` rejects the `javascript:` scheme.
6. Add an ESLint rule set for `packages/ui-components/src`: `no-eval`,
   `no-new-func`, `no-implied-eval`.
7. `src/a11y/`: `focus.js` (`trapFocus(container) -> release`,
   `restoreFocus(previous)`), `roving.js` (`createRovingTabindex(items, { orientation, loop })`),
   `typeahead.js` (`createTypeahead(getLabels, { timeout, clock })`),
   `keys.js` (`bindKeys(element, map, { ignoreInFields: true })`, so plain
   keys never fire while focus is in a text field), `announce.js`
   (`announce(message, { politeness: 'polite' | 'assertive' })` with one
   shared live region), `bind-machine.js`
   (`bindMachine(root, service, parts) -> unbind` that applies `attrs(part)`
   and key maps).
8. In `ui-dom` integration (`src/behavior/dom.js`): when an element has
   `(machine toggle-machine)`, create a service on mount and stop it on
   destroy; route `ui-action` events through the registry.
9. Tests and an example page with toggle and disclosure.

## Acceptance criteria

- [ ] `parse-machine.test.js`: both reference machines parse without
      diagnostics; an unknown `target` and a missing `initial` each produce a
      named diagnostic.
- [ ] `interpret.test.js`: `send('toggle')` moves `off` to `on` and back;
      `attrs('root')` returns `{ 'aria-pressed': 'true' }` in `on`; a false
      guard blocks the transition.
- [ ] `timers.test.js`: `after 500ms` fires only after the fake clock advances
      500 ms; `stop()` clears pending timers.
- [ ] `security.test.js`: a document with `(on press 'alert(1)')` and a
      machine with `(do 'globalThis.x = 1')` do not execute anything and
      report `unknown-action`; `navigate` to `'javascript:alert(1)'` is
      rejected.
- [ ] `no-dom.test.js`: importing `@link-foundation/ui-components/behavior`
      with no `window`/`document` globals works.
- [ ] `focus.test.js`: Tab and Shift+Tab cycle inside a trap; release restores
      focus to the previous element.
- [ ] `roving.test.js`, `typeahead.test.js`, `keys.test.js` (including "a
      plain letter key in an input does not trigger a binding"),
      `announce.test.js` pass.
- [ ] `npm run lint` fails on a test fixture file containing `eval(` under
      `src/` (rule active) and passes on the real sources.
- [ ] `behavior.e2e.mjs`: keyboard-only use of the toggle and disclosure works
      in Chromium and WebKit, and `expectAccessible(page)` from {{F05}}
      reports no violations.
- [ ] `npm test`, `npm run lint`, `npm run format:check`,
      `npm run check:duplication` pass.

## Prior art and libraries

- Zag.js (MIT, https://zagjs.com): machine structure, `connect` to parts.
  Reimplement in LiNo; if any code is ported, keep the MIT notice in
  `THIRD_PARTY_NOTICES.md`.
- Ark UI (MIT): parts naming (`root`, `trigger`, `content`).
- React Aria (Apache-2.0): behaviour reference and acceptance bar.
- XState (MIT) and SCXML (W3C): vocabulary for `entry`, `exit`, `after`.
- WAI-ARIA APG: https://www.w3.org/WAI/ARIA/apg/ (link, never copy text).
