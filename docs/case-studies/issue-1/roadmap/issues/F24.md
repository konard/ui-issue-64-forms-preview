## Context

R22 asks for a native Kotlin implementation. The architecture plans a
Gradle / Kotlin Multiplatform package with a Jetpack Compose / Compose
Multiplatform renderer that reads the same LiNo documents and passes the
shared fixtures in `docs/spec/`
([ARCHITECTURE.md](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md),
"Platforms" and "Native ports"). The research tags Kotlin Multiplatform plus
Compose Multiplatform (Apache-2.0) as ADOPT: one renderer covers Android,
desktop and iOS (iOS stable since 1.8.0, May 2025; web status must be
checked)
([existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)
section 8).

There is no Kotlin `links-notation` package; the Java one is not published
(https://github.com/link-foundation/links-notation/issues/192), so {{F23}}
provides the parser
([links-notation-ecosystem.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)
section 2). We have no Kotlin apps yet; the inventory lists air-navigator and
resonance as pilots for the native path
([ui-projects-inventory.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/ui-projects-inventory.md)
section 5, "Wave 6").

This issue is the Kotlin twin of {{F22}}; keep the render-tree format and
the mapping table identical.

## Goal

Create `packages/ui-kotlin/` with a composable `UiView(document)` that
renders the basic dialect kinds with Material 3 Compose components, resolves
design tokens, dispatches actions by name, tags every node with its link ID
and passes render-tree snapshot tests for the shared fixtures.

## Scope

### In scope

- Gradle Kotlin Multiplatform project with source sets `commonMain`
  (model, tokens, render tree, Compose UI) and targets `jvm("desktop")` (CI
  and tests) and `androidTarget()` (build only; optional if the Android SDK
  makes CI too slow, then a follow-up).
- Kinds: `document`, `stack`, `text`, `button`, `image`; unknown kinds render
  an empty `Box` and report a diagnostic.
- Tokens: the Kotlin output of {{F11}} as the default theme, plus loading a
  theme `.lino` at runtime with the {{F23}} parser.
- Actions: `UiAction(source, event, action: List<String>)` passed to an
  `onAction` lambda.
- `Modifier.testTag(id)` on every node, `semantics` roles for buttons and
  images.
- Render-tree snapshots stored as LiNo for every supported fixture.
- CI workflow with a JDK.

### Out of scope

- Behaviour machines and the full control set (follow-ups after {{F25}}–{{F27}}).
- The Material 3 theme pack ({{F40}}), animation ({{F44}}), iOS and web
  targets of Compose Multiplatform (follow-up once the desktop target works).
- A Kotlin port of `ui-store` undo/redo and persistence.

## Dependencies

- {{F23}} (blocker): the Kotlin parser (Gradle module and package name as
  merged there) and, if included, the projection to the F03 element tree. If
  not included, implement `Projection.kt` following `docs/spec/projection.md`
  from {{F03}}.
- {{F11}} (blocker): the generated Kotlin token file used as the default
  theme.
- Related: {{F03}} (fixtures), {{F22}} (same design), {{F20}} (same mapping
  table), {{F40}}.
- To start before F23 merges, build trees by hand in tests and add the text
  entry point last.

## Step-by-step plan

1. Create `packages/ui-kotlin/` with `settings.gradle.kts`,
   `build.gradle.kts`, `gradle.properties` and the Gradle wrapper. Plugins:
   Kotlin Multiplatform, `org.jetbrains.compose` and the Compose compiler
   plugin (check the current versions and their compatibility table). Module
   `ui-kotlin`, package `foundation.link.ui` (or the group used by F23).
2. `commonMain/.../Model.kt`:
   ```kotlin
   data class UiNode(val id: String?, val kind: String, val props: List<UiProp>, val children: List<UiNode>)
   data class UiAction(val source: String, val event: String, val action: List<String>)
   ```
   Field names follow the F03 `.tree.json` shape.
3. `RenderTree.kt`: platform-neutral mapping, used by the composables and by
   tests:
   ```kotlin
   data class RenderNode(val id: String?, val primitive: String,
       val props: List<Pair<String, String>>, val children: List<RenderNode>)
   fun renderTree(node: UiNode, theme: UiTheme): RenderNode
   ```
   Mapping: `document` to `LazyColumn` or scrollable `Column`, `stack` to
   `Column`/`Row` with `Arrangement.spacedBy(gap)`, `text` to `Text`,
   `button` to Material 3 `Button` with a `Text` child, `image` to `Image`
   (the loader is a pluggable lambda; no network library in core) with
   `contentDescription` from `alt`, unknown to `Box`.
4. `Theme.kt`: `UiTheme` resolves `(token space.medium)` to `Dp` or a colour;
   built from the F11 file or from a theme `.lino`.
5. `Snapshot.kt`: `fun dumpLino(node: RenderNode): String`, the same format
   as {{F22}}:
   ```lino
   (app: Column (scroll vertical)
     (body: Column (spacing 16)
       (greeting: Text 'Hello, links')
       (ok: Button (label 'OK'))))
   ```
   Use the F23 formatter for quoting.
6. `UiView.kt`:
   `@Composable fun UiView(document: UiDocumentState, modifier: Modifier = Modifier, theme: UiTheme = UiTheme.Default, onAction: (UiAction) -> Unit = {})`.
   `UiDocumentState` keeps one `mutableStateOf` per element so `setProp`
   recomposes only that element. Every node gets `Modifier.testTag(id)`.
7. Actions: `Button(onClick = { onAction(...) })` with the parsed
   `on press` link. Strings are never executed; `javascript:` navigate targets
   are rejected.
8. Tests in `jvmTest` / `desktopTest`: `RenderTreeTest`, `ThemeTest`,
   `ActionTest`, `FixtureTest` (same rules as F22, snapshots in
   `src/commonTest/resources/snapshots/<area>/<name>.render.lino`; reading
   fixtures from `../../docs/spec/fixtures`), and `UiViewTest` with
   `runComposeUiTest { setContent { UiView(...) }; onNodeWithTag("ok").performClick() }`
   asserting the action (check that the Compose UI test API is available for
   the desktop target in the chosen version).
9. Example: a desktop `main()` in `examples/kotlin/` (`./gradlew run`)
   rendering `docs/case-studies/issue-1/samples/document.lino`.
10. `.github/workflows/kotlin.yml`: `ubuntu-latest`, `actions/setup-java`
    (Temurin 17 or newer, check what the Compose version needs),
    `gradle/actions/setup-gradle`, `./gradlew check` in `packages/ui-kotlin`;
    path filters `packages/ui-kotlin/**`, `docs/spec/**`.

## Acceptance criteria

- [ ] `./gradlew check` passes in `packages/ui-kotlin` on the CI job.
- [ ] `FixtureTest`: every supported fixture in `docs/spec/fixtures/` has a
      `.render.lino` snapshot; adding a fixture without one fails the test.
- [ ] For those fixtures, IDs and parent/child pairs equal those in the
      `.tree.json`.
- [ ] Each fixture's `.render.lino` is identical to {{F22}}'s for kinds that
      map to the same primitive name, or the differences are listed in
      `packages/ui-kotlin/README.md` (for example `ScrollView` vs `Column`).
- [ ] `UiViewTest`: `onNodeWithTag("ok").performClick()` produces
      `UiAction("ok", "press", listOf("navigate", "home"))`; every element
      with an ID has a node with that test tag.
- [ ] `ThemeTest`: token references resolve; missing tokens give a
      diagnostic, not an exception.
- [ ] `javascript:` targets are rejected (`ActionTest`).
- [ ] Screenshot of the desktop example (light and dark) attached to the
      pull request.
- [ ] Every dependency is Apache-2.0, MIT or BSD (reviewed in the PR).
