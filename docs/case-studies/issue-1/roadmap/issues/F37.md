## Context

R9, R11 and R12 ask that any UI can be reconfigured on the fly, visually, and
that the changes can be handed to an agent as new defaults. Three of our
projects built settings panels by hand:

- **konard.github.io** `/settings/` (learn only, the repository has **no
  licence**): `src/settings/schema.js`, `fields.js` (`range(key, d, min, max,
step, label, extra)`, `toggle`, `select(key, d, options, label)`, `color`),
  `apply.js` (CSS variables and `data-*` attributes), `store.js` (stores only
  the difference, syncs tabs with the `storage` event), `SettingsPage.jsx`
  (row `label | control | value | ↺ reset`, `is-changed` class, per-section
  reset, "Reset everything", peek mode, a "Your changes" box with copy and
  paste, a live interface preview; explicit columns because Safari multicol
  was buggy) and `applied.test.js` (every setting is really used)
  ([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md)).
- **immortality** `app/src/components/SettingsPanel.tsx` (Unlicense): one
  generic `AxisControl`, presets, Randomize, "Copy share link" with a
  clipboard fallback, Restore defaults, an `aria-live` count of customised
  settings; a non-modal docked drawer, Escape closes it, focus returns,
  arrow-key tabs, `aria-pressed` toggles, `<output>` for ranges. Bug to avoid:
  `isPresetActive` compares with `JSON.stringify`, so key order breaks it
  ([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md)).
- **formal-ai** `js/app/preferences.jsx`: per-setting reset and reset-all via
  `settingIsDefault` (https://github.com/link-assistant/formal-ai/issues/386)
  ([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md)).
- **anime-avatar** Studio kit (Section with randomize and reset, Row, Slider,
  ColorPick, Select, Chips, Toggle, ConfigDrawer, GlassPanel).

## Goal

A `settings-panel` element is generated entirely from a settings schema
written in Links Notation ({{F15}}): one row per setting with the right control,
the current value, a changed marker and a reset button; sections, search,
presets, randomise, a "Your changes" box that shows the diff as LiNo, a share
link, and live application of changes.

## Scope

### In scope

- Control mapping by schema kind: `toggle` → switch, `choice` → select or
  segmented buttons (≤ 4 options), `range` → slider plus number input with
  `<output>` and unit, `color` → colour input, `text` → text field, `vector`
  → several number inputs, `list` → chips.
- Rows, sections (tabs or collapsible groups), search filter, per-setting,
  per-section and global reset, changed markers, an `aria-live` count.
- Presets (active preset detection with structural comparison), Randomize
  (injected random function), peek defaults (hold a button to see defaults).
- "Your changes": the diff as LiNo, copy and paste; "Copy share link".
- Layout modes: docked drawer (non-modal) and full page.
- Writes to an injected target (user or session layer).

### Out of scope

- The schema engine itself: validation, presets, diff and share encoding
  ({{F15}}).
- The dev-mode inspector for arbitrary elements ({{F46}}) and the designer
  properties panel ({{F48}}); both reuse this panel later.

## Dependencies

- **Blocked by {{F15}}**: schema parsing and validation, defaults, `diff`
  against defaults, preset application and the share-link encoding. Use the
  names {{F15}} exports; until it merges, stub them in
  `tests/settings/stub-schema-engine.js` with the same signatures.
- **Blocked by {{F26}}**: switch, select, slider, number input, colour input,
  text field and buttons.
- **Related:** {{F10}} (config layers user and session), {{F28}} (docked
  drawer), {{F13}} (labels), {{F39}} (themes as presets), {{F46}}, {{F48}},
  {{F58}}, {{F61}}, {{F63}}, {{F64}} (projects that replace their own panels).

## Step-by-step plan

1. Create `packages/ui-components/src/settings/` and export it.
2. Write `control-for.js`:
   `controlFor(field) → { element: string, props: object }` (pure, table
   driven, one test per kind).
3. Write `panel-model.js` (pure):
   ```js
   /**
    * @param {SettingsSchema} schema from F15
    * @param {Record<string, unknown>} values current values
    * @returns {{ sections: Section[], changedCount: number, activePreset?: string }}
    */
   export function buildPanelModel(schema, values, { query } = {}) {}
   ```
   Use a structural equality helper, not `JSON.stringify`, for presets.
4. Write `settings-panel.js` (element): one row per field with label, control,
   value (`<output>` for ranges), changed marker (`data-changed`), and a reset
   button labelled "Reset <label>". Use CSS grid columns, not multicol.
5. Add section reset, "Reset everything" (with confirmation), search, presets,
   Randomize, peek defaults, "Your changes" (LiNo diff with Copy and Paste;
   pasted text is parsed and validated with {{F15}}), and "Copy share link"
   with a fallback text field when the clipboard API is not available.
6. Apply changes live through render hints from the schema:
   `(apply (css-var --liquid-blur))` or `(apply (data-attr density))`.
7. Accessibility: drawer mode is non-modal, Escape closes it and returns focus,
   section tabs follow the APG tabs pattern, toggles use `aria-pressed` or
   `role="switch"`, the changed count is announced in `aria-live="polite"`.
8. Write `examples/settings.html` using a schema like the one below, with a
   preview area that reacts to the settings.

Schema input (format from {{F15}}; this matches the konard.github.io migration
note) and expected diff output:

```lino
(appearance: section (label 'Appearance'))
(liquid.blur: (type range) (default 18) (min 0) (max 40) (unit px) (section appearance))
(theme.mode: (type choice) (default auto) (options auto light dark) (section appearance))
(motion.reduce: (type toggle) (default false) (section appearance))
```

After changing blur to 24, "Your changes" shows `(liquid.blur 24)`.

## Acceptance criteria

- [ ] `controlFor` has a test for every schema kind.
- [ ] `buildPanelModel` detects the active preset regardless of key order
      (test reproduces the immortality bug).
- [ ] Changing a value marks the row changed, updates the count in
      `aria-live`, and resetting the row restores the default (Playwright).
- [ ] "Your changes" shows only changed values as valid LiNo, and pasting it
      into a fresh panel restores them (Playwright).
- [ ] Randomize with a seeded random function gives the same values on two
      runs (test).
- [ ] The drawer closes with Escape and focus returns to the opener
      (Playwright).
- [ ] An example check like `applied.test.js` proves every field in the
      example schema changes the preview (test).
- [ ] axe reports no violations in drawer and page modes.
