## Context

Issue #1 says "any other UI/UX framework is just a Links Notation document"
(R6), asks for compatibility with MUI (R15) and for easy migration of existing
projects (R23). The inventory
([ui-projects-inventory.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/ui-projects-inventory.md))
counts about 45 React repositories in our organisations; MUI is used by
`deep-foundation/deep` and `konard/mui-nextjs-chonky` (listed as the test case
for MUI import); Chakra is the most used component library (12 repositories);
Vue has no apps yet, only the `lino-i18n` Vue example. Chakra rules are a
follow-up that reuses the rule engine of this issue.

{{F17}} creates `@link-foundation/ui-convert` with an HTML/DOM importer: a
shared intermediate form `{ tag, attrs, children, text, span }`, a mapping
table to dialect kinds, deterministic IDs and security rules. This issue adds
two more front ends that produce the same intermediate form:

- **JSX** (`.jsx`, `.tsx` markup), with a mapping for **MUI** components;
- **Vue single-file components** (`.vue`), whose `<template>` is HTML-like.

[meta-language](https://github.com/link-foundation/meta-language) (npm
0.46.0 at research time) is "a self-describing language over a links network:
grammars and translation rules" with a native HTML import and a CSS import
with a lossless CST
([links-notation-ecosystem.md section 3](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)).
The research did **not** confirm a JSX or Vue grammar in meta-language. The
[transformer](https://github.com/link-foundation/transformer) project (Rust)
defines LiNo rewrite rules (match / replace with `$vars`); we use the same
rule shape for the MUI mapping so it is data, not code.

## Goal

`importJsx(text, options)` and `importVue(text, options)` in
`@link-foundation/ui-convert` turn a component file into a UI dialect LiNo
document plus diagnostics, with MUI components mapped to dialect kinds through
a LiNo rule file. Anything that cannot be mapped is kept, marked and reported,
never silently dropped.

## Scope

### In scope

- JSX parsing: first check the current meta-language version for a JSX
  grammar; if it is missing or unusable, use `acorn` with `acorn-jsx` (both
  MIT) or `@babel/parser` (MIT) for `.tsx`, and open an issue in
  meta-language asking for a JSX grammar (link it in the pull request).
- Vue SFC: split blocks; parse `<template>` with the meta-language HTML import
  (as {{F17}} does); `<script>` and `<style>` are kept as raw links and
  reported. Directives: `v-if` / `v-else` → `(when ...)`, `v-for` → `(each ...)`,
  `@click` → `(on press (action <name>))`, `:prop` bindings → `(bind ...)`,
  static attributes → props. Use the names fixed by {{F03}}; if it has no
  binding vocabulary, keep `(unsupported vue-directive '...')`.
- JSX: elements, fragments, string and number props, `className`, `style`
  objects with literal values, text children. `onClick={save}` becomes
  `(on press (action save))` when the handler is an identifier; anything else
  is `(unsupported jsx-expression '<source text>')`.
- MUI mapping rules in `src/mappings/mui.lino` for at least: `Button`
  (`variant` contained/outlined/text), `IconButton`, `TextField`,
  `Checkbox`, `Switch`, `Typography` (`variant` h1–h6/body1/body2),
  `Stack` (`direction`, `spacing` → `gap` token), `Box`, `Card`,
  `CardContent`, `Dialog`, `Tabs`/`Tab`, `List`/`ListItem`, `AppBar`,
  `Toolbar`.
- `sx` props with literal values become `(style ...)`; theme callbacks are
  unsupported. Importing the MUI theme object is {{F40}}.
- Diagnostics `{ code, message, span }` for every unsupported construct;
  output always parses.
- A CLI entry if {{F17}} added one: `ui-convert import --from jsx|vue <file>`.

### Out of scope

- Executing component code, hooks, state or data fetching.
- Importing MUI themes ({{F40}}) and the human migration guide ({{F57}}).
- Exporting back to code: {{F52}}.
- Angular, Svelte and other frameworks (follow-ups using the same rule files).

## Dependencies

- {{F17}} (blocker): package `@link-foundation/ui-convert`, the intermediate
  form, `mapping.js`, `ids.js`, `style.js`, security rules and the formatter
  path through `formatLinks`. This issue only adds front ends and rules.
- Related: {{F03}} (dialect kind names), {{F26}} (component catalog: target
  kinds), {{F40}} (MUI theme mapping), {{F52}} (round trip), {{F57}}
  (migration guide uses this importer).

## Step-by-step plan

1. Check `meta-language` (current npm version, README, exports) for JSX and
   Vue support. Record the finding in the README of `ui-convert`.
2. `src/jsx/parse.js`: `parseJsx(text) -> HtmlNode` (the {{F17}} intermediate
   form, `tag` keeps the component name such as `Button`, `attrs` keep the
   source text of expressions with spans).
3. `src/vue/parse.js`: `parseVue(text) -> { template: HtmlNode, script, styles }`.
4. `src/rules.js`: a small rule engine for rules written in LiNo:

   ```lino
   (mui-button-contained: rule
     (match (Button (variant contained) (children $label)))
     (replace (button (label $label) (variant filled))))
   (mui-stack: rule
     (match (Stack (direction $direction) (spacing $n)))
     (replace (stack (direction $direction) (gap (token space $n)))))
   ```

   `applyRules(node, rules) -> { node, applied: string[] }`. The match shape
   follows transformer's match/replace with `$vars`; keep the engine in JS
   and do not depend on the Rust crate. If F03 names the spacing tokens
   differently, follow F03.

5. `src/mappings/mui.lino`: the rules listed in scope; unmatched MUI
   components fall back to the {{F17}} `html` fallback with `(tag Button)`.
6. `src/jsx/import.js`, `src/vue/import.js`: `importJsx(text, { mappings = ['mui'] })`
   and `importVue(text, options)` return `{ text, tree, spans, diagnostics }`
   like `importHtml`.
7. Fixtures and expected outputs; tests; README; changeset.

Example input `tests/jsx/fixtures/login.jsx`:

```jsx
<Stack direction="column" spacing={2}>
  <TextField label="Email" />
  <Button variant="contained" onClick={signIn}>
    Sign in
  </Button>
</Stack>
```

Expected output (IDs from the {{F17}} rules):

```lino
(stack-0: stack
  (direction column)
  (gap (token space 2))
  (text-field-0: text-field (label 'Email'))
  (button-0: button
    (label 'Sign in')
    (variant filled)
    (on press (action signIn))))
```

## Acceptance criteria

- [ ] Every fixture's output equals its expected `.lino` file.
- [ ] Every output parses with `links-notation` and with the `ui-core` parser
      without errors.
- [ ] `unsupported.jsx` (spread props, inline arrow handlers, `.map()`
      children) produces `unsupported` links and one diagnostic each, with a
      source span.
- [ ] `rules.test.js` covers `$var` binding, a non-matching rule and rule
      order (first match wins).
- [ ] All MUI components listed in scope have a rule and a test case.
- [ ] A Vue fixture with `v-if`, `v-for` and `@click` imports as specified.
- [ ] The README records whether meta-language supports JSX/Vue and links the
      upstream issue if it does not.
- [ ] Only permissive dependencies are added (`npm ls` reviewed).
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication`,
      `npm test` pass.
