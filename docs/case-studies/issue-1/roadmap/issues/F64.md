## Context

[immortality](https://github.com/konard/immortality) is the "Longevity Escape
Velocity Monitor", a dashboard of OWID life-expectancy data with a fully
configurable sci-fi HUD look. It uses React 18.3, Vite 6, TypeScript 5.7 and
Vitest 2, and is Unlicense, so its code can move into the framework directly.
The facts below come from the
[research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md).

The framework's schema-driven settings idea comes from this project.
`app/src/settings.ts` (1,560 lines) holds:

- `AXES`: 49 axes of kind `choice`, `toggle` or `range`, in 8
  `SETTING_GROUPS`;
- the catalogs: `PALETTES` (12), `SURFACES` (13), `FRAME_STYLES` (9),
  `BACKGROUNDS` (21), `SOUNDS` (26) and others, with a `REFERENCES`
  provenance registry;
- 12 presets (Poseidon is the default);
- the pure functions `mergeSettings`, `diffFromDefaults`,
  `migrateLegacySettings`, `encodeShareHash`/`decodeShareHash` (`#ui=` with
  JSON `v:2`), `applySharedLook` (keeps comfort keys) and
  `randomizeSettings` (injected RNG, locked keys).

Problems:

- **One stylesheet.** `app/src/styles.css` has 3,359 lines (about 76 KB) and
  mixes all themes, components and axes.
- **Duplicated mapping.** `Shell` in `App.tsx` writes axes to `data-*`
  attributes and CSS variables, and `styling.test.ts` repeats that list by
  hand as `CSS_AXES`.
- **Key-order bug.** `isPresetActive` compares with `JSON.stringify`.
- **No i18n.** Labels are English literals in the schema.
- **React only.** Nothing can be used from plain JS or Vue.
- **Unreadable share links.** They are percent-encoded JSON.

`sound.ts` synthesizes 26 voices for 10 UI events with Web Audio. The
framework sound layer comes from {{F66}}.

## Goal

immortality keeps its look, its presets and its share links, but:

- the schema is a LiNo file run by {{F15}};
- the drawer is the {{F37}} panel;
- the motion primitives come from {{F44}};
- the stylesheet is split into per-axis and per-theme rules generated from
  the schema.

Old `#ui=` links and old storage still load.

### Out of scope

- The OWID data pipeline and the monthly refresh cron.
- New axes, presets or sounds.
- Translating the labels. This issue moves them into {{F13}} keys; the
  Russian or other catalogs come later.

## Dependencies

- **Blocked by {{F37}}**: the generated panel. It must support:
  - choice as buttons or a select;
  - toggle with `aria-pressed`;
  - range with unit and `<output>`;
  - group tabs with arrow keys;
  - presets, Randomize, share and Restore defaults;
  - a non-modal drawer that returns focus;
  - an `aria-live` count of customized settings.
- **Blocked by {{F44}}**: deterministic, clock-driven text effects and
  entrances scaled by a motion multiplier.
- **Related:** {{F57}} (playbook), {{F15}}, {{F47}}, {{F39}}, {{F43}}, {{F05}},
  {{F63}} (the same schema engine).
- **Blocked by {{F66}}**: the UI sound theme layer (event → voices,
  random/cycle/layer modes, lazy AudioContext, comfort keys and per-voice
  provenance, with `sound.ts` as prior art).
- A stub is possible: steps 1–5 need only {{F15}}.

## Step-by-step plan

1. Copy the {{F57}} checklist template into the tracking pull request.
2. **Freeze the contracts** with Vitest:
   - `immortality.ui-settings.v2` loads unchanged, and the v1 key is
     migrated once;
   - a fixed set of `#ui=` JSON `v:2` links decode to the same settings;
   - `Shell` writes the same `data-*` attributes and CSS variables for each
     preset.

   Save the attribute/variable snapshots as fixtures.

3. **Baseline screenshots** with `experiments/preset-gallery.js`: all 12
   presets × desktop/mobile, with motion off for stable frames.
4. **Schema as LiNo.** Generate `app/src/settings.lino` from `AXES` with a
   one-off script, for example:
   ```lino
   (surface: axis (label 'Panel material') (group panels) (kind choice)
     (display buttons) (render data-attr) (sources arwes gridcn))
   (surfaceOpacity: axis (group panels) (kind range) (render css-var))
   ```
   Take the real min, max, step and options from the code. Labels become
   {{F13}} keys with the English text as the default.
5. **Engine.** Swap the local functions for {{F15}} one at a time; the step-2
   tests must stay green. Fix `isPresetActive` with key-order-independent
   comparison (add a test with reordered keys).
6. **Rendering from hints.** Generate the `Shell` attributes and the
   `CSS_AXES` test list from `render` hints, then delete both hand lists.
7. **Panel.** Replace `SettingsPanel.tsx` with {{F37}} and keep the
   `REFERENCES` links next to each axis.
8. **Stylesheet split.** Move `styles.css` rules into one file per axis
   (`styles/axes/surface.css` …) and per theme, generated or checked against
   the schema. Every option must still have a rule (the existing test).
9. **Motion.** Move `textEffects.ts`, entrances and frames to {{F44}}. Keep
   the regression tests for `animation-fill-mode: both` leaving `clip-path`,
   and for the `steps(1)` flash.
10. **Share links.** Write LiNo diffs, for example
    `(settings (version 3) (palette ares) (frame octagon))`, and keep
    reading `#ui=` JSON `v:2`.
11. **Sound.** Move `sound.ts` onto {{F66}}: load the `immortality` sound
    theme it ships and delete the local synthesizer.
12. **Delete** the replaced code. Record the line counts of `settings.ts`,
    `styles.css` and `SettingsPanel.tsx` before and after.

## Acceptance criteria

- [ ] Old `immortality.ui-settings.v2` storage and the fixed `#ui=` links load
      the same settings (tests).
- [ ] For every preset, the `data-*` attributes and CSS variables match the
      step-2 fixtures.
- [ ] The 12 preset screenshots differ by less than 0.5 % of pixels from the
      baseline.
- [ ] `grep -n "CSS_AXES = \[" app/src/styling.test.ts` returns nothing; the
      list comes from the schema.
- [ ] `isPresetActive` is true for a preset with reordered keys (test).
- [ ] No single CSS file under `app/src/` exceeds 600 lines.
- [ ] The panel passes axe and keyboard checks (tabs, Escape, focus return).
- [ ] Sounds are played by {{F66}} with the `immortality` theme, and the
      local synthesizer in `sound.ts` is deleted.

## How to verify

```bash
# run the test, typecheck and build steps exactly as .github/workflows/website.yml does
node experiments/preset-gallery.js
wc -l app/src/settings.ts app/src/styles/*/*.css
```

Open the site, apply each preset, copy a share link, and open it in a fresh
profile. Check that the comfort settings (animations, sound, volume) of the
viewer are kept.
