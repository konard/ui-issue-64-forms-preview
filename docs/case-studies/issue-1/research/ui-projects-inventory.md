# UI/UX projects inventory and migration plan (issue #1)

> Scope: every repository with a user interface owned by `konard`,
> `deep-foundation`, `link-foundation` and `link-assistant`, collected to
> plan how each one moves to the associative UI framework (`link-foundation/ui`).
> Snapshot date: 2026-11-01.

## 1. Methodology

1. **Raw listings.** Each owner was listed and saved (compact JSON, fields
   `name, description, primaryLanguage, pushedAt, homepageUrl, isFork, stargazerCount`) to
   [`../data/repos-<owner>.json`](../data/):
   - `gh repo list OWNER --limit 1000 --no-archived --json ...` for `deep-foundation`,
     `link-foundation`, `link-assistant`.
   - `konard` has 1,463 public repositories, so `gh repo list` stopped at 1,000. Its listing
     was rebuilt with the paginated REST API (`gh api users/konard/repos --paginate`),
     using the same field names, with archived repos removed (5 archived, none of them UI).
2. **Totals.**

   | Owner           | Not archived | Not forks | Notes                                                                                                                                                                                                                                                 |
   | --------------- | -----------: | --------: | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | konard          |        1,458 |       885 | 584 are `log-tmp-solution-draft-log-pr-*` (AI-solver logs), 22 are `test-*`, about 70 are copies of contributors' or clients' repos (`VisageDvachevsky-*`, `uselessgoddess-*`, `MixaByk1996-*`, `ideav-*`, ...). About 100 are konard's own projects. |
   | deep-foundation |          107 |       102 | 2 archived (`boilerplate`, `payments-tinkoff-c2b-test-integration`), neither has a UI                                                                                                                                                                 |
   | link-foundation |          177 |       177 | 97 are copies of `deep-foundation` repos (pushed 2024-09 or 2025-02), so about 80 are its own projects                                                                                                                                                |
   | link-assistant  |           30 |        30 | 1 archived (`scalper-trader-bot`), no UI                                                                                                                                                                                                              |

3. **Finding UI candidates.** A repo was a candidate if any of these held:
   - its primary language is HTML, CSS, JS/TS, Vue, Svelte, Swift, Kotlin or Dart, and it has a UI;
   - its description mentions an app, site, UI, visual, bot, widget or Mini App;
   - it publishes a GitHub Pages `homepageUrl`.
4. **Deep checks (120 repos).** For each candidate, a script read the recursive git tree
   with `node_modules`, `dist` and `dev/log` skipped. It recorded:
   - the number of files per extension (`tsx/jsx/vue/svelte/swift/kt/dart/html/css`);
   - marker files (`vite.config`, `next.config`, `capacitor.config`, `electron/`,
     `tailwind.config`, `AndroidManifest.xml`, `Package.swift`, `index.html`);
   - the dependency names in up to 4 `package.json` files.

   The key repos also had their READMEs, `index.html` script tags and `src/` component
   listings read.

5. **Pattern search.** GitHub code search was run over all four owners for `i18next`,
   `lino-i18n`, `d3-force`, `cytoscape`, `three`, `@telegram-apps/sdk`, `Telegram.WebApp`,
   `@chakra-ui/react`, `@mui/material`, `tailwindcss`, `katex`, `mermaid`,
   `electron-builder`, `@capacitor/core`, `doublets-web`, `links-notation`, `SettingsPanel`,
   `chat-ui-kit` and `prefers-color-scheme`. The search API rate limit cut a few queries
   short. Hits from code search can include docs or case-study folders, so the stack
   columns below rely on `package.json` and the file tree first.
6. **Priority rule.**
   - **High:** the issue names the repo as a reference, it is actively developed
     (pushed 2026), or it holds a UI pattern many other repos copy.
   - **Medium:** an active app with a real UI that would get simpler after migration.
   - **Low:** a single-page demo, a stale repo (2023-2024), a placeholder, a bot without
     a web UI, or a third-party copy.

Legend for the platform column: **W** web (usually GitHub Pages), **D** desktop (Electron),
**M** mobile (Capacitor iOS/Android or native), **TMA** Telegram Mini App, **Bot** chat-bot UI
(messages and keyboards), **Ext** browser or VS Code extension, **Lib** UI component library.

"**universal-app template**" means the `examples/universal-app` folder copied from
[`link-foundation/js-ai-driven-development-pipeline-template`](https://github.com/link-foundation/js-ai-driven-development-pipeline-template):
React 19 without JSX (`createElement as h`), Vite, Capacitor (`@capacitor/android` and
`@capacitor/ios`), and Electron (electron-builder or Electron Forge). It has no theme
and no i18n, so each derived repo adds its own.

  are natural pilots).

## 5. Recommended migration waves

Every wave has the same exit check: the migrated repo deletes its local copies of the
patterns from section 3, and its UI config is a LiNo file it can export and import.

### Wave 0: references to extract, not migrate (issue-named sources)

Turn these into requirements, components and theme packs; port them back in later waves.

- konard.github.io: settings, theme, i18n prefs, network editor
- immortality: settings axes, HUD theme, charts
- anime-avatar: avatar component and config panel
- links-visuals: link render primitives
- deepcase: graph, tabs, editors, the "classic UI as theme" requirement
- meta-sovereign: chat
- links-notation: the LiNo-to-UI converter
- formal-ai: needs list

### Wave 1: pilots (small, active, high duplication)

1. `link-foundation/js-ai-driven-development-pipeline-template`: replace
   `examples/universal-app` with a `ui`-based universal app. Every new repo inherits it.
2. `link-assistant/calculator`: React + `.lino` i18n + theme; small, shows LiNo-native
   config.
3. `konard/todo` and `link-assistant/models`: minimal React apps for the docs examples.
4. `konard/github-pages-telegram-mini-app`: proves the TMA adapter.

### Wave 2: active template copies (the 15 universal-app repos)

- medical-speech-to-text, wavy-physics, voice-simulator, numbers-vectorization,
  vietnam-accomodation-search, lazada-search, air-navigator, solar-distilling-dryer
- disk-space-saviour, universal-translator, law, legal, conversation

These are mechanical: swap the shell, replace local `SettingsPanel`, theme and i18n with
`ui` modules. Run them in parallel issues.

### Wave 3: issue-named flagship apps

- konard.github.io and immortality: migrate the settings, theme and network editor onto
  the modules built from them in wave 0.
- formal-ai: replace Chakra v3 with `ui` and keep its Electron and VS Code hosts.
- meta-sovereign: move the chat modules into `ui`, then consume them.
- link-cli web, links-notation website, lfs visualizer, meta-expression: switch to the
  shared `LinksView`.
- model-in-browser and react-chat-ui: replace the 6 third-party chat kits with the `ui`
  chat (keep one kit as a comparison baseline).
