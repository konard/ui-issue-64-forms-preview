## Context

The "Regenerate Preview Images" job (`preview-regen` in
`.github/workflows/example-app.yml`) runs inside the container
`mcr.microsoft.com/playwright@sha256:b0ab6f3c…` (`v1.59.1-noble`). When the
screenshots in `docs/screenshots/example-app/` drift, the step "Commit drift
back to main" runs `gh auth setup-git` (line 346). The Playwright image does
not contain the GitHub CLI, so on `main` (run 41299671748, commit `428ee07`)
the step fails:

```text
/__w/_temp/10b5d8bd-….sh: line 4: gh: command not found
##[error]Process completed with exit code 127.
```

This is a code defect, not a missing secret: the error happens before
`RELEASE_PR_TOKEN` is used. The log is stored in
[`ci-logs/main-41299671748.log`](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/ci-logs/main-41299671748.log).

`gh` is also needed later in the same step: when a ruleset refuses a direct
push, `scripts/push-main-with-rebase-retry.mjs` calls
`scripts/land-via-pull-request.mjs`, which runs `gh pr create`,
`gh pr checks` and `gh pr merge`. So removing the `gh auth setup-git` line is
not enough.

## Goal

The preview-regen job can commit regenerated screenshots to `main` (directly,
or through the fallback pull request) without `gh: command not found`.

## Scope

### In scope

- Make the GitHub CLI available in the `preview-regen` job. Recommended: add a
  step before "Commit drift back to main" that installs `gh` from the official
  apt repository (https://github.com/cli/cli/blob/trunk/docs/install_linux.md),
  verifying the keyring, and prints `gh --version`. Only run it when
  `steps.drift.outputs.drift == 'true'`, so the common no-drift run stays fast.
- Alternative (acceptable if simpler): move "Detect drift" and the commit
  into a second job on `ubuntu-24.04` (which has `gh` preinstalled) that
  downloads the screenshots as an artifact from `preview-regen`.
- A regression check: extend the existing workflow tests (search `tests/` for
  `example-app.yml`) or add a test that fails when a job with a `container:`
  runs `gh` without a step that installs it.

### Out of scope

- Changing the Playwright image or version.
- Adding the `RELEASE_PR_TOKEN` secret (only needed if a ruleset blocks direct
  pushes; the step already reports this case explicitly).

## Dependencies

None.

## Step-by-step plan

1. Read `.github/workflows/example-app.yml` from the `preview-regen:` job to
   the end of "Commit drift back to main".
2. Add the install step (or split the job). Keep actions pinned by full SHA
   and keep `persist-credentials: false`, as in the rest of the workflow.
3. Add the regression test described above and run `npm test`.
4. Run `node scripts/check-ci-workflows.mjs` and `actionlint` (if installed)
   to validate the workflow.
5. After merge, check the next `main` run. If there is no drift, trigger the
   job manually with `gh workflow run example-app.yml --ref main` after
   deleting one screenshot in a test branch, or confirm with the step logs that
   `gh --version` runs.

## Files to create or change

- `.github/workflows/example-app.yml`
- `tests/` (new or extended workflow test)

## Acceptance criteria

- [ ] The `preview-regen` job prints `gh --version` before it calls
      `gh auth setup-git`, or the commit runs in a job whose runner has `gh`.
- [ ] A test fails when the install step is removed.
- [ ] `npm test` and `node scripts/check-ci-workflows.mjs` pass.
- [ ] The first `main` run after merge has no `gh: command not found` in the
      "Regenerate Preview Images" job.

## How to verify

```bash
npm test
node scripts/check-ci-workflows.mjs
gh run list --repo link-foundation/ui --workflow example-app.yml --branch main --limit 1
gh run view <run-id> --repo link-foundation/ui --log | grep -n "gh: command not found" || echo "fixed"
```
