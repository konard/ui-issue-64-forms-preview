## Context

The "Security" workflow (`.github/workflows/security.yml`) runs
`scripts/check-dependency-graph.sh`. It is required on `main`
(`REQUIRE_GRAPH=1` when the event is not `pull_request`, line 92). On commit
`428ee07` (run 41299671730) GitHub answered `403 Forbidden` and the job failed:

```text
##[error]The dependency graph of link-foundation/ui is disabled, so dependency
review cannot run. A repository administrator has to enable "Dependency graph"
at https://github.com/link-foundation/ui/settings/security_analysis.
```

The log is stored in
[`ci-logs/main-41299671730.log`](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/ci-logs/main-41299671730.log).
Pull requests only get a warning, so this does not block pull requests, but
licence and vulnerability review of new dependencies (requirement R25: every
dependency must have a permissive licence) does not run until it is enabled.

## Goal

The dependency graph is enabled, and the "Security" workflow on `main` is
green with dependency review running.

## Scope

### In scope

- **Maintainer action (cannot be done by an agent or a pull request):** open
  https://github.com/link-foundation/ui/settings/security_analysis and enable
  **Dependency graph** (and, optionally, Dependabot alerts).
- Re-run the latest "Security" run on `main`.
- Add a licence policy to the `actions/dependency-review-action@v5` step of
  `security.yml`. At the time of writing it only sets
  `fail-on-severity: high` and `comment-summary-in-pr: on-failure`. Use
  `allow-licenses` with the permissive list from the licensing conventions
  (MIT, ISC, BSD-2-Clause, BSD-3-Clause, Apache-2.0, 0BSD, Unlicense, CC0-1.0,
  CC-BY-4.0, BlueOak-1.0.0, Python-2.0), so GPL, AGPL and non-commercial
  licences fail the review.

### Out of scope

- Changing `scripts/check-dependency-graph.sh`: it already fails on `main`
  with the exact action and only warns on pull requests.
- The full licensing and asset record system: that is {{F02}}.

## Dependencies

None. An agent can do the licence policy part; the setting itself needs an
administrator. Merge the policy first: it is harmless while the graph is
disabled, because pull requests only warn.

## Step-by-step plan

1. Check the setting:
   `gh api repos/link-foundation/ui/dependency-graph/sbom --silent && echo enabled`.
2. If it is disabled, comment on this issue asking an administrator to enable
   it at the URL above.
3. Add `allow-licenses` to the "Review dependency changes" step in
   `.github/workflows/security.yml`. Run `npx license-checker-rseidelsohn
--summary` (or `npx license-checker --summary`) to make sure no existing
   dependency would fail; if one does, list it under `allow-dependencies-licenses`
   with a comment explaining why.
4. Re-run the workflow and confirm it passes.

## Files to create or change
