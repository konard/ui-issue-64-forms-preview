## Context

[deepcase](https://github.com/deep-foundation/deepcase) is the UI library of
Deep. It is `@deep-foundation/deepcase` 0.0.135, Unlicense, built on
Next.js 14, React 18, Chakra UI v2, framer-motion, Cytoscape, Monaco, Slate
and rjsf. [deepcase-app](https://github.com/deep-foundation/deepcase-app) is
its application shell. The facts below come from the
[research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/deepcase.md).

deepcase already stores the UI as links, but runs it unsafely:

- A handler is TSX source stored in a link.
- deeplinks `evalClientHandler` runs it with `eval`, without a sandbox.
- A `require` whitelist (`r.list` in `imports/client-handler.tsx`) only
  limits imports.
- Issue https://github.com/deep-foundation/deepcase/issues/85 proposes
  renaming these handlers to "unsafe" and adding safe ones.

Bindings are links:

- `HandleClient` maps Type to Handler;
- `HandleCyto` sets the node look;
- `Context` chooses a view per context.

Graph styles live in Cytoscape stylesheets (`imports/cyto/stylesheets.tsx`),
outside the theme. This causes dark/light mismatches (deep-foundation/deepcase#22;
deep-foundation/deepcase-app#234, deep-foundation/deepcase-app#80, deep-foundation/deepcase-app#296).

The research cites about 80 issues across the two repositories, grouped by
topic:

## Goal

deepcase renders handlers from LiNo component trees through framework
renderers, with no `eval` on the default path. The graph uses the {{F34}}
network view, styled by theme tokens. The classic deepcase looks are
available as {{F43}} themes. Running TSX handlers remains possible only as
an explicit, sandboxed "unsafe" escape hatch.

## Scope

### In scope

The inventory and mapping (deepcase paths are under `imports/`):

| Old piece                                                                                    | Framework piece                                                         |
| -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `client-handler.tsx` (`ClientHandler`, `evalClientHandler`, `CatchErrors`, `r.list`)         | {{F06}} LiNo tree → {{F18}} `ui-react`; error boundary per handler      |
| `HandleClient` / `HandleCyto` / `Context` links                                              | LiNo relations `(render: Type -> view)`, `(inContext: view -> context)` |
| `cyto/graph.tsx`, `layouts.tsx` (d3-force `infinite`, cola, dagre), `elements.tsx`           | {{F34}} network view with bounded layouts                               |
| `cyto/stylesheets.tsx`                                                                       | {{F12}} style rules over {{F11}} tokens                                 |
| `cyto/react.tsx` (`CytoReactLayout`), `cyto/opened.tsx`, `cyto/hooks.tsx` header (~L640–710) | {{F28}} windows anchored to nodes; window state as LiNo                 |
| `cyto/hooks.tsx` cxtmenu (~L905–1065), `cyto/menu.tsx`, `cyto/traveler.tsx`                  | {{F27}} radial and linear menu, top menu as data                        |
| `cyto/editor.tsx` (656 lines), `editor/editor-grid.tsx`, `editor/editor-switcher.tsx`        | {{F38}} editor, state keyed by link id                                  |
| `theme/theme.tsx`, `switch-mode.tsx`, `color-mode-toggle.tsx`                                | {{F39}} theme engine, {{F43}} deepcase classic themes, one mode toggle  |
| `deep-wysiwyg.tsx` (Slate)                                                                   | stays; follow-up issue if a framework rich-text editor appears          |
| `deep.json` (types, handlers, symbols)                                                       | LiNo package file; type Symbols (emoji) are the default icons           |

### Out of scope

- deeplinks engine internals (Hasura, GraphQL, minilinks), except the
  handler lookup hook.
- perception-imports, perception-app and the 2025 `deep` rewrite
  (MUI 6 + echarts). The {{F57}} MUI guide covers the rewrite later.
- Capacitor, Electron and Helm packaging.

## Dependencies

- **Blocked by {{F43}}**: the classic themes "DeepCase classic light", "dark
  - radial menu", "handler windows" and "Perception dark". These are tokens
    plus graph style rules plus chrome layout.
- **Blocked by {{F34}}**: the network view with bounded force (stop and
  settle), label level of detail, pinning and positions as data.
- **Related:** {{F57}} (playbook), {{F06}}, {{F18}}, {{F27}}, {{F28}},
  {{F38}}, {{F45}} (Focus/Opened changes as recordings, undo deep-foundation/deepcase#8), {{F35}}.
- A stub is possible: steps 1–4 (contracts, screenshots, handler format)
  need only {{F06}} and {{F18}}.

## Step-by-step plan

1. Copy the {{F57}} checklist template into the tracking pull request.
2. **Freeze the contracts** with tests in deepcase:
   - handler lookup by `HandleClient` for a Type;
   - `Context` selection;
   - the `require` whitelist list;
   - URL state for space and container;
   - the `Focus` link value `{x, y}`.
3. **Baseline screenshots** of deepcase-app `pages/index.tsx` and
   `pages/editor.tsx`, light and dark, with a fixed 50-link fixture.
4. **Handler format.** Define a LiNo handler document and a resolver that
   tries the LiNo handler first:
   ```lino
   (user-card: handler (for User) (context window)
     (view: stack (direction vertical)
       (title: text (bind name))
       (open: button (label 'Open') (on press (navigate (bind id))))))
   ```
   A TSX handler still runs, but only when it is marked `(unsafe true)`, in
   a sandboxed iframe with a strict CSP. This follows deep-foundation/deepcase#85.
5. **Port three built-in handlers** to LiNo (link card, value editor, type
   view) and render them with `@link-foundation/ui-react`. Compare the
   screenshots.
6. **Graph.** Replace `cyto/graph.tsx` with the {{F34}} view behind a
   feature flag `?graph=framework`:
   - keep the label template `id / type / name / value / symbol`;
   - map the Cytoscape selectors to style rules, for example
     `(link-style: style (selector (type link)) (line dashed) (arrow triangle))`;
   - add regression tests for deep-foundation/deepcase#51, deep-foundation/deepcase#52 (layout settles), deep-foundation/deepcase#37, deep-foundation/deepcase#47 (label level
     of detail), deep-foundation/deepcase#28 (an Any-Any link is not a node) and deep-foundation/deepcase#22 (icons visible
     in dark mode).
7. **Windows and menus.** Anchor handler windows to nodes with {{F28}}, and
   use one overlay z-index layer (deep-foundation/deepcase-app#290). Make the radial menu
   labels horizontal, with a linear alternative (deep-foundation/deepcase-app#299).
8. **Editor.** Key editor tabs by link id (fixes deep-foundation/deepcase#43 and
   deep-foundation/deepcase-app#243, deep-foundation/deepcase-app#238), remember the splitter size (deep-foundation/deepcase#54), and warn before overwriting
   (deep-foundation/deepcase#44).
9. **Themes.** Switch to the {{F43}} deepcase themes. Use valid LiNo
   colours, for example `(token color.primary '#0080ff')` and
   `(scheme dark (token color.bg '#141214'))`.
10. **Convert `deep.json`** handlers to LiNo files, keeping the emoji
    Symbols.
11. Remove the flag and **delete** the replaced code. Record the line counts.

## Acceptance criteria

- [ ] The default handler path runs without `eval` (unit test with `eval`
      stubbed to throw).
- [ ] A handler marked `(unsafe true)` runs only inside the sandboxed iframe
      and cannot read `window.parent` (test).
- [ ] Three built-in handlers render from LiNo with screenshot diffs below
      0.5 %.
- [ ] Layout settles: node positions change less than 1 px over 2 s after
      settling (test for deep-foundation/deepcase#51, deep-foundation/deepcase#52).
- [ ] Icons and edges are visible in dark and light modes, with contrast of
      at least 3:1 against the canvas (deep-foundation/deepcase#22).
- [ ] Editor content survives switching tabs (deep-foundation/deepcase#43, Playwright).
- [ ] The four classic themes from {{F43}} switch at runtime.
- [ ] The pull request lists every cited issue number that the migration
      fixes or makes obsolete.

## How to verify

npm ci && npm test
