## Context

In the UI dialect a theme is a LiNo package of tokens, style rules and
component templates. The idea comes from XAML control templates and Ionic
"modes": one document, many looks
([`docs/ARCHITECTURE.md`](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md),
section "Themes and other frameworks as LiNo"). Material 3 ({{F40}}), Fluent 2
({{F41}}), the Apple HIG-guided theme ({{F42}}) and the classic themes ({{F43}})
are all theme packages built on the engine from this issue.

Our projects show what works and what breaks:

- **What works.** immortality and konard.github.io switch looks without a
  re-render. They write every choice to `data-*` attributes and CSS custom
  properties. konard.github.io also runs a before-paint script so the page
  never flashes the wrong theme
  ([immortality-and-anime-avatar.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md),
  [konard-github-io-and-links-visuals.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md)).
- **What breaks.** formal-ai implements dark mode as an override file,
  `06-dark-theme.css`, which is 1,097 lines and holds about 248 dark selectors.
  The same "theme not applied everywhere" bugs keep coming back: formal-ai
  issues [388](https://github.com/link-assistant/formal-ai/issues/388),
  [541](https://github.com/link-assistant/formal-ai/issues/541) and
  [550](https://github.com/link-assistant/formal-ai/issues/550)
  ([formal-ai.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md)).
  deepcase has the same class of bug because its graph styles live outside the
  tokens
  ([deepcase.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/deepcase.md)
  section 10).
- **What to copy.** meta-sovereign darkens filled accents until they keep a
  4.5:1 contrast ratio, and honours `prefers-reduced-motion`,
  `prefers-reduced-transparency` and `prefers-color-scheme`
  ([meta-sovereign-chat.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/meta-sovereign-chat.md)).

## Goal

Build a theme engine. It loads theme packages written in LiNo, resolves
inheritance and modes (light, dark, high contrast, reduced motion), and
compiles each theme to scoped CSS custom properties. The renderer applies a
theme to any subtree by setting `data-*` attributes, so a subtree can carry a
nested theme and switching a theme never re-renders. A colour scheme is a set
of token values, never a separate override stylesheet.

## Scope

### In scope

- The theme model in `@link-foundation/ui-tokens`, in `packages/ui-tokens/src/themes/`:
  - `theme` links with `extends`, `token`, `style`, `template`, and the
    `mode dark`, `mode high-contrast` and `motion reduced` blocks.
- The new package `packages/ui-themes/` (`@link-foundation/ui-themes`). It
  holds theme packages as data and starts with the `base` theme only.
- Nested themes. `(theme x)` and `(scheme dark)` on any element apply to its
  subtree, and an inner subtree can switch back to `light`.
- Modes: scheme `light`, `dark` or `system` (`prefers-color-scheme`);
  contrast `normal` or `more` (`prefers-contrast`, plus `forced-colors`
  mapped to system colours); motion `full` or `reduced` (`prefers-reduced-motion`).
- Contrast-safe accents. Declared colour pairs are checked against WCAG 2.2
  ratios, and any filled accent that fails is adjusted automatically.
- Component templates, following the XAML control-template idea. A theme can
  replace the part tree of a {{F26}} control. Part names follow Open UI
  anatomy (`root`, `label`, `icon`, `indicator`).
- Theme switching without re-rendering, plus a before-paint script that stops
  the wrong theme from flashing on load.
- Comfort keys. A theme must never override the user's motion, sound, volume
  or transparency choices (the konard.github.io COMFORT keys).

### Out of scope

- The concrete design-system themes: {{F40}}, {{F41}}, {{F42}} and {{F43}}.
- The settings panel UI for choosing themes ({{F37}}).
- Animation runtime. This issue only defines motion tokens and the reduced
  mode; {{F44}} covers animation.
- Native theme switching ({{F21}}, {{F23}}); {{F11}} already exports tokens.

## Dependencies

- {{F11}} (blocker). Supplies the token model, reference/semantic/component
  layers, the CSS custom property naming (for example `--color-primary`) and
  the DTCG 2025.10 export. Themes are token sets, so reuse its resolver and do
  not write a second one.
- {{F12}} (blocker). Supplies style rules with `(state ...)` and
  `(media ...)`. The engine compiles `style` links inside a theme with this
  resolver, scoped to `[data-theme="<id>"]`.
- {{F26}} (blocker). Supplies the basic controls and their default part trees.
  The `button` control is the first consumer of `resolveTemplate`.
- Indirect: {{F06}} (parser), {{F07}} (colour values, OKLCH conversion) and
  {{F16}} (ui-dom, which writes the attributes).
- Related: {{F10}} (configuration layers, where the user's `theme` and
  `scheme` choices live), {{F37}}, {{F40}}–{{F43}}, {{F54}}, {{F57}}.
- To start before {{F26}} merges, test templates against a stub `button` kind
  registered in the test file.

## Step-by-step plan

1. Write a theme package format. Save this example as
   `packages/ui-themes/themes/base/theme.lino`; the final syntax is fixed by {{F03}}:
   ```lino
   (base: theme
     (token color.primary '#3A5BA0')
     (token color.on-primary '#FFFFFF')
     (token color.surface '#FFFFFF')
     (token color.on-surface '#1B1B1F')
     (token motion.duration.short 150ms)
     (pair color.on-primary color.primary)
     (pair color.on-surface color.surface)
     (mode dark
       (token color.primary '#AFC6FF')
       (token color.on-primary '#0A2F6B')
       (token color.surface '#121316')
       (token color.on-surface '#E3E2E6'))
     (mode high-contrast
       (token color.primary '#0B2A66'))
     (motion reduced
       (token motion.duration.short 0ms)))
   ```
2. In `packages/ui-tokens/src/themes/model.js`, implement:
   ```js
   /** @typedef {{ id: string, extends: string[], tokens: Map<string, TokenValue>,
    *   modes: Record<string, Map<string, TokenValue>>, styles: StyleRule[],
    *   templates: Map<string, TemplateNode>, pairs: [string, string][] }} Theme */
   /** @param {string} linoText @returns {{ themes: Theme[], diagnostics: Diagnostic[] }} */
   export function loadThemes(linoText) {}
   /** Merges the `extends` chain; the child wins and order is deterministic.
    * @param {Map<string, Theme>} registry @param {string} id @returns {Theme} */
   export function resolveTheme(registry, id) {}
   ```
   Reject executable content: any value containing `javascript:` or
   `expression(` and any `script` link. Each rejection produces a diagnostic.
   Inheritance cycles produce a diagnostic, not a crash.
3. In `src/themes/contrast.js`, implement:
   ```js
   /** WCAG 2.2 relative-luminance contrast ratio. @returns {number} */
   export function contrastRatio(fg, bg) {}
   /** Moves `fill` in OKLCH lightness until contrastRatio(on, fill) >= min.
    * @returns {{ color: string, adjusted: boolean, ratio: number }} */
   export function ensureContrast(on, fill, min = 4.5) {}
   ```
   Every `pair` in every mode is checked. When a pair fails, the engine writes
   the adjusted colour into the compiled output and emits a warning
   diagnostic. `{ strict: true }` turns that warning into an error.
4. In `src/themes/compile-css.js`, write
   `compileThemeCss(theme, options) -> string`. It emits:
   - `[data-theme="base"]` with the light values;
   - `[data-theme="base"][data-scheme="dark"]`;
   - `@media (prefers-color-scheme: dark) { [data-theme="base"][data-scheme="system"] {...} }`;
   - `[data-contrast="more"]` and `@media (prefers-contrast: more)` for
     `data-contrast="system"`;
   - `@media (forced-colors: active)`, which maps semantic tokens to system
     colours (`Canvas`, `CanvasText`, `ButtonText`, `Highlight`);
   - `[data-motion="reduced"]` and `@media (prefers-reduced-motion: reduce)`.

   Style rules from the theme are compiled with {{F12}} and prefixed with
   `:where([data-theme="base"])` so that their specificity stays low.

5. Nesting. In ui-dom ({{F16}}), add `src/themes.js`, which handles every
   element that carries `theme`, `scheme`, `contrast` or `motion`. On that
   element it writes all four effective values as `data-theme`,
   `data-scheme`, `data-contrast` and `data-motion`, copying any value it
   does not set from the nearest themed ancestor. Custom properties inherit,
   so the innermost theme wins. Setting a new value is a store `set`, and the
   change handler only rewrites attributes on the theme boundaries; it never
   rebuilds nodes.
6. Comfort keys. `motion`, `sound`, `volume` and `transparency` are read from
   configuration ({{F10}}), and a theme may only supply defaults for them. The
   user layer always wins. Add a test that applies a theme with
   `(motion reduced)` defaults to a user who chose `full`.
7. Templates. Write
   `resolveTemplate(themeChain, kind) -> TemplateNode | null` in
   `src/themes/templates.js` and call it from the {{F26}} `button` kind. An
   example template:
   `(template button (part root (kind box)) (part icon (kind icon)) (part label (kind text)))`.
   An unknown part name produces a diagnostic.
8. Before-paint script. Write
   `themeBootScript({ storageKey }) -> string`, an inline script of at most
   1 KB. It reads the saved theme and scheme from `localStorage` and sets the
   attributes on `<html>` before first paint, following the konard.github.io
   `themeBeforePaint` pattern.
9. DTCG. Write `exportThemeResolver(theme) -> object`, which maps the modes
   to a DTCG 2025.10 Resolver Module document. Check the current Resolver
   Module schema and validate against it in a test.
10. In `examples/themes/`, build a page that shows the same {{F26}} controls
    four times: base light, base dark, nested dark-inside-light, and high
    contrast. Add the README, the changesets for ui-tokens, ui-dom and
    ui-themes, and the tests listed below.

## Acceptance criteria

- [ ] `themes-model.test.js`: `extends` chains of depth 3 resolve
      deterministically, a cycle gives a diagnostic, and a `script` link or a
      `javascript:` value is rejected.
- [ ] `themes-contrast.test.js`: `contrastRatio('#FFFFFF', '#000000')` is 21,
      `ensureContrast` raises a failing pair to at least 4.5:1, and every
      `pair` in `base` passes 4.5:1 in light, dark and high contrast.
- [ ] `themes-css.test.js`: a snapshot of the compiled CSS for `base` contains
      the scheme, contrast, forced-colors and reduced-motion blocks, and no
      selector has `!important`.
- [ ] `themes.test.js` (jsdom): switching `scheme` from light to dark creates
      zero new nodes. A `MutationObserver` must record only attribute
      mutations, and those only on theme boundaries.
- [ ] Light inside dark inside light: each subtree resolves its own
      `--color-surface`, and a user's `full` motion choice survives a theme
      whose default is `reduced`.
- [ ] `resolveTemplate` returns the theme template for `button`, and the
      rendered button exposes the template parts.
- [ ] Every theme the repository ships has a dark mode. The engine has no
      per-scheme override stylesheets (no `*dark*.css` files under
      `packages/`).
- [ ] Playwright `themes.spec.js` produces screenshots of the 4 panels in
      Chromium, and axe finds no contrast violations.
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication` and
      `npm test` pass.

## How to verify

```bash
npm install
node --test packages/ui-tokens/tests/themes-*.test.js
node --test packages/ui-dom/tests/themes.test.js
npm test
npx playwright test tests/e2e/themes.spec.js
find packages -name '*dark*.css'   # must print nothing
```

Open `examples/themes/index.html`. Toggle the colour scheme in the operating
system and check that the "system" panel follows it with no flash on reload.
