# Existing solutions: prior art, libraries and specifications

Research for [link-foundation/ui#1](https://github.com/link-foundation/ui/issues/1),
"Initial version of associative UI framework". Collected 2026-11-01.

This document lists components, libraries and specifications that solve parts of
the problem in issue #1. The issue asks for:

- one Links Notation (LiNo) dialect for structure, config, styles, animations;
- animation recording;
- a WYSIWYG designer and a development/configuration mode;
- classic UIs as themes;
- Material, Fluent and Apple HIG alignment;
- our own controls, charts, diagrams and links-network visualisation;
- vanilla JS, React, React Native, Vue, Swift and Kotlin targets;
- public-domain assets of our own;
- a self-hosted documentation site.

## How to read the tables

Each entry gives a one-line description, the license, a URL and a relevance tag.
The tags mean:

| Tag         | Meaning                                                                                                                                |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **ADOPT**   | Depend on it, or embed it, in shipped packages. The license is permissive (MIT, ISC, BSD, Apache-2.0, CC0) and the project is healthy. |
| **INTEROP** | Import from it, export to it, or provide an adapter for it. Do not make it a core dependency.                                          |
| **LEARN**   | Study its design, data model or user experience. Do not depend on it.                                                                  |
| **AVOID**   | The license or terms conflict with our goals (public domain, no-code designer, cross-platform), or it is unmaintained.                 |

Facts marked **(verify)** were not confirmed against a primary source, or the
sources disagree. Re-check them before relying on them in an issue or in code.

The license for our own code and assets is assumed to be **Unlicense** (code)
and **CC0-1.0** (assets). That matches the issue's "fully public domain"
requirement. Every dependency must be compatible with redistribution inside
public-domain packages, which means permissive licenses only. Copyleft
dependencies (MPL, EPL, LGPL) are acceptable only as optional, separately
packaged adapters.

## 1. Declarative and serialisable UI description formats

These are the closest prior art for "any UI framework is just a Links Notation
document". Most use JSON with a **component catalog**: the document names
components from a trusted registry, and each platform renders them natively.
A LiNo dialect can follow the same pattern.

**Takeaways for the dialect.** Every successful format here separates five
things:

1. a structure tree (component plus props plus children);
2. a component catalog or schema;
3. a theme or host config (tokens);
4. state and bindings;
5. actions and events.

The ones with designers (XAML, QML) add design-time-only metadata and visual
states. Our LiNo dialect should name these five layers explicitly. It should be
lossless to and from JSON, so A2UI, Adaptive Cards and JSON Forms import is
mechanical.

**Takeaway.** Use a three-layer token model. LiNo is the source, and DTCG
2025.10 is the exchange format.

1. Reference: raw palette and scales.
2. Semantic (system): roles such as `surface`, `on-surface` and `primary`.
3. Component: for example `button.primary.background`.

Material, Fluent, HIG and "classic" themes (Windows 95, Aqua and so on) are then
just alternative reference and semantic layers, plus optional
control-template overrides (the XAML idea).

## Recommendations

### A. Build on these (permissive, healthy, aligned)

1. **Links Notation as the single source of truth**, with lossless conversion
   to the closest standard in each domain:
   - **DTCG 2025.10** for tokens (via **Style Dictionary** transforms to CSS,
     Swift, Kotlin and JS);
   - **WAAPI / Lottie** for animation;
   - **Vega-Lite** for charts;
   - **Mermaid / DOT** for diagrams;
   - **A2UI / Adaptive Cards / JSON Forms** for UI trees;
   - **Custom Elements Manifest** for component metadata.

   "Every other framework is just LiNo" then becomes concrete: each one has an
   importer and exporter.

2. **Web Components (Lit or plain custom elements)** as the reference
   vanilla-JS renderer. Generate **React and Vue wrappers** with a Stencil-like
   output-target approach, so one implementation serves all web frameworks.
3. **Zag.js-style state machines** (adopt Zag.js, or reimplement its machines
   described in LiNo) for component behaviour and accessibility. Use **React
   Aria** and WAI-ARIA APG as the acceptance criteria. **Floating UI** for
   positioning.
4. **Three-layer tokens** (reference → semantic → component), with
   **material-color-utilities** for palette generation. **Material, Fluent and
   Apple (HIG-guided) themes** plus "classic" themes as alternative token sets
   and control templates. Use **Ionic's modes** and **XAML control templates**
   as the model, and **Open UI** research for canonical component and part
   names.
5. **Visualisation:** D3 modules plus our own LiNo chart grammar
   (Vega-Lite-like). Renderers: **ECharts** (broad charts), **Cytoscape.js**,
   **Sigma.js/Graphology** and **force-graph/3d-force-graph** (links networks),
   **xyflow** (editable node graphs, React), **Dagre** (default layout).
6. **Animation:** our own LiNo keyframe and spring and state-machine model,
   compiled to **WAAPI / View Transitions**, **Motion** (MIT) on web, and
   SwiftUI and Compose natively. **rrweb** as an optional DOM-level session
   recorder. **Playwright** for turning recordings into tests.
7. **Designer and dev mode:** our own, over the LiNo tree. Copy the panel
   architecture from **GrapesJS / Puck / Visual Studio**, the runtime-overlay
   inspector from **React DevTools / Live Visual Tree**, the variants matrix
   from **Xcode Previews / Storybook**, and the timeline from **Theatre.js**
   (design only). Use **Puck** (MIT) or **GrapesJS** (BSD-3) only for a
   throw-away early prototype if speed matters.
8. **Native:** **SwiftUI** (SwiftPM) and **Jetpack Compose / Compose
   Multiplatform** renderers that interpret the same LiNo. **React Native New
   Architecture** (0.82+) with **Expo** for demos, and **React Native Web** to
   show RN components on the docs site. **Tauri** for a desktop designer shell
   that can use the Rust associative stack (`doublets-rs`, `link-cli`).
9. **Assets:** our own icon and illustration set under **CC0-1.0**. Default
   third-party sets: **Lucide** (ISC), **Material Symbols** (Apache-2.0),
   **Fluent System Icons** (MIT), **Phosphor / Tabler** (MIT), **Health Icons /
   Kenney** (CC0). Keep attribution records in LiNo modelled on **Iconify's
   per-set metadata**, with **SPDX** IDs, a **REUSE 3.3** compliant repo
   (`REUSE.toml`), and **ScanCode** license scanning in CI.

### B. Only interoperate with (import, export or optional adapter; no core dependency)

- **Figma** (Dev Mode, Variables, Code Connect) and **Penpot** (MPL-2.0;
  DTCG tokens). Token sync and component mapping only.
- **MUI, Radix, shadcn/ui, Base UI, Headless UI, Fluent UI React,
  Ionic.** Migration converters (theme to tokens, component-name mapping) and
  a **shadcn-registry export** so agents can install our components.
- **A2UI, Adaptive Cards, JSON Forms, DivKit, json-render.** Importers and
  exporters, plus learning their catalog and versioning models.
- **Lottie / dotLottie** for animation exchange. **Mermaid / Graphviz DOT /
  Vega-Lite** for diagrams and charts.
- **ELK.js (EPL-2.0)** and **Graphviz WASM (EPL)**. Optional, separately
  licensed plugin packages only.
- **OpenMoji (CC BY-SA 4.0)**, **Twemoji (CC BY 4.0)**, **game-icons
  (CC BY 3.0)**. Optional packs with the required credits.
- **Skip** (LGPL libraries), **Capacitor**, **Electron**. Optional delivery
  routes.
- **SF Symbols and SF fonts.** Reference by name at runtime on Apple platforms
  only.

### C. Avoid (license or maintenance conflicts)

- **GSAP.** Its "Standard No Charge" license is proprietary and explicitly
  forbids use in no-code visual animation tools that compete with Webflow,
  which is our designer. Webflow can also revoke or change the terms.
- **tldraw SDK.** Production requires a license key (since 4.0), with a
  watermark on hobby licenses. Incompatible with public-domain redistribution.
- **Theatre.js Studio (AGPL-3.0)**, the **Plasmic `platform/` code (AGPL)**,
  **ToolJet (AGPL)**, **Qt/QML** and **Slint** (GPL/commercial) as
  dependencies. Learn from their designs only.
- **Rive editor and `.riv` as the core format.** Closed editor and format,
  though the runtimes are MIT.
- **Remix Icon** (custom license since January 2026) and **SF Symbols / SF Pro
  / Segoe UI** (restricted) in any bundled package.
- **Commercial-only libraries** (GoJS, yFiles, Highcharts, amCharts, AG
  Grid/Charts Enterprise, MUI X Pro, JointJS+, Remotion) in core.
- **Material Web (MWC)** as a dependency, because it is in maintenance mode.
  Use material-color-utilities and the M3 token specs directly.
- **Heavy code generation as the primary architecture** (lesson from Airbnb
  Lona, and Mitosis' slow progress). Prefer a runtime LiNo interpreter plus
  thin native renderers, and use codegen only for wrappers and types.

### D. Open questions to verify before writing issues

- Current stable version of A2UI (0.8 versus 0.9/1.0) and its component
  catalog schema.
- Compose Multiplatform for Web stability (Beta or Stable in 2026?).
- Exact license of the open-sourced Skip engine (skipstone).
- Fluent UI Web Components v3 stable date.
- Remix Icon License v1.0 text.
- Licenses of Adaptive Cards (MIT expected), Onlook, Terrazzo, Tokens Studio
  plugin, Custom Elements Manifest and mdui. Confirm each in the repo's
  LICENSE file.
- Whether link-foundation standardises on Unlicense or CC0 for code. Check
  `links-notation` and sibling repos.
