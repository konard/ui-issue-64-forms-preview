## Context

The repository is still the link-foundation JavaScript template:

- one package, `@link-foundation/example-package-name` (version 0.11.31), with `src/index.js`;
- tests in `tests/*.test.js`, run on Node (`node --test`), Bun (`bun test`, `bunfig.toml` root `./tests`) and Deno (`deno test`, `deno.json` include `tests/`) through `test-anywhere`;
- releases through changesets in `.github/workflows/release.yml`.

The architecture needs about 16 packages (`ui-core`, `ui-store`, `ui-config`, `ui-tokens`, `ui-style`, `ui-dom`, `ui-react`, ...; see the layer table in [`docs/ARCHITECTURE.md`](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md)). Every later JavaScript issue assumes they live under `packages/<name>/` with npm names `@link-foundation/ui-*`.

Several release scripts assume a single package:

- `scripts/package-info.mjs` (`readPackageInfo()` reads only `./package.json`);
- `scripts/js-paths.mjs` (`getJsRoot()` returns `.` or `./js`);
- `scripts/check-version.mjs`, which compares the root version;
- `scripts/validate-changeset.mjs`, which requires the changeset frontmatter to name the root package;
- `scripts/check-changesets.mjs`;
- `scripts/publish-to-npm.mjs` and `scripts/smoke-test-package.mjs`;
- the GitHub release scripts (`release-naming.mjs`, `create-github-release.mjs`).

R23 asks for easy migration and deduplication: shared code must be in one place, not copied per package.

## Goal

Turn the root into an npm workspaces monorepo (`packages/*`) with one skeleton package `@link-foundation/ui-core`. Lint, format, duplication check, tests on Node/Bun/Deno, changesets, the version check and publishing must keep working in CI for every non-private workspace package.

## Scope

### In scope

- Root `package.json` with `"private": true` and `"workspaces": ["packages/*"]`. The root keeps the dev tooling and the name chosen in {{B01}}.
- `packages/ui-core/` skeleton: `package.json`, `src/index.js`, `tests/index.test.js`, `README.md`, `LICENSE` (Unlicense).
- Test discovery across `tests/` and `packages/*/tests/` for Node, Bun and Deno.
- Multi-package awareness in the release scripts, through one helper module.
- Changesets that name `@link-foundation/ui-*` packages; independent versions.
- A short `docs/monorepo.md` that says how to add a package.

### Out of scope

- Real `ui-core` code ({{F06}}) and the other packages (each has its own issue).
- Swift and Kotlin build systems ({{F21}}, {{F23}}).
- Moving `examples/universal-app`: it stays a separate npm project used with `npm --prefix`.

## Dependencies

- **{{B01}}** (blocker) renames the repository identity: the package name, the README and `docs/CONTRIBUTING.md`. F01 needs the final root name, and it needs the template name gone so that `validate-changeset.mjs` and the checks of the existing `.changeset/*.md` files can be rewritten once. To start early, branch from {{B01}}'s PR and rebase when it merges.

Related:

- {{B05}} (publishing preflight and `NPM_TOKEN`) must accept the list of workspace packages.
- {{F05}} adds Playwright and axe tests on top of the workspace.
- {{F56}} documents the workflow for agents.
- {{F06}} is the first real package.

## Step-by-step plan

1. Read `package.json`, `.changeset/config.json`, `scripts/package-info.mjs`, `scripts/js-paths.mjs`, `scripts/validate-changeset.mjs`, `scripts/check-changesets.mjs`, `scripts/check-version.mjs` and `scripts/publish-to-npm.mjs`. Then read the `version-check`, `changeset-check`, `lint`, `test`, `release` and `instant-release` jobs in `.github/workflows/release.yml`.
2. Add `scripts/workspace-packages.mjs`, which exports:
   - `/** @returns {Promise<Array<{dir: string, name: string, version: string, private: boolean}>>} */ listWorkspacePackages(rootDir = '.')`. It reads `workspaces` from the root `package.json`, expands `packages/*` with `node:fs` (no new dependency), and returns them sorted by name.
   - `/** @returns {Promise<Array<...>>} */ listPublishablePackages(rootDir)`, which returns the non-private packages only.
3. Create `packages/ui-core/package.json` with these fields:
   - `"name": "@link-foundation/ui-core"`, `"version": "0.0.0"`, `"type": "module"`;
   - `"exports": {".": "./src/index.js"}`, `"files": ["src/", "README.md", "LICENSE"]`;
   - `"license": "Unlicense"`, `"engines": {"node": ">=20"}`, `"publishConfig": {"access": "public"}`.

   Its `src/index.js` exports `export const UI_DIALECT_VERSION = 'ui-dialect/0';`.

4. Root `package.json` changes:
   - add `"private": true` and `"workspaces": ["packages/*"]`;
   - remove `main`, `bin` and `files`, and move `src/index.js` and `tests/index.test.js` out (delete the template `add`/`multiply` examples);
   - set `"test": "node --test --test-timeout=30000 tests/*.test.js packages/*/tests/*.test.js"`. If `tests/` is empty, keep only the packages glob.
5. Update `bunfig.toml`: remove `root = "./tests"` so that Bun discovers `**/*.test.js`, or check the current Bun docs for multiple roots. Update `deno.json`: set `"test": {"include": ["tests/", "packages/"]}`. Make sure `examples/` and `node_modules/` are excluded.
6. Make the release scripts loop over `listPublishablePackages()`:
   - `check-version.mjs` checks each package against npm;
   - `validate-changeset.mjs` accepts any frontmatter key that is a workspace package name and rejects unknown names;
   - `check-changesets.mjs` counts per package;
   - `publish-to-npm.mjs` and `smoke-test-package.mjs` run per package (`npm publish --workspace <name>`, or `changeset publish`, which already handles workspaces);
   - the release naming uses `<name>@<version>` tags.

   Keep the old single-package path working when `workspaces` is absent, so that template sync stays possible.

7. Keep `.changeset/config.json` with `"fixed": []` and `"linked": []` (independent versions) and `"updateInternalDependencies": "patch"`. Delete or rewrite the template changesets that name `@link-foundation/example-package-name`.
8. Run `npm install` to regenerate `package-lock.json` with the workspace. Check that `npm ci` works from a clean clone.
9. Update `.github/workflows/release.yml` only where it hard-codes paths: test globs, `src/` and the package name. Keep job names, because the pipeline status gate checks them (`scripts/check-status-gate-covers-all-jobs.mjs`).
10. Add tests:
    - `tests/workspace-packages.test.js`, for listing, filtering private packages, and the single-package fallback, using a temp-dir fixture;
    - `packages/ui-core/tests/index.test.js`, which imports `@link-foundation/ui-core` through the workspace link.
11. Write `docs/monorepo.md`: the layout, how to add a package (copy `ui-core`, rename, `npm install`), naming, versioning and changesets. Link it from `docs/CONTRIBUTING.md`.

## Files to create or change

- `package.json`, `package-lock.json`, `bunfig.toml`, `deno.json`, `eslint.config.js` (test overrides for `packages/*/tests/**`)
- `scripts/workspace-packages.mjs` (new); `scripts/check-version.mjs`, `validate-changeset.mjs`, `check-changesets.mjs`, `publish-to-npm.mjs`, `smoke-test-package.mjs`, release naming scripts
- `packages/ui-core/{package.json,src/index.js,tests/index.test.js,README.md,LICENSE}`
- `tests/workspace-packages.test.js`, `docs/monorepo.md`, `docs/CONTRIBUTING.md`
- `.github/workflows/release.yml` (paths only), `.changeset/*.md`

## Acceptance criteria

- [ ] `npm ci` succeeds on a clean clone, and `npm ls @link-foundation/ui-core` shows the workspace link.
- [ ] `npm test` runs both `tests/*.test.js` and `packages/*/tests/*.test.js`, and the output includes the `ui-core` test.
- [ ] `bun test` and `deno test -A --parallel` also run the `ui-core` test.
- [ ] `node scripts/validate-changeset.mjs` accepts a changeset naming `'@link-foundation/ui-core': patch` and rejects one naming an unknown package.
- [ ] `npm run changeset:version` in a scratch clone bumps only `packages/ui-core/package.json`.
- [ ] `npm pack --workspace @link-foundation/ui-core --dry-run` lists only `src/`, `README.md`, `LICENSE` and `package.json`.
- [ ] `npm run lint`, `npm run format:check` and `npm run check:duplication` pass.
- [ ] All jobs of `release.yml` are green on the PR. `docs/monorepo.md` exists and is linked from `docs/CONTRIBUTING.md`.

## How to verify

```bash
rm -rf node_modules && npm ci
npm test
bun test --timeout 30000
deno test -A --parallel
npm pack --workspace @link-foundation/ui-core --dry-run
npm run lint && npm run format:check && npm run check:duplication
node --test tests/workspace-packages.test.js
```

## Prior art and libraries

- npm workspaces (built into npm 7+). No Lerna, Nx or Turborepo, because plain npm is enough and it keeps R18.
- Changesets' monorepo support: https://github.com/changesets/changesets (MIT).
- The upstream `links-notation` repository also hosts several language packages in one repository (`js/`, `rust/`, `java/`, ...; see [links-notation-ecosystem.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)).
