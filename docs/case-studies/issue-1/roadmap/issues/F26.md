## Context

R13 asks for a complete component set and R15 for accessibility and a
familiar look. Every app of ours ships its own controls today. konard.github.io
owns `Select.jsx` (portal popup, APG listbox keyboard with typeahead),
`NumberInput.jsx`, `ColorInput.jsx` and `numericKeys.js` (arrows,
PageUp/PageDown, Home/End, Shift for ×10, a Safari focus fix)
([konard-github-io-and-links-visuals.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md)
section 4.1). immortality has a WAI-ARIA select-only combobox with type-ahead
and edge flip, a toggle button with `aria-pressed`, a range input with an
`<output>` and a `--fill` CSS variable, and swatch buttons in a fieldset
([immortality-and-anime-avatar.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md)
sections 5 and 6). formal-ai uses segmented controls with `role=radiogroup`
([formal-ai.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md)
section 5).

This issue turns these into one set of LiNo-described controls on top of the
machines, actions registry and accessibility helpers from {{F25}}. Headless
libraries (Zag.js, Ark UI, React Aria) are the behaviour reference
([existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)
section 4).

## Goal

Ship the basic controls in `@link-foundation/ui-components`. Each control has
a LiNo schema (kind entry), a state machine, ARIA and keyboard behaviour,
token-based styles, unit and browser tests and a gallery story.

## Scope

### In scope

Controls (kind names in brackets):

- button (`button`), icon button (`icon-button`), label (`label`) and link
  (`link`);
- text field (`text-field`), text area (`text-area`), number field
  (`number-field`) and colour field (`color-field`, hex text plus the native
  colour picker), both needed by {{F37}};
- checkbox (`checkbox`, including the mixed state), radio group
  (`radio-group` with `radio` children), switch (`switch`);
- slider (`slider`), select / combobox (`select`, select-only combobox;
  `combobox` with a text input and filtering);
- progress (`progress`, determinate and indeterminate), badge (`badge`),
  avatar (`avatar`, image with initials fallback).

For every control:

- a kind entry in `src/controls/kinds.lino` in the {{F03}} vocabulary format;
- a machine in `src/controls/machines/<kind>.lino` (stateless kinds such as
  `badge` declare no machine);
- parts named after Open UI anatomy (`root`, `label`, `icon`, `indicator`,
  `input`, `track`, `thumb`, `listbox`, `option`) so {{F39}} templates can
  replace them;
- styles only through tokens (`color.*`, `space.*`, `shape.corner.*`,
  `motion.*` from {{F04}} and {{F11}}); states `hover`, `focus-visible`,
  `pressed`, `disabled`, `invalid`, `checked`;
- form participation: native `<input>`, `<textarea>` and `<button>` elements
  in light DOM, so `FormData` and browser autofill keep working;
- a story file and a catalog entry used by the gallery ({{F55}}).

### Out of scope

- Overlays, menus, tabs and toasts ({{F27}}); `select` uses a minimal
  positioned listbox here and moves onto the {{F27}} popover when it merges.
- Lists, trees, tables ({{F29}}), date and time pickers (later issue).
- Theme packs ({{F40}}–{{F43}}) and the theme engine ({{F39}}); this issue
  uses the default token values only.
- Icons themselves ({{F36}}); `icon-button` takes an icon name and renders a
  placeholder until {{F36}} merges.

## Dependencies

- Related: {{F27}}, {{F30}}, {{F36}}, {{F37}}, {{F38}}, {{F39}}, {{F55}},

- To start before F25 merges, write the kind entries, stories and pure value
  helpers (`clampStep`, `formatHex`) first; wire machines last.

## Step-by-step plan

1. Create `packages/ui-components/src/controls/` with `index.js` exporting
   `registerControls(registry?)`, which calls `defineKind` for every control.
2. Write the kind entries, for example:
   ```lino
   (button: kind
     (positional label)
     (property label string)
     (property variant (enum filled tonal outlined text))
     (property disabled boolean)
     (property on action multi)
     (machine button-machine)
     (role button))
   (slider: kind
     (property value number)
     (property min number)
     (property max number)
     (property step number)
     (property label string)
     (machine slider-machine)
     (role slider))
   ```
3. Shared numeric keys in `src/controls/numeric-keys.js` (pure):
   `/** @returns {number | null} */ nextValue(key, { value, min, max, step, shift })`
   for ArrowUp/Right, ArrowDown/Left, PageUp/PageDown (10 steps), Home/End and
   Shift (×10). `slider` and `number-field` both use it (behaviour from
   konard `numericKeys.js`).
4. Implement the controls in three pull requests (one issue, linked PRs):
   - A: `button`, `icon-button`, `label`, `link`, `badge`, `avatar`,
     `progress`;
   - B: `text-field`, `text-area`, `number-field`, `color-field`, `checkbox`,
     `radio-group`, `switch`;
   - C: `slider`, `select`, `combobox`.
5. Accessibility per control follows the APG pattern linked from the {{F04}}
   catalogue: `icon-button` requires `label` (a missing one is a diagnostic);
   `switch` uses `role="switch"` with `aria-checked`; `radio-group` uses one
   tab stop and arrow keys; `slider` sets `aria-valuenow`, `aria-valuemin`,
   `aria-valuemax`, `aria-valuetext`; `select` is a select-only combobox
   with `aria-expanded`, `aria-activedescendant` and typeahead; `progress`
   uses `role="progressbar"` and omits `aria-valuenow` when indeterminate;
   `link` rejects `javascript:` URLs via the {{F25}} `navigate` action.
6. Value changes update the store through `setProp` (one transaction per
   user change) and dispatch `(on change ...)` through the registry.
7. Styles in `src/controls/styles.css` use only token variables; add a
   `forced-colors: active` block and visible `:focus-visible` rings.
8. Stories in `packages/ui-components/stories/<kind>.lino`, for example:
   ```lino
   (button-stories: stories
     (component button)
     (story filled (button (label 'Save') (variant filled)))
     (story disabled (button (label 'Save') (disabled true))))
   ```
   and `src/controls/catalog.lino` with one entry per control:
   `(button: control (title 'Button') (stories button-stories) (apg button))`.
9. Gallery page `packages/ui-components/e2e/pages/controls.html` that renders
   every story; browser tests in `packages/ui-components/e2e/controls.e2e.mjs`.

## Acceptance criteria

- [ ] Every control listed in scope has a kind entry, a story file, a
      catalog entry and a test file; `catalog.test.js` fails if one is missing.
- [ ] `numeric-keys.test.js` covers every key, Shift ×10, clamping to
      min/max and step rounding.
- [ ] Unit tests (jsdom) check the ARIA attributes per state for each
      control, for example `switch` toggles `aria-checked` on Space and Enter.
- [ ] `controls.e2e.mjs` operates every control with the keyboard only in
      Chromium and WebKit, following the {{F04}} keyboard summary for its kind.
- [ ] `expectAccessible(page)` reports no violations on `controls.html`.
- [ ] `screenshotMatrix(page, 'controls', { themes: ['light', 'dark'], locales: ['en', 'ru'] })`
      baselines are committed.
- [ ] A form containing every input control submits the expected
      `FormData` (e2e test).
- [ ] A plain letter typed in `text-field` never triggers a shortcut
      (test with a bound key).
- [ ] `grep -rE "#[0-9a-fA-F]{3,8}\b" packages/ui-components/src/controls/styles.css`
      is empty (tokens only).
- [ ] `npm test`, `npm run lint`, `npm run format:check`,
      `npm run check:duplication` pass.

## How to verify

```bash
node --test packages/ui-components/tests/controls/*.test.js
npx playwright test packages/ui-components/e2e/controls.e2e.mjs
npm test && npm run lint && npm run format:check && npm run check:duplication
```

Open `controls.html` from the static server of {{F05}} and tab through all
controls; attach light and dark screenshots to each pull request.

## Prior art and libraries

- Zag.js and Ark UI (MIT): machines and part names; React Aria
  (Apache-2.0): behaviour bar (existing-solutions.md section 4).
- Open UI (W3C community group): anatomy and part names.
- konard.github.io `Select.jsx`, `NumberInput.jsx`, `ColorInput.jsx`,
  `numericKeys.js` (research section 4.1);
  https://github.com/konard/konard.github.io/issues/39 says "all UI
  elements must be owned by us".
- immortality `Select`, toggle, range with `<output>`, swatch fieldset
  (research sections 5 and 6).
- Material 3, Fluent 2 and Apple HIG component guidance through {{F04}};
  never depend on Material Web.
- WAI-ARIA APG patterns: button, checkbox, radio group, switch, slider,
  combobox, listbox, link (https://www.w3.org/WAI/ARIA/apg/patterns/).
