## Context

R4 asks for animation recording, with recordings stored as Links Notation.
R7 asks for the simplest description, sharable by default. The verified
sample
https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/samples/animation.lino
shows the target shape:

```lino
(recording-1: recording
  (started '2026-11-01T12:00:00Z')
  (event 0ms (set ok label 'OK'))
  (event 840ms (input pointer down ok))
  (event 990ms (set ok label 'Saved')))
```

None of our repositories records anything today: immortality and
anime-avatar have no recording or timeline. Their animations are pure
functions of time, though, and that makes the design simple: **record the
clock, the inputs, the state changes and the seed, not the pixels**.
Playback re-evaluates the pure functions, so recordings are small, diffable
and reproducible
([immortality-and-anime-avatar.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md),
migration note 6).

deepcase points the same way. Its window and focus state
(`Opened`, `Focus`, `Traveler`) is links, so timestamped changes to it are a
recording too
([deepcase.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/deepcase.md)
section 11).

rrweb (MIT) records DOM mutations. It is useful for comparison, but it is not
our format
([existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)).

## Goal

Add a recorder and a deterministic replayer to `@link-foundation/ui-animation`.

- The recorder captures store diffs, user input events and animation starts
  as timestamped LiNo events, together with the seed, the clock origin and
  the viewport.
- Replay reproduces the same state at every time `t`, and it can seek both
  forward and backward.
- A verifier replays only the inputs and proves that they regenerate the
  recorded state changes.
- A recording can be exported as a Playwright test.

## Scope

### In scope

- The recording format:
  - header fields `started`, `seed`, `viewport`, `document` (the id of the
    recorded document), `snapshot` (the initial state as LiNo) and
    `redacted`;
  - `event` links with a relative time in ms;
  - event kinds `set`, `insert`, `remove` and `move` (from {{F08}}),
    `input` (pointer, key, wheel, text, focus), `play` and `cancel` (from the
    {{F44}} player), and `mark` (a user label).
- `createRecorder(...)`, `replay(...)`, `stateAt(recording, t)` and
  `verifyReplay(recording, ...)`.
- Coalescing. Pointer moves are throttled to at most 60 per second, text
  input is merged per field, and every timestamp is an integer in ms.
- Redaction is on by default. Values from `password` fields and from fields
  marked `(sensitive true)` are recorded as `'***'`.
- `toPlaywright(recording)`, which generates a Playwright spec.
- Optional comparison script: `experiments/recorder/vs-rrweb.mjs`. It
  records the same scripted session with rrweb (a devDependency of the
  experiment only) and prints both sizes.

### Out of scope

- Video, screen or MediaRecorder capture, which is pixels, not links.
- The timeline editor UI ({{F49}}) and the dev mode recording button
  ({{F46}}).
- Persisting recordings to IndexedDB ({{F09}}). This issue returns text, and
  the caller saves it.
- rrweb as a runtime dependency, and any rrweb import or export in the
  shipped package.

## Dependencies

- {{F44}} (blocker). Supplies the player's `play`/`cancel` hooks, used to
  record animation starts; `sample(animation, t, { seed })`, used to
  re-evaluate animations during replay; and `seededRandom`.
- {{F08}} (blocker). Supplies the store change events (insert, update,
  remove, move), transactions, `snapshot()` and `restore()`, and stable IDs.
  Use the event shape actually merged. Until then, a stub store with
  `subscribe` and `apply(diff)` in `tests/helpers/fake-store.js` is enough.
- Indirect: {{F06}} (parse and serialise LiNo) and {{F16}}
  (`handle.idFor(node)`, which maps DOM input targets to link IDs).
- Related: {{F09}}, {{F46}}, {{F49}}, {{F63}} (anime-avatar gestures),
  {{F64}}, {{F05}} (the Playwright harness for generated specs).

## Step-by-step plan

1. Write `src/recorder/format.js`, which provides
   `parseRecording(text) -> Recording` and
   `serializeRecording(recording) -> string`. Both use `links-notation`;
   never use regular expressions. This is the full form:
   ```lino
   (session-7: recording
     (started '2026-11-01T12:00:00Z')
     (seed 42)
     (viewport 1280 800)
     (document app)
     (redacted true)
     (event 0ms (set ok label 'OK'))
     (event 840ms (input pointer down ok (at 12 8)))
     (event 841ms (play press-feedback (target ok)))
     (event 990ms (set ok label 'Saved'))
     (event 1500ms (input key down Enter (target ok)))
     (event 2100ms (mark 'saved once')))
   ```
   `serializeRecording(parseRecording(x))` must equal `x` for the canonical
   form.
2. Write `src/recorder/recorder.js`:

   ```js
   /** @param {{ store: Store, player?: Player, root?: Element, handle?: DomHandle,
    *   clock?: { now(): number }, seed?: number, redact?: boolean,
    *   maxEvents?: number }} options
    * @returns {{ start(): void, stop(): string, mark(label: string): void, size(): number }} */
   export function createRecorder(options) {}
   ```

   - `start()` snapshots the store and stores the snapshot.
   - The recorder subscribes to the store, the player and DOM input events on
     `root`, which are captured in the capture phase and passive.
   - Each DOM target maps to a link ID with `handle.idFor`. Pointer
     coordinates are recorded relative to the target box.
   - `maxEvents` (default 100,000) turns the buffer into a ring buffer and
     adds a `(truncated true)` header.

3. Write `src/recorder/state-at.js`, which provides
   `/** Pure. */ stateAt(recording, tMs) -> Snapshot`. It restores the
   initial snapshot and applies every diff with time `<= tMs`.
   `animationsAt(recording, tMs)` lists the running animations with their
   local time, so the {{F44}} `sample()` can give the exact visual values.
4. Write `src/recorder/replay.js`:

   ```js
   /** @param {string | Recording} recording
    * @param {{ store: Store, player?: Player, clock?: ManualClock }} options
    * @returns {{ play(): Promise<void>, pause(): void, seek(ms: number): void,
    *   readonly time: number, readonly duration: number }} */
   export function replay(recording, options) {}
   ```

   - Seeking backward uses `stateAt` from the snapshot, not undo.
   - The clock is injected. Tests use `createManualClock()`, where
     `advance(ms)` runs due events in order, and ties keep file order.
   - A player seeded with the recording's `seed` reproduces procedural
     effects such as `decipher`.

5. Write `src/recorder/verify.js`, which provides
   `verifyReplay(recording, { createApp }) -> { ok: boolean, mismatches: Array<{ time, expected, actual }> }`.
   It builds a fresh app with `createApp(seed)`, dispatches only the `input`
   events at their times on a manual clock, records again, and compares the
   resulting `set`, `insert`, `remove` and `move` events.
6. Write `src/recorder/to-playwright.js`, which provides
   `toPlaywright(recording, { url }) -> string`. It generates a spec that
   opens `url`, clicks and types at the recorded targets using
   `[data-link-id="ok"]` selectors, and asserts the recorded `set` values.
   `mark` events become `test.step` names.
7. Wire `examples/animation/` from {{F44}}: add Record, Stop, Replay and a
   scrubber (`<input type="range">`) that calls `seek`. Show the LiNo
   recording in a `<pre>`.
8. Add the optional `experiments/recorder/vs-rrweb.mjs`, the README section
   "Recording format", tests and a changeset.

## Acceptance criteria

- [ ] `recording-format.test.js`: `recording-1` from `samples/animation.lino`
      and the step 1 example parse, and serialising them round-trips to
      identical text.
- [ ] `recorder.test.js`: a scripted session with a manual clock
      (`set`, a pointer down on `ok`, `play`, `set`) produces exactly the
      events and timestamps of the step 1 example.
- [ ] 1,000 pointer moves within one second are coalesced to at most 60
      `input pointer move` events.
- [ ] `redact.test.js`: text typed in a `password` field is stored as `'***'`
      by default and stored as typed when `redact: false`.
- [ ] `state-at.test.js`: `stateAt(r, 900)` has label `'OK'` and
      `stateAt(r, 990)` has label `'Saved'`. Seeking 990 → 0 → 990 gives
      equal snapshots.
- [ ] `replay.test.js`: replaying the same recording twice gives identical
      store snapshots and identical `sample()` values at every event time,
      including a `decipher` effect with `seed 42`.
- [ ] `verify.test.js`: `verifyReplay` returns `ok: true` for a
      deterministic fixture app, and reports a mismatch when the fixture uses
      `Date.now()` internally.
- [ ] `to-playwright.test.js`: the generated spec matches a snapshot.
      `tests/e2e/recorder.spec.js` runs a generated spec against the example
      and it passes in Chromium.
- [ ] `npm ls rrweb` shows no dependency of any `packages/*` package.
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication` and
      `npm test` pass.

## How to verify

```bash
npm install
node --test packages/ui-animation/tests/*.test.js
npx playwright test tests/e2e/recorder.spec.js
node experiments/recorder/vs-rrweb.mjs   # optional, prints both sizes
npm test
```

Manual check: in `examples/animation/`, record a session, then drag the
scrubber backwards and forwards. The UI must match the state at each time,
with no drift between runs.
