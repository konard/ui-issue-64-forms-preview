## Context

The framework is a runtime interpreter of a links network with thin renderers
per platform (principle 4 of
[`docs/ARCHITECTURE.md`](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md)).
The web reference renderer is `@link-foundation/ui-dom`: plain JavaScript,
custom elements (Web Components), no framework. React ({{F18}}) and Vue
({{F19}}) adapters wrap it, components ({{F25}}, {{F26}}, {{F27}}) plug into it,
and dev mode ({{F46}}) depends on one property of it: every rendered node
carries the stable link ID of the element it came from (principle 6).

The research recommends "Web Components (Lit or plain custom elements) as the
reference vanilla-JS renderer" and warns against heavy code generation
(section "Recommendations" A.2 and C in
[existing-solutions.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md)).
konard.github.io and immortality show that projecting state to `data-*`
attributes and CSS variables works the same for plain JS, React and Vue
([konard-github-io-and-links-visuals.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md)
pattern 3,
[immortality-and-anime-avatar.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/immortality-and-anime-avatar.md)
pattern 9).

## Goal

Create `packages/ui-dom/` that renders a `ui-store` links network into the DOM
as custom elements, keeps it in sync incrementally from store change events,
applies resolved styles from `ui-style`, dispatches declared actions as data,
and marks every node with `data-link-id`.

## Scope

### In scope

- `render(container, store, options)` and the convenience
  `mountDocument(container, linoText, options)` (parse with `ui-core`, create a
  store, render).
- Custom elements with the `ui-` prefix for the basic kinds needed by the
  dialect samples: `document`, `stack`, `text`, `button`, `image`, plus a
  `ui-unknown` fallback for kinds without a registered renderer.
- A kind registry (`defineKind`) so components and adapters add kinds without
  touching the renderer.
- Incremental updates: insert, update, remove and move of elements, batched in
  one microtask per store transaction.
- `data-link-id` on every element node; `handle.nodeFor(id)` and
  `handle.idFor(node)` lookups.
- Styles: inject the stylesheet produced by `ui-style` ({{F12}}) and token CSS
  custom properties ({{F11}} output) with `adoptedStyleSheets` (fallback:
  one `<style>` element).
- Events: `(on press (navigate home))` dispatches a `ui-action` `CustomEvent`
  and calls `options.onAction`. Handlers are data, never code.
- `renderToHTML(store | tree, options)`: static HTML string export with the same
  tags and `data-link-id` attributes (no hydration).

### Out of scope

- Full controls, state machines and accessibility behaviour ({{F25}}, {{F26}},
  {{F27}}). The basic `button` here is a native `<button>` inside `ui-button`.
- Layout primitives beyond `stack` ({{F28}}), animation ({{F44}}), dev mode
  overlay ({{F46}}).
- Hydration of server-rendered HTML; Shadow DOM per kind (may be added later
  per kind).
- Lit or any other runtime library: use plain custom elements (zero runtime
  dependencies besides workspace packages and `links-notation`).

## Dependencies

- {{F08}} (blocker): the store API — read the tree, `subscribe(listener)` to
  change events, transactions, stable IDs for every element including
  anonymous ones. F08 calls each listener once per committed transaction with
  an array of events shaped like
  `{ type: 'insert' | 'update' | 'remove' | 'move' | 'rename', id, parentId, index, props }`;
  adapt to the event shape actually merged in F08.
- {{F12}} (blocker): the style resolver — a compiled stylesheet (or resolved
  declarations per element and state) from LiNo `style` links such as
  `docs/case-studies/issue-1/samples/styles.lino`.
- Indirect: {{F06}} (`parse` to the element tree, used by `mountDocument`),
  {{F11}} (token CSS custom properties).
- Related: {{F05}} (Playwright and axe harness), {{F17}} (HTML import, the
  reverse direction), {{F18}}, {{F19}}, {{F25}}, {{F46}}, {{F54}}.
- To start before F12 merges, inject styles through `options.styles` (a CSS
  string) and add the F12 call in the last step.

## Step-by-step plan

1. Create `packages/ui-dom/package.json` (`"name": "@link-foundation/ui-dom"`,
   `"type": "module"`, `exports` for `.` and `./html`), `README.md` and
   `src/index.d.ts`. Dependencies: `@link-foundation/ui-core`,
   `@link-foundation/ui-store`, `@link-foundation/ui-style` (workspace).
   Dev dependency for tests: `jsdom` (MIT).
2. `src/kinds.js`: a registry.
   ```js
   /**
    * @typedef {object} KindSpec
    * @property {string} tag  custom element name, e.g. 'ui-button'
    * @property {(el: UiNode, ctx: RenderContext) => Element} create
    * @property {(node: Element, el: UiNode, changed: string[], ctx: RenderContext) => void} update
    * @property {(node: Element) => Element | null} [childrenSlot] where children go; null = no children
    * @property {(node: Element) => void} [destroy]
    */
   /** @param {string} kind @param {KindSpec} spec */
   export function defineKind(kind, spec) {}
   ```
   Registering a tag calls `customElements.define` only if
   `customElements.get(tag)` is undefined, so importing twice is safe.
3. `src/kinds/basic.js`: `document` (`ui-document`, sets `document.title` only
   when `options.setTitle` is true), `stack` (`direction`, `gap` as CSS
   `flex-direction` and `gap`), `text` (text content), `button` (native
   `<button type="button">` child, `label`, `variant` mirrored to an attribute
   for style selectors, `disabled`), `image` (`<img>` with `src` and `alt`;
   an `image` without `alt` gets `alt=""` and a diagnostic), `unknown`.
4. `src/render.js`: walk the store tree, create nodes, set
   `data-link-id="<id>"` on every element, keep `Map<id, Element>` and a
   `WeakMap<Element, id>`. Return
   `{ nodeFor(id), idFor(node), flush(), destroy() }`.
5. `src/patch.js` and `src/scheduler.js`: on each store change event, queue a
   patch; apply all queued patches in one microtask (`queueMicrotask`).
   `update` re-uses the existing node and calls `spec.update` with the changed
   prop names only; `move` uses `insertBefore`; `remove` calls `spec.destroy`
   and drops map entries; `rename` rewrites `data-link-id` and both maps. `flush()` applies the queue synchronously (tests).
6. `src/events.js`: for each `(on <event> <action...>)` prop, attach a listener
   for the mapped DOM event (`press` = `click` on the native button, plus
   Enter/Space through the native button). Dispatch
   `new CustomEvent('ui-action', { bubbles: true, composed: true, detail })`
   with `detail = { source: 'ok', event: 'press', action: ['navigate', 'home'] }`
   and call `options.onAction?.(detail)`. Never call `eval`, `new Function`
   or set `on*` attributes from document text.
7. `src/styles.js`: build one `CSSStyleSheet` from the F12 output and token
   variables; adopt it on the container's root node; selectors use the custom
   element tag plus attributes, e.g. `ui-button[variant="filled"]`. Light DOM
   is used so that page CSS, dev mode and native form participation work.
8. `src/html.js`: `renderToHTML(source, { kinds })` returns a string such as
   `<ui-document data-link-id="app"><ui-stack data-link-id="body" ...>`. Escape
   text and attribute values; never emit `on*` attributes or `<script>`.
9. `mountDocument(container, text, options)` in `src/index.js`: parse with
   `ui-core`, build a store with `ui-store`, call `render`, return
   `{ store, handle }`.
10. Example page `examples/ui-dom/index.html` + `main.js` that mounts
    `docs/case-studies/issue-1/samples/document.lino` with the sample styles
    and tokens, and a button that changes `greeting` through the store.
11. Write the tests listed below, the README (API, kind registry, decision
    "plain custom elements, light DOM" with the reasons above) and a changeset.

## Acceptance criteria

- [ ] `render.test.js`: `samples/document.lino` renders
      `ui-document > ui-stack > (ui-text, ui-button)` and matches
      `tests/__snapshots__/document.html`.
- [ ] Every rendered element node has `data-link-id`; for every store ID
      `handle.idFor(handle.nodeFor(id)) === id` (test iterates all IDs).
- [ ] `incremental.test.js`: changing `greeting` text mutates only the
      `ui-text` node (asserted with a `MutationObserver`), and the node keeps its
      identity; insert, remove and move each have a test.
- [ ] 1,000 updates in one store transaction produce one patch flush (counted).
- [ ] `events.test.js`: clicking the `ok` button calls `onAction` with
      `{ source: 'ok', event: 'press', action: ['navigate', 'home'] }` and a
      bubbling `ui-action` event; a prop value like `'alert(1)'` is never
      executed (`grep -rE "eval\(|new Function" packages/ui-dom/src` is empty).
- [ ] An unknown kind renders `ui-unknown` with `data-kind` and a diagnostic;
      rendering does not throw.
- [ ] `styles.test.js`: the F12 stylesheet and token variables are adopted once
      per root; `ui-button[variant="filled"]` receives the
      `--color-primary`-style variable produced by F11 (check the real name).
- [ ] `handle.destroy()` removes all nodes and the store listener (listener
      count returns to 0).
- [ ] `html.test.js`: `renderToHTML` of the sample equals a snapshot, contains
      `data-link-id` for every element and escapes `<`, `&` and quotes.
- [ ] A screenshot of `examples/ui-dom/index.html` in Chromium is attached to
      the pull request.
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication` and
      `npm test` pass.

npm install

  https://developer.mozilla.org/docs/Web/API/Web_components (ADOPT).
