## Context

Issue #1 asks for "a WYSIWYG editor based entirely on Links Notation" (R5) and
"full support for an industry-leading WYSIWYG editor, similar to Visual Studio
... but we do it our way" (R10).
[`docs/ARCHITECTURE.md`](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md)
says the designer reuses the dev mode inspector ({{F46}}) and adds a toolbox,
canvas drag and drop, alignment guides, multi-select, undo/redo, docked panels,
two-way source sync and a timeline ({{F49}}), and is built with the framework
itself.

The research
([existing-solutions.md section 3](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/existing-solutions.md))
recommends our own designer over the LiNo tree with the standard panel
architecture: Toolbox/Blocks, Layers/Outline, Properties/Traits, Styles/Tokens.
The reference UX is the Visual Studio designers (Toolbox, categorised
Properties grid, Document Outline, snaplines, Live Visual Tree). GrapesJS
(BSD-3-Clause) and Puck (MIT) are design references only; they must not become
the source of truth. **Do not use** the tldraw SDK (production licence key
since 4.0), Plasmic `platform/` code, ToolJet or any other AGPL code.

The source of truth is a LiNo document such as
[`samples/document.lino`](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/samples/document.lino).
Links Notation drops comments on parse, so the designer writes back through
the source-preserving editor from {{F14}}
([links-notation-ecosystem.md section 5.4](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)).

## Goal

A package `@link-foundation/ui-designer` (`packages/ui-designer/`) that opens a
LiNo document, renders it on a canvas, and lets the user build and change the
UI visually, with every change written to the LiNo source without losing
comments, and every change undoable.

## Scope

### In scope

Delivered in four milestones. If the pull request would exceed about 1,500
changed lines, open one pull request per milestone (`Part of` this issue; the
last one says `Fixes`).

- **M1 Shell.** Designer layout described in LiNo (`src/designer.lino`) and
  rendered with the framework: docked panels from {{F28}} (left: Toolbox and
  Outline; centre: Canvas; right: Properties from {{F46}}; bottom: Source),
  resizable, collapsible, layout persisted in the `user` layer. Design mode and
  Run mode toggle (in Design mode clicks select, in Run mode the UI works).
- **M2 Editing.** Toolbox generated from the component catalog of {{F26}}
  (one item per component, with icon and name), drag from toolbox to canvas or
  Outline to insert, drag on canvas or Outline to move, delete, duplicate,
  cut/copy/paste of LiNo fragments, multi-select (Shift+click, Ctrl/Cmd+click,
  marquee), undo/redo (`Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z`) using the ui-store
  transactions from {{F08}}. One user gesture is one transaction.
- **M3 Layout aids.** Alignment guides and snapping to sibling edges and
  centres (threshold 6 CSS pixels, configurable), drop indicators for flow
  layouts (stack/grid insert position), resize handles for elements with
  explicit size, keyboard nudging (arrows 1 px, Shift+arrows 10 px).
- **M4 Two-way sync.** Canvas edits are written to the LiNo text via {{F14}};
  text edits in the Source panel are parsed, diffed against the store and
  applied as one transaction that keeps stable ids. Parse errors are shown with
  line and column and do not destroy the canvas state.
- Accessibility: every canvas action has a keyboard path (select in Outline,
  `Alt+Up/Down` to reorder among siblings, `Enter` on a toolbox item inserts
  into the selected container).
- Save and open: open a `.lino` file (file input), save by download and copy;
  the draft is kept in the store so reload restores it.

### Out of scope

- Animation timeline: {{F49}}.
- Pages not built with the framework: {{F50}}.
- Code export: {{F52}}. Imports: {{F51}}.
- Real-time collaboration, design-time data and variant matrices (follow-ups).

## Step-by-step plan

1. Create `packages/ui-designer/` (`package.json` named
   `@link-foundation/ui-designer`, `src/`, `tests/`, `examples/`).
2. `src/commands.js` (pure): `insertElement(store, { parentId, index, type, props })`,
   `moveElements(store, { ids, parentId, index })`, `removeElements(store, ids)`,
   `duplicateElements(store, ids)`, `setProperty(store, id, name, value)`.
   Each runs in one store transaction and returns the new ids. Drop rules come
   from the catalog: `canContain(catalog, parentType, childType)`.
3. `src/selection.js` (pure): selection set, anchor, `toggle`, `range`,
   `marquee(rects, box)`.
4. `src/snap.js` (pure):
   `computeSnap(moving, others, { threshold = 6 })` returns
   `{ dx, dy, guides: [{ axis, position, from, to }] }`; edges and centres.
5. `src/sync.js`: `canvasToSource(sourceText, change)` uses {{F14}};
   `sourceToStore(store, text)` parses, maps ids, applies a diff in one
   transaction; on error returns `{ error: { line, column, message } }`.
6. `src/designer.lino` and `src/designer.js`: the shell (M1), wiring panels,
   overlay and commands. `mountDesigner({ root, documentText })` returns
   `{ getText(), undo(), redo(), destroy() }`.
7. `src/canvas.js`: pointer-based drag and drop (Pointer Events, pointer
   capture), drop indicator, guides rendering, design/run mode.
8. `examples/index.html`: designer opened on the sample document.
9. Tests per module; Playwright scenarios for each milestone.

Example: dragging a `text` from the toolbox between `greeting` and `ok` of the
sample document and setting its text produces (every other line of the source,
including comments in real files, stays byte-for-byte unchanged):

```lino
(app: document
  (title 'Links UI demo')
  (theme material3)
  (body: stack
    (direction vertical)
    (gap (token space.medium))
    (greeting: text 'Hello, links')
    (text-1: text 'New text')
    (ok: button
      (label 'OK')
      (variant filled)
      (on press (navigate home)))))
```

## Acceptance criteria

- [ ] M1: the shell renders with four docked panels, panels resize and
      collapse, layout survives reload; screenshot attached.
- [ ] M2: insert, move, delete, duplicate, copy/paste and multi-select work on
      canvas and in Outline; every one is undone and redone by one
      `Ctrl/Cmd+Z` / `Ctrl/Cmd+Shift+Z`.
- [ ] M2: dropping a child into an element whose catalog entry does not allow
      it is refused with a visible indicator.
- [ ] M3: `computeSnap` unit tests cover left, right, centre and middle
      alignment and the threshold; guides appear in the Playwright test.
- [ ] M4: for every fixture, a canvas edit keeps all comments of the input
      file and the output parses to the expected links.
- [ ] M4: editing the Source panel updates the canvas; an invalid edit shows
      line and column and leaves the canvas unchanged.
- [ ] All canvas actions are possible with the keyboard; axe reports no
      violations on the designer page.
- [ ] No dependency with a non-permissive licence (`npm ls` reviewed in the
      pull request).
- [ ] `npm run lint`, `npm run format:check`, `npm run check:duplication`,
      `npm test` pass.

## Prior art and libraries

- Visual Studio WinForms/WPF designers, XAML Live Visual Tree (UX target).
- GrapesJS (BSD-3-Clause): block, style, layer and trait managers.
- Puck (MIT), Craft.js (MIT): component config plus serialised tree.

  Studio (learn only, GPL/commercial).
