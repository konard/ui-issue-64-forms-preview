## Context

Every UI concept in this framework (element, property, style rule, token, theme, behaviour, animation, recording, override, asset record) is a link, and Links Notation (LiNo) is its only canonical text form (principles 1–3 of [`docs/ARCHITECTURE.md`](https://github.com/link-foundation/ui/blob/main/docs/ARCHITECTURE.md)). The samples in [`docs/case-studies/issue-1/samples/`](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/samples/) show the intended _UI dialect_, but nothing defines it yet. The JavaScript core ({{F06}}, {{F07}}), the Swift ({{F21}}) and Kotlin ({{F23}}) parsers and every renderer need one written contract and one shared set of fixtures.

The research found concrete gaps that must be closed here (sections 4–6 of [links-notation-ecosystem.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/links-notation-ecosystem.md)): typed values, units and colours, `:` and `#` in values, ordering, ids and scoping, reference sigils, schemas, expressions and bindings, and security limits. Facts measured with `links-notation` 0.27.1 (re-run them; check the current version):

- Parse shapes differ ([`experiments/issue-1/lino-parse-shapes.mjs`](https://github.com/link-foundation/ui/blob/main/experiments/issue-1/lino-parse-shapes.mjs), section "Links Notation parse shapes" of ARCHITECTURE.md). `(ok: button (label 'OK'))` on one line is one nested link. The same text split over lines inside parentheses gives path links `(ok: button)`, `((ok: button) (label OK))`. The indented form gives the same path links from `parse()`, and a real tree only from `parseGroups()`.
- `(x #6750A4)` is a syntax error (the comment swallows `)`); `(x '#6750A4')` works.
- `(t a:b)` is a syntax error; `(t 'a:b')` works.
- `(t 1 '1')` gives two equal references `1`: the quoted/bare distinction is lost.
- `(a: b)` followed by `(a: c)` parses without error (duplicate ids are not detected).
- `@color.primary`, `$draft.text` and `button.save` are plain references; no sigil has a meaning.

## Goal

Publish `docs/spec/` as version `ui-dialect/0`: a normative description of how LiNo links map to a UI element tree, plus language-neutral conformance fixtures (`.lino` input and expected element tree JSON) that the JS, Swift and Kotlin implementations must all pass. Every open question in research section 5 is either decided or listed in `docs/spec/open-questions.md` with an owner issue.

## Scope

### In scope

- Element model: `(id: kind positional-values... (property ...)... child-elements...)`.
- The **tree projection** that turns all three parse shapes into the same tree.
- The rule that classifies a sublink as property, child element, or unknown.
- The value grammar and its JSON form: references, numbers, dimensions, durations, colours, token references, actions.
- A machine-readable vocabulary (`docs/spec/vocabulary.lino`) listing the v0 kinds, their properties and the multi-valued properties. It covers the samples: `document`, `stack`, `text`, `button`, `image`, `theme`, `style`, `animation`, `recording`, `overrides` and `asset`.
- Diagnostics: codes, severities, and where they point.
- Limits: maximum depth, maximum input size, and "handlers are names, never code".
- At least 30 fixtures and a checker script with a test.

### Out of scope

- The `ui-core` implementation of the projection ({{F06}}) and typed value parsing ({{F07}}).
- Source-preserving edits and comment round trips ({{F14}}).
- The full settings schema engine ({{F15}}).
- The style cascade ({{F12}}) and token export ({{F11}}).

## Dependencies

No blockers; start immediately. `links-notation` is already in `node_modules` as a transitive dependency. Add it as a root `devDependency` (check the current version; the research used 0.27.1).

Related:

## Step-by-step plan

1. Create `docs/spec/README.md`. Cover the version string `ui-dialect/0`, the RFC 2119 keywords, the list of documents, and how fixtures are named.
2. Write `docs/spec/elements.md`. An element is a link whose id is the element id and whose first value is its kind. Then define how the remaining values are read:
   - atoms after the kind are positional values (`(greeting: text 'Hello, links')`);
   - a sublink with an id (`(body: stack ...)`) is a child element;
   - a sublink without an id is a **property** when its head is declared for the parent kind in `vocabulary.lino`;
   - otherwise it is an **anonymous child** when its head is a registered kind;
   - otherwise it is kept verbatim with the diagnostic `unknown-sublink` (warning).

   Decide, and write down, that the kind is the first value, never an id prefix (`button.save:` is just an id with a dot).

3. Write `docs/spec/projection.md`. It must say:
   - Implementations MUST project `parse()` output by **path folding**: a link without an id whose first value is a link structurally equal to an already-seen element head (or to a path made of them) appends its other values to that element or sublink.
   - `parseGroups()` MAY be used where available; the result MUST be identical.
   - Give the algorithm in pseudocode, plus the worked example of the four links `(ok: button)`, `((ok: button) (label OK))`, `((ok: button) (on press))` and `(((ok: button) (on press)) (navigate home))`.
4. Write `docs/spec/values.md`:
   - **Typing is schema-driven:** the vocabulary declares each property type. Quoting never changes a type, because the parser loses it.
   - **Types:** `string`, `number` (`-1`, `1.5e3`), `dimension` (`16px`, `1.5rem`, `50%`; units px, rem, em, %, vw, vh), `duration` (`150ms`, `0.2s`), `color`, `enum`, `token-ref`, `element-ref` and `action`.
   - **Colours** are quoted hex (`'#6750A4'`, `'#6750A4CC'`) or `(oklch 0.6 0.2 300)` / `(rgb 103 80 164)`. A bare `#` is invalid.
   - **No `:` in bare values.** Use structured links instead: `(state hover)`, `(media (max-width 640px))`, `(aspect 16 9)`. Quote URLs.
5. Decide the **reference form** in `values.md`. Canonical v0 is the structured form used by the samples: `(token color.primary)`, `(param draft.text)` and an element id as a bare reference. The prefixes `@` and `$` are reserved: a value starting with them gives the diagnostic `reserved-sigil` until a later version defines them as shorthand. Also document:
   - resolution order: theme chain, then base;
   - a cycle gives the error `reference-cycle`;
   - fallbacks use `(or (token a) (token b) 8px)`.
6. Write `docs/spec/ordering-and-ids.md`:
   - Children and multi-valued properties (`on`, `token`, `track`, `key`, `event`, `set`) are ordered sequences.
   - Single-valued properties are a set: a repeated property means the last one wins, with a `duplicate-property` warning.
   - Element ids are unique per document; a duplicate gives the error `duplicate-id`.
   - A dot in a token name is a path separator. A dot in an element id has no meaning.
   - Cross-document references are deferred to `open-questions.md`.
7. Write `docs/spec/behaviour.md`:
   - Shape: `(on <event> <action>...)`, where an action is a link whose head is a vocabulary action (`navigate`, `emit`, `set`, `toggle`, `focus`).
   - Bindings are reserved as `(bind <property> (param path))`.
   - Conditions (`when`) and expressions are deferred and recorded.
   - Handlers are data and are never evaluated as code. `navigate` targets are ids or quoted URLs; renderers MUST reject the `javascript:` scheme.
8. Write `docs/spec/limits.md`:
   - depth at most 64 (the `links-notation` default `maxDepth`);
   - a `maxInputSize` value that you choose and record (for example 1 MiB; check the parser option name in the current version);
   - unknown kinds render as an inert placeholder and are never executed.
9. Write `docs/spec/vocabulary.lino`, one link per kind. A sketch:

   ```lino
   (button: kind
     (positional label)
     (property label string)
     (property variant (enum filled outlined text))
     (property on action multi)
     (children none))
   ```

10. Write `docs/spec/element-tree.schema.json` (JSON Schema 2020-12) for the expected trees. Use this shape:

    ```json
    {
      "spec": "ui-dialect/0",
      "elements": [
        {
          "id": "ok",
          "kind": "button",
          "positional": [],
          "properties": [
            { "name": "label", "values": ["OK"] },
            { "name": "on", "values": ["press", ["navigate", "home"]] }
          ],
          "children": []
        }
      ],
      "diagnostics": []
    }
    ```

    In this shape:
    - a reference atom is a JSON string;
    - a nested non-element link is a JSON array;
    - an anonymous element has `"id": null`;
    - properties keep source order.

11. Add fixtures under `docs/spec/fixtures/<area>/<name>.lino`, each with a sibling `<name>.tree.json`, or `<name>.diagnostics.json` for invalid input. Areas and minimum counts:
    - `shapes/`: one-line, multi-line and indented forms of the same document, all with one identical tree (at least 3);
    - `elements/` (5);
    - `properties/` (5), including duplicates;
    - `values/` (6): colours, dimensions, durations, URLs and `(or ...)`;
    - `references/` (3), including `reserved-sigil`;
    - `behaviour/` (3);
    - `errors/` (5): `duplicate-id`, `unknown-sublink`, `reference-cycle`, depth over the limit, and unquoted hex as a syntax error;
    - a copy of each sample in `docs/case-studies/issue-1/samples/`.
12. Write `docs/spec/open-questions.md`. List each undecided point with the alternatives and an owner issue:
    - comments on round trip ({{F14}});
    - asking upstream for a `quoted` flag on references;
    - whether the multi-line path expansion is intended upstream (open an issue at https://github.com/link-foundation/links-notation/issues if none exists, and link it);
    - cross-document ids;
    - expressions and `when`;
    - links-theory doublet mapping of the element tree.
13. Add `scripts/check-spec-fixtures.mjs` and `tests/spec-fixtures.test.js`. The script:
    - parses every `.lino` with `links-notation`; files in `errors/` named `syntax-*` must throw, all others must parse;
    - checks that every `.lino` has exactly one sibling JSON;
    - validates each JSON against the schema (with `ajv`, MIT, as a devDependency, or a hand-written check);
    - checks that all `shapes/*.tree.json` files in a group are byte-equal.

## Acceptance criteria

- [ ] All eight documents listed above exist under `docs/spec/`, and each uses MUST/SHOULD/MAY wording.
- [ ] Each research gap is either decided in a spec document or listed in `open-questions.md` with an owner issue: typed values, units, colours, `:`/`#`, ordering, ids/scoping, sigils, schemas, expressions/bindings, security, and the three section 6.5 decisions.
- [ ] `docs/spec/fixtures/` contains at least 30 `.lino` files, each with exactly one `.tree.json` or `.diagnostics.json`.
- [ ] `shapes/` proves that one-line, multi-line and indented input give byte-identical trees.
- [ ] Every sample from `docs/case-studies/issue-1/samples/` has a fixture.
- [ ] `npm run check:spec` exits 0; `node --test tests/spec-fixtures.test.js`, `npm run lint` and `npm run format:check` pass.
- [ ] Every LiNo snippet in `docs/spec/*.md` parses with `links-notation`; the checker also extracts fenced `lino` blocks and parses them.
