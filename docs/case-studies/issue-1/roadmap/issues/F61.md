## Context

[formal-ai](https://github.com/link-assistant/formal-ai) has a chat SPA at
`/app/` and vanilla landing, docs and download pages. The facts below come
from the
[research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md).

Stack:

- React 19 with JSX, partly migrated to Chakra ^3.37;
- marked, dompurify, mermaid and tesseract.js;
- `lino-i18n` 0.4.0, although `js/i18n.js` reports 0.3.0;
- committed bun IIFE bundles;
- a generated `ts/` mirror of `js/`.

Problems:

- `js/app/application.jsx` is 1,445 lines.
- Seven order-dependent stylesheets, `js/styles/01-tokens.css` to
  `07-interactions.css`, total 4,884 lines. `06-dark-theme.css` alone is
  1,097 lines.
- Preferences are parsed by hand in `js/preferences.js`.
- `js/site-chrome.js` (625 lines) re-implements `h()` and
  `segmentedControl` "verbatim" from `js/download/download.js` (line 752).

Open issues this migration touches:

- [#447](https://github.com/link-assistant/formal-ai/issues/447): the sidebar
  mouse scroll;
- [#557](https://github.com/link-assistant/formal-ai/issues/557): skins and
  the adaptive composer;
- [#665](https://github.com/link-assistant/formal-ai/issues/665): PWA;
- [#666](https://github.com/link-assistant/formal-ai/issues/666): the VS Code
  extension;
- [#825](https://github.com/link-assistant/formal-ai/issues/825): autocomplete;
- [#951](https://github.com/link-assistant/formal-ai/issues/951): splitting
  the monolith;
- [#953](https://github.com/link-assistant/formal-ai/issues/953): committed
  bundles;
- [#1190](https://github.com/link-assistant/formal-ai/issues/1190): Mermaid on
  GitHub.

The deliverable is a pull request series in formal-ai, plus link-foundation/ui
issues for any missing pieces.

## Goal

formal-ai uses framework tokens, themes, i18n, the settings panel and the
chat kit on every page. Its external contracts stay unchanged, and the
duplicated chrome, the hand-written parsers and the dark-theme override
sheet are deleted.

### Out of scope

- Reasoning logic, Rust/WASM and the permission logic (link-assistant/formal-ai#953 asks to move it
  to Rust; that is separate).
- Web-search ranking (`web-search-component-entry.js`).
- React Native, Swift and Kotlin hosts. They reuse tokens and catalogs
  later.

## Dependencies

- **Blocked by {{F30}}**: the composer, message, reasoning trace and stream,
  which replace `message-view.jsx` and `thinking-steps.jsx`.
- **Blocked by {{F13}}**: the `ui-i18n` adapter over lino-i18n, which keeps
  the `formal-ai:i18n-ready` event and the `window.FormalAiI18n` shape.
- **Blocked by {{F37}}**: the settings panel generated from a schema, which
  replaces `preferences.jsx`. It must support "is default" detection (like
  `settingIsDefault`) and reset.
- **Related:** {{F57}} (playbook), {{F43}} (formal-ai skins as themes),
  {{F40}}, {{F41}}, {{F42}} (link-assistant/formal-ai#557 wants guideline skins), {{F32}} (Mermaid,
  link-assistant/formal-ai#1190), {{F60}} (the same chat kit).
- A stub is possible: phases 0–2 need only {{F11}}, {{F13}} and {{F26}}.

## Step-by-step plan

1. Copy the {{F57}} checklist template into the tracking pull request.
2. **Phase 0, contracts.** Add `tests/e2e/framework-contracts.spec.js`. It
   checks:
   - an old `formal-ai.preferences.v1` document loads with every key
     (`uiSkin`, `chatStyle`, `composerStyle`, `toolbarIconPack`,
     `glassOpacity` 0.78, `uiLanguage`, …);
   - `data-theme` on `<html>`;
   - the `formal-ai:i18n-ready` event fires;
   - `window.FormalAiPreferences`, `FormalAiI18n`, `FormalAiLanding`,
     `FormalAiDocs` and `FormalAiDownload` exist;
   - every `data-testid` with prefix `setting-`, `composer-`, `conversation-`
     or `desktop-` is still present.

   Save the current list as `tests/e2e/fixtures/testids.json`.

3. **Baseline screenshots.** Cover `/`, `/app/`, `/docs/` and `/download/`,
   in 4 skins × light/dark × desktop/mobile.
4. **Phase 1, tokens.** Write `js/styles/tokens.lino` with light, dark and
   contrast values, for example
   `(fa: theme (token surface.card '#FFFFFF') (scheme dark (token surface.card '#1E1E1E')))`.
   Take the real values from `01-tokens.css`. Generate `--fa-*` variables and
   the Chakra bridge from it. Delete `06-dark-theme.css` rule by rule, with
   screenshot diffs.
5. **Phase 2, chrome.** Replace the `h()`/`segmentedControl` copies with the
   framework vanilla binding (`@link-foundation/ui-dom`), and move `LABELS`
   into `js/i18n-catalog.lino`. Fix the reported lino-i18n version.
6. **Phase 3, skins.** Map the `ui-skin-*`, `chat-style-*`,
   `composer-style-*` and `toolbar-icon-pack-*` classes onto theme axes.
   Keep the old classes as aliases for one release. Drop the
   `remix-icon` pack: Remix Icon is on the framework avoid list. Map its
   users to `names` or a permitted pack.
7. **Phase 4, components.** Replace them in this order, one pull request
   each, keeping every `data-testid`:
   1. `CollapsibleSection`
   2. `ToolbarButton`
   3. settings rows
   4. composer
   5. message
   6. reasoning trace
   7. issue reporter
   8. links view

   Fix link-assistant/formal-ai#447 (the sidebar wheel scroll) while replacing the sidebar.

8. **Phase 5, storage.** Read and write preferences with `links-notation`.
   Keep the root `demo_preferences` and the `on`/`off` booleans. Keep the
   `memory.js` event-log shape.
9. **Phase 6, hosts.** Rebuild the Electron and VS Code webviews from the
   same package.
10. **After each phase:**
    - regenerate `ts/` (never hand-edit it);
    - keep `web-ui-boundary.yml`, the i18n parity check and the line budgets
      green.
11. **Delete** the replaced code. Record the line counts of `js/styles/*.css`,
    `application.jsx` and `site-chrome.js` before and after.

## Acceptance criteria

- [ ] `framework-contracts.spec.js` passes before and after every phase.
- [ ] Every `data-testid` from `fixtures/testids.json` still exists.
- [ ] `06-dark-theme.css` is deleted, and dark-mode screenshot diffs are
      below 0.1 %.
- [ ] `grep -n "verbatim" js/site-chrome.js` returns nothing; there is one
      segmented control implementation.
- [ ] `js/preferences.js` imports `links-notation`, and old documents still
      load (test).
- [ ] No `remix-icon` dependency remains (`grep -rn remix package.json js/`).
- [ ] Wheel scrolling of the sidebar works (link-assistant/formal-ai#447, Playwright `mouse.wheel`).
- [ ] The i18n parity check and `web-ui-boundary.yml` pass.

Compare the screenshots with the baseline in every skin and theme.
