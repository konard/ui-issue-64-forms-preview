## Context

Most roadmap issues will be solved by AI coding agents, many of them less capable than the agent that planned the roadmap. R35 asks for issues that are detailed enough for such agents. The roadmap issues follow one body template (Context, Goal, Scope, Dependencies, Step-by-step plan, Files to create or change, Acceptance criteria, How to verify, Prior art and libraries, References) and one conventions footer. Both are defined in [`docs/case-studies/issue-1/roadmap/README.md`](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/roadmap/README.md) and [`issue-footer.md`](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/roadmap/issue-footer.md).

New issues opened by people or agents after the roadmap have no such structure today:

- `.github/ISSUE_TEMPLATE/` does not exist.
- `AGENTS.md` is still template text. It talks about "Rust CI" and coordinator pushes, but says nothing about LiNo, packages, fixtures or screenshots.
- There is no `CLAUDE.md`. Upstream `links-notation` has both `AGENTS.md` and `CLAUDE.md` (https://github.com/link-foundation/links-notation).
- `docs/CONTRIBUTING.md` is rebranded by {{B01}}, but it describes the single-package template workflow.

## Goal

Give agents one entry point (`AGENTS.md`) and one guide (`docs/agents/`) that explain how to pick, plan, implement, verify and hand off work in this monorepo. Add GitHub issue forms (bug, feature) and a pull request template that mirror the roadmap template sections, so that every new issue is as actionable as the roadmap issues.

## Scope

### In scope

- Rewrite `AGENTS.md`: a short framework-specific entry point that links to the guide.
- `CLAUDE.md`: a one-line pointer to `AGENTS.md`, so that there is one source of truth.
- `docs/agents/README.md`: the workflow guide.
- `docs/agents/conventions.md`: the conventions now in the roadmap footer, as the canonical copy.
- `docs/agents/writing-issues.md`: how to write an issue that a less capable agent can solve.
- `.github/ISSUE_TEMPLATE/config.yml`, `feature.yml` and `bug.yml` (GitHub issue forms), and `.github/pull_request_template.md`.
- `tests/issue-templates.test.js`, which validates the forms against the roadmap template.
- A "For AI agents" section in `docs/CONTRIBUTING.md`, linking the above.

### Out of scope

- Rewriting the release process documentation (owned by {{F01}} and {{B05}}).
- Issue automation bots or labels beyond `bug`, `enhancement` and `documentation`.
- The documentation site content ({{F54}}).

## Step-by-step plan

1. Rewrite `AGENTS.md`, under 60 lines. It contains:
   - a repository map (`packages/*`, `docs/spec/`, `docs/ARCHITECTURE.md`, `assets/`, `examples/`, `experiments/`, `scripts/`);
   - the four commands that must pass (`npm test`, `npm run lint`, `npm run format:check`, `npm run check:duplication`);
   - "read the issue's Dependencies section first; stub blocked APIs, never fake them in tests";
   - links to `docs/agents/README.md` and `docs/agents/conventions.md`.

   Keep the existing rules that still apply: work in bulk, one pusher per branch, no deletion of user caches.

2. Create `CLAUDE.md` containing only `See [AGENTS.md](AGENTS.md).`
3. Move the text of `docs/case-studies/issue-1/roadmap/issue-footer.md` into `docs/agents/conventions.md`, adapted from "this issue" to "every change". Leave `issue-footer.md` untouched; it is a case-study record.
4. Write `docs/agents/README.md` with these sections:
   - **Pick an issue:** check that every `Blocked by` issue is closed, or work against a stub as the issue says.
   - **Plan:** follow the numbered steps; one commit per step is fine.
   - **Write tests first:** `node --test packages/<name>/tests/<file>.test.js` must fail before the change.
   - **LiNo first:** never use regex parsing; read `docs/spec/` for dialect questions.
   - **Verify UI:** run `npm run test:ui` and attach screenshots in the PR.
   - **Licensing:** read `docs/licensing.md`; run `npm run check:assets`.
   - **Changesets:** run `npx changeset` and pick the package.
   - **Hand-off:** a PR description with `Fixes #N` and the evidence for each criterion.
   - **When stuck:** open a new Bug or Feature issue with the forms instead of widening scope.
5. Write `docs/agents/writing-issues.md`. It covers:
   - the required sections and their purpose;
   - concrete names (packages, files, JSDoc signatures, LiNo inputs and outputs);
   - only objectively verifiable acceptance criteria;
   - exact verify commands;
   - a length of roughly 90–200 lines;
   - quoting rules for LiNo examples (`'#6750A4'`, quoted URLs);
   - no copyrighted text.

   Link one roadmap issue as the model, for example {{F06}}.

6. Create `.github/ISSUE_TEMPLATE/feature.yml`:
   - `name: Feature`, `labels: [enhancement]`; add `type: Feature` if the issue-forms schema supports issue types (check the current GitHub docs);
   - `textarea` fields with ids `context`, `goal`, `in-scope`, `out-of-scope`, `dependencies`, `plan`, `files`, `acceptance` (pre-filled with `- [ ] `), `verify` (rendered as a `shell` code block), `prior-art` and `references`;
   - an `input` field `requirements` (R-IDs, optional).

   Required: `context`, `goal`, `in-scope`, `acceptance`, `verify`. Add a `markdown` intro that links `docs/agents/writing-issues.md`.

7. Create `.github/ISSUE_TEMPLATE/bug.yml`:
   - `name: Bug`, `labels: [bug]`;
   - fields `summary`, `reproduce` (numbered steps and exact commands), `expected`, `actual`, `logs` (with a CI run URL, rendered as a code block), `environment` (Node/Bun/Deno version, browser, OS), `suspected-cause` (optional), `acceptance` (`- [ ]`) and `verify`.

   Required: `summary`, `reproduce`, `expected`, `actual`, `acceptance`.

8. Create `.github/ISSUE_TEMPLATE/config.yml` with `blank_issues_enabled: true`, and a `contact_links` entry to the roadmap tracking issue's case study folder.
9. Create `.github/pull_request_template.md`: `Fixes #`, Summary, a checklist mirroring the "Done means" convention (criteria checked, CI green, changeset, screenshots for UI, licensing records).
10. Add `yaml` (ISC) as a devDependency. Write `tests/issue-templates.test.js`, which parses both forms and asserts:
    - all ids are unique;
    - the required ids listed above exist and have `validations.required: true`;
    - the feature form ids appear in the same order as the H2/H3 sections of the roadmap template;
    - every `labels` value is one of `bug`, `enhancement`, `documentation`.
11. Add the "For AI agents" section to `docs/CONTRIBUTING.md`. Keep the headings that `scripts/check-required-docs.sh` requires ("Development Workflow", "Release Process").

## Acceptance criteria

- [ ] `AGENTS.md` is under 60 lines, mentions no Rust CI, and links `docs/agents/README.md` and `docs/agents/conventions.md`.
- [ ] `CLAUDE.md` points to `AGENTS.md`.
- [ ] `docs/agents/` contains the three documents, with the sections listed in steps 4 and 5.
- [ ] Opening "New issue" on GitHub (in a fork or after merge) offers the Feature and Bug forms; screenshots of both forms are attached to the PR.
- [ ] `node --test tests/issue-templates.test.js` passes and checks the section order against the roadmap template.
- [ ] `bash scripts/check-required-docs.sh` still passes.
- [ ] `npm test`, `npm run lint` and `npm run format:check` pass, and the links workflow reports no broken links.

## How to verify

```bash
npm ci
node --test tests/issue-templates.test.js
bash scripts/check-required-docs.sh
wc -l AGENTS.md            # expect < 60
npm test && npm run lint && npm run format:check
```

Then open `https://github.com/<fork>/ui/issues/new/choose` and check that both forms render and that the required fields are enforced.
