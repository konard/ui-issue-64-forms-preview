## Context

Two of our projects contain the best chat UI we have:

- **meta-sovereign** (https://github.com/link-foundation/meta-sovereign, files
  under `js/src/web/`): `chat-view.js` (floating composer, `messageRuns()`
  groups messages by sender, `--chat-column: 44rem`), `chat-model.js` (pure:
  `summarizeChats`, `sortChats`, `CHAT_FILTERS`, `unreadCount`,
  `deliveryStatus`, `dayGroup`, `typingStatus`), `chat-message.js`
  (MessageBubble, MsgAvatar, ReplyQuote, reactions, service lines, pending and
  failed states), `message-text.js` and `rich-text-nodes.js` (entities by
  UTF-16 offsets), `chat-window.js` (pages of 50, prefetch 30, ceiling),
  `chat-follow.js` (stick to bottom, keep place on prepend, unread line),
  `chat-selection.js`, `chat-drag.js`, `chat-composer-height.js`,
  `chat-composer-space.js`, `chat-days.js` and `chat-jump.js`. It has four
  skins: t3 (default), telegram, whatsapp and signal; for example
  `--bubble-radius` is 15px for Telegram, 7.5px for WhatsApp and 18px for
  Signal. The research lists 14 duplication candidates
  ([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/meta-sovereign-chat.md)).
- **formal-ai** (https://github.com/link-assistant/formal-ai): `js/app/message-view.jsx`
  (Message, PendingAssistantBubble, ThinkingPreview, StepHierarchyMenu),
  `thinking-steps.jsx` (reasoning trace), `markdown-render.jsx`,
  `attachments.jsx`, `autocomplete.js` (Enter sends, Shift+Enter new line);
  chat styles `cards`, `compact`, `bubbles` and composer styles `flat`,
  `glass-soft`, `glass-clear`, `bubble`
  ([research](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md)).

Known problems to avoid: chat code coupled to Telegram semantics; the composer
overlapping the last message; WebKit `ResizeObserver` loops; white-on-white
selection; the textarea limited to 50 % height
(https://github.com/link-assistant/formal-ai/issues/112). Some behaviour was
learned from GPL and AGPL clients: never copy their code.

## Goal

`@link-foundation/ui-components` contains a provider-neutral chat kit (chat
list, message stream, bubble, composer, reasoning trace, day separators,
selection and context menu) driven by one LiNo data contract, with skins as
token sets, so meta-sovereign ({{F60}}) and formal-ai ({{F61}}) can delete their
own copies.

## Scope

### In scope

- The data contract (`chat`, `message`, `participant`, `attachment`,
  `reaction`, `step`) and capabilities passed as data (`can-edit`,
  `can-react`, `can-reply`, `max-attachments`).
- `chat-list`, `message-stream` (load older and newer, jump to a message,
  stick to bottom, unread line, ceiling), `message-bubble` with reply quote,
  reactions, delivery ticks and service lines, `day-separator`, `composer`
  (slots, auto-grow text area, reserved-space contract), `reasoning-trace`.
- Skins `t3`, `telegram`, `whatsapp`, `signal` and styles `cards`, `compact`,
  `bubbles` as token sets ({{F11}} format).
- Selection model: a context-menu target is separate from a multi-selection.

### Out of scope

- Network transports, Telegram or LLM providers (the app supplies data and
  actions).
- Voice recording, Lottie stickers and the emoji picker (follow-up issues).
- Markdown and Mermaid rendering inside messages (use {{F32}} for diagrams;
  messages accept a renderer slot).

## Dependencies

- **Blocked by {{F26}}**: buttons, icon buttons, text area and toggles used by
  the composer and the bubble actions.
- **Blocked by {{F29}}**: `virtual-range.js` (offsets, `indexAt`, anchor on
  prepend) for the chat list and the message stream; `list` for the chat list.
- A stub is possible: write `chat-model.js`, `stream-window.js` and the data
  contract tests first; they are pure.
- **Related:** {{F27}} (context menu, popovers), {{F28}} (`split` and
  `app-shell`), {{F13}} (i18n for "Today", "Yesterday"), {{F36}} (icons),
  {{F37}} (chat appearance settings), {{F60}}, {{F61}}.

## Step-by-step plan

1. Create `packages/ui-components/src/chat/` and export it.
2. Write `chat-contract.js` with JSDoc typedefs and
   `parseChatData(links)` / `chatDataToLino(data)` using the `links-notation`
   package. Example data:
   ```lino
   (c1: chat (title 'Design review') (unread 2) (can-edit true) (can-react true))
   (m1: message (chat c1) (sender alice) (time '2026-10-30T10:00:00Z') (text 'Hi'))
   (m2: message (chat c1) (sender bob) (reply-to m1) (status delivered) (text 'Hello'))
   (s1: step (message m2) (title 'Search') (state done) (parent none))
   ```
3. Port `chat-model.js` from meta-sovereign (Unlicense): `summarizeChats`,
   `sortChats`, `unreadCount`, `deliveryStatus`, `dayGroup`, `messageRuns`.
   Inject the clock and locale; tests must not use the real time.
4. Write `stream-window.js`:
   ```js
   /**
    * @param {{ pageSize?: number, prefetch?: number, ceiling?: number }} options
    * @returns {{ loadOlder(): Promise<void>, loadNewer(): Promise<void>,
    *   jumpTo(id: string): Promise<void>, state(): StreamState }}
    */
   export function createStreamWindow(source, options) {}
   ```
   Defaults from meta-sovereign: page 50, prefetch 30. `jumpTo` loads history
   around the target and highlights it.
5. Write `follow.js` (stick to bottom unless the user scrolled up, keep place
   on prepend, unread line) on top of `anchorScrollTop` from {{F29}}.
6. Write the elements `chat-list.js`, `message-stream.js`,
   `message-bubble.js`, `day-separator.js`, `composer.js`,
   `reasoning-trace.js`. The composer publishes its height as the CSS variable
   `--composer-space`, measured by a `ResizeObserver` deferred to
   `requestAnimationFrame`; the stream adds that space at the bottom.
7. Write skins in `packages/ui-components/src/chat/skins/*.lino`
   (`t3`, `telegram`, `whatsapp`, `signal`), for example
   `(token chat.bubble.radius 15px)` for Telegram. Copy the other values
   (`--bubble-in`, `--bubble-out`, `--bubble-tail`, `--chat-bg` and so on)
   from the skin blocks in meta-sovereign `app.css` (around lines 3310–3400)
   and quote hex colours in LiNo. Check selection contrast for every skin with
   WCAG 2.2 AA.
8. Keyboard parity: arrow keys move between messages, Enter opens actions,
   Escape clears the selection, Enter sends and Shift+Enter adds a new line.
9. Add `packages/ui-components/examples/chat.html` with a fake in-memory
   source of 10 000 messages and a skin switcher.

## Acceptance criteria

- [ ] `parseChatData(chatDataToLino(x))` equals `x` for the fixtures in
      `tests/chat/fixtures/*.lino`.
- [ ] `chat-model.test.js` covers sorting, unread counts, day groups and
      sender runs with an injected clock.
- [ ] `stream-window.test.js` covers `loadOlder`, `loadNewer`, `jumpTo` and
      the ceiling.
- [ ] The last message is never hidden by the composer when the composer grows
      to five lines (Playwright measures the rectangles).
- [ ] Prepending older messages keeps the visible message in place (1 px).
- [ ] A capability set to `false` hides the matching action (test).
- [ ] Four skins render; selected text contrast is at least 4.5:1 in each
      (screenshots plus a contrast test).
- [ ] No file in `src/chat/` imports Telegram- or provider-specific code
      (lint rule or test that scans imports).

## How to verify

```bash
node --test packages/ui-components/tests/chat/*.test.js
npx playwright test packages/ui-components/tests/e2e/chat.spec.js
npm run lint && npm run format:check && npm run check:duplication
```

Expected screenshots: the same conversation in the four skins, the composer
with five lines, a message highlighted after `jumpTo`, and a reasoning trace
with nested steps.
