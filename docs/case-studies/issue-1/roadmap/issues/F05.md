## Context

The framework owns all of its UI elements (R13), and it ships its own documentation and demo site built with itself (R24). Each component issue ({{F26}}–{{F30}}) and each theme ({{F40}}–{{F43}}) needs two checks in CI: a screenshot comparison per theme and locale, and an automated accessibility audit.

What exists already:

- `scripts/update-preview-images.mjs` uses `browser-commander` and the Playwright Chromium. It serves `examples/universal-app/dist` at 1280×800 and writes `docs/screenshots/example-app/example-app-{en,ru}-{light,dark}.png`.
- The `preview-regen` job in `.github/workflows/example-app.yml` runs in the pinned container `mcr.microsoft.com/playwright@sha256:b0ab6f3c…` (v1.59.1-noble), with `PLAYWRIGHT_BROWSERS_PATH=/ms-playwright`. It installs `playwright@1.59.1` with `--no-save`. The job currently fails because `gh` is missing in that container ({{B04}}).

Prior art in our other repositories:

- meta-sovereign-chat runs Playwright end-to-end tests in Chromium and WebKit, a WCAG 2.0 A/AA axe-core audit (`stepAxeAudit`), and pixel and contrast checks ([meta-sovereign-chat.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/meta-sovereign-chat.md)).
- formal-ai produces per-locale and per-theme CI screenshots `app-preview-{en,hi,ru,zh}-{dark,light}.png` with `data-testid` hooks, but has no axe audit ([formal-ai.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/formal-ai.md)).
- konard.github.io tests in Chromium, Firefox and WebKit ([konard-github-io-and-links-visuals.md](https://github.com/link-foundation/ui/blob/main/docs/case-studies/issue-1/research/konard-github-io-and-links-visuals.md)).

## Goal

Add one reusable Playwright Test setup with axe-core that any package under `packages/*` and the demo site can use. It provides:

- screenshot baselines per browser, theme and locale;
- a WCAG 2.2 A/AA audit (the conventions require WCAG 2.2 AA contrast);
- a pinned container so that baselines are reproducible;
- a CI workflow that uploads diffs when it fails.

## Scope

### In scope

- Root devDependencies:
  - `@playwright/test` (Apache-2.0), at the same version as the container tag;
  - `@axe-core/playwright` and `axe-core` (MPL-2.0). These are allowed only as dev/CI tools, never imported by a published package; record this in `docs/testing-ui.md`.
- `playwright.config.mjs` with the `chromium` and `webkit` projects (`firefox` optional), a `webServer` that serves static fixtures, and a fixed viewport, locale and timezone.
- Helpers in `tests/ui/helpers.mjs`: an accessibility assertion and a theme × locale screenshot matrix.
- Fixture pages, a smoke test, and a negative test proving that axe catches violations.
- A test for the existing example app (`examples/universal-app/dist`), replacing nothing in `update-preview-images.mjs`.
- A `ui-tests.yml` workflow in the pinned Playwright container, with a manual "update snapshots" mode.
- `scripts/check-playwright-version.mjs`, which keeps the npm version and the container tag in sync.

### Out of scope

- Fixing `gh` in `preview-regen` ({{B04}}).
- Component tests themselves (each component issue adds its own `*.e2e.mjs`).
- The docs site ({{F54}}), which adds its own tests using these helpers.

## Step-by-step plan

1. Add the devDependencies. Pin `@playwright/test` to exactly the version in the `example-app.yml` container comment (1.59.1 at the time of writing; check the current pin).
2. Write `scripts/check-playwright-version.mjs`. It reads the `@playwright/test` version from `package.json`, finds every `mcr.microsoft.com/playwright@sha256:… # vX.Y.Z-noble` comment in `.github/workflows/*.yml`, and exits 1 on a mismatch. Add it to `npm run lint` or as `npm run check:playwright`.
3. Write `playwright.config.mjs` with these settings:
   - `testMatch: ['tests/ui/**/*.e2e.mjs', 'packages/*/e2e/**/*.e2e.mjs']`. Use the `.e2e.mjs` suffix so that `node --test`, `bun test` (which matches `*.spec.*`) and `deno test` never pick these files up.
   - `snapshotPathTemplate: '{testDir}/__screenshots__/{projectName}/{testFilePath}/{arg}{ext}'`.
   - `use: {viewport: {width: 1280, height: 800}, locale: 'en-US', timezoneId: 'UTC', colorScheme: 'light'}`.
   - `expect.toHaveScreenshot: {maxDiffPixelRatio: 0.001, animations: 'disabled'}`.
   - `webServer: {command: 'node scripts/serve-static.mjs --port 4173', url: 'http://127.0.0.1:4173/'}`.
   - `retries: process.env.CI ? 1 : 0`.
   - `reporter: [['list'], ['html', {open: 'never'}]]`.
4. Write `scripts/serve-static.mjs`, a dependency-free `node:http` server for `tests/ui/pages/`, `packages/*/e2e/pages/` and `examples/universal-app/dist/`. Reuse the server code of `update-preview-images.mjs` by moving it into `scripts/lib/static-server.mjs` (do not duplicate it, because jscpd runs in CI).
5. Write `tests/ui/helpers.mjs` with two exports:
   - `/** @param {import('@playwright/test').Page} page @param {{include?: string, exclude?: string[], tags?: string[]}} [opts] */ export async function expectAccessible(page, opts)`. It runs `new AxeBuilder({page}).withTags(opts.tags ?? ['wcag2a','wcag2aa','wcag21a','wcag21aa','wcag22aa'])`, and fails with a readable list of `id`, `impact` and target selectors.
   - `/** @param {Page} page @param {string} name @param {{themes?: string[], locales?: string[], apply: (page, {theme, locale}) => Promise<void>}} opts */ export async function screenshotMatrix(page, name, opts)`. It produces `<name>-<locale>-<theme>.png`.
6. Add the fixture pages:
   - `tests/ui/pages/smoke.html`: a heading, a labelled input, a button, and a light/dark switch through `data-theme`;
   - `tests/ui/pages/inaccessible.html`: an unlabelled input and a low-contrast button.
7. Add the tests:
   - `tests/ui/smoke.e2e.mjs`, which runs `expectAccessible` and `screenshotMatrix` on `smoke.html`, with en and ru × light and dark;
   - `tests/ui/negative.e2e.mjs`, which asserts that axe reports `label` and `color-contrast` violations on `inaccessible.html`;
   - `tests/ui/example-app.e2e.mjs`, which builds nothing itself; it expects `npm run example:web:build` to have run, and audits `examples/universal-app/dist/index.html`. Existing violations go into an explicit `knownViolations` list, each with a linked issue, rather than being ignored silently.
8. Add the npm scripts:
   - `"test:ui": "playwright test"`;
   - `"test:ui:update": "playwright test --update-snapshots"`;
   - `"test:ui:docker": "docker run --rm -v \"$PWD\":/work -w /work -e CI=1 mcr.microsoft.com/playwright:v1.59.1-noble sh -c 'npm ci && npx playwright test'"`. Use the same tag as the pin.
9. Add `.github/workflows/ui-tests.yml`:
   - it runs on PRs and on main;
   - one job in the same container digest as `preview-regen`, with `PLAYWRIGHT_BROWSERS_PATH=/ms-playwright`;
   - steps: `git config --global --add safe.directory "$GITHUB_WORKSPACE"`, `npm ci`, `npm run example:web:build`, then `npx playwright test`;
   - on failure, upload `playwright-report/` and `test-results/` as artifacts;
   - a `workflow_dispatch` input `update-snapshots` runs `--update-snapshots` and uploads `**/__screenshots__/**` as an artifact for a human to commit. It does not push and does not need `gh`.

   Pin the actions by SHA, as the other workflows do.

10. Commit the baselines that the container generates, never baselines from a local macOS or Windows run. Add `playwright-report/` and `test-results/` to `.gitignore`.
11. Write `docs/testing-ui.md`. It explains how to add an `e2e/` folder to a package, update baselines with `npm run test:ui:docker -- --update-snapshots`, read the diff artifacts, and handle the `knownViolations` policy. It also records the MPL-2.0 note for axe-core.

## Acceptance criteria

- [ ] `npx playwright test` in the pinned container passes for the `chromium` and `webkit` projects.
- [ ] The smoke test produces 4 baselines per browser (`en`/`ru` × `light`/`dark`), and they are committed.
- [ ] `tests/ui/negative.e2e.mjs` passes, which proves that axe detects the `label` and `color-contrast` violations.
- [ ] Changing one colour in `smoke.html` makes `toHaveScreenshot` fail, and the CI artifact contains the diff image.
- [ ] `node scripts/check-playwright-version.mjs` exits 0, and exits 1 after you edit the version in `package.json`.
- [ ] `npm test`, `bun test` and `deno test -A --parallel` do not execute any `*.e2e.mjs` file.
- [ ] `npm run lint`, `npm run format:check` and `npm run check:duplication` pass, and `ui-tests.yml` is green.

## How to verify

```bash
npm ci
node scripts/check-playwright-version.mjs
npm run example:web:build
npm run test:ui:docker                       # all e2e tests in the pinned image
npx playwright test tests/ui/negative.e2e.mjs --project chromium
npm test && npm run lint && npm run check:duplication
```
